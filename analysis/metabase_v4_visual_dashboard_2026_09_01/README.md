# Waje 端侧体验问题图表总览 V4

- 可筛选诊断入口：<http://127.0.0.1:3010/dashboard/9-waje-v3>

## 视觉设计

V4 的作用是让产品和研发先看见异常，而不是先阅读宽表：

| 区域 | 图形 | 读取问题 | 数据边界 |
|---|---|---|---|
| 原生端轨迹 P95 | 横向条形图 | 哪个端的轨迹时延最慢？ | Android 三包和当前 iOS 来源分别计算，不跨端合并。 |
| 版本相对基线 | 横向条形图 | 哪些 Android 版本相对近 7 天中位数恶化？ | 仅显示有效样本不少于 500、有效日满足条件的版本。 |
| 设备 Top 5 | 横向条形图 | 哪些设备型号的轨迹 P95 最高？ | 仅前 5；不输出设备唯一标识。 |
| 运营商 Top 5 | 横向条形图 | 哪些运营商/端侧组合的网络响应 P95 最高？ | 网络 P95 不代表支付、登录或下注成功。 |
| Fatal 受影响主体率 | 横向条形图 | 哪个 Android 包的 Fatal 崩溃影响比例更高？ | `Fatal 受影响 first_session_id ÷ 活跃 first_session_id × 10,000`；仅作为去标识化活跃主体代理，不等同登录账号用户。 |
| 数据可信度与 H5 | 紧凑状态表 | 数据是否足够、H5 哪些性能能力未接入？ | H5 Web Vitals、前端错误、核心请求和游戏链路维持 `data_gap`。 |

所有图表均使用只读聚合 SQL；每个排行最多返回 5 行。`trace_p95_ms` 和 `network_p95_ms` 均为毫秒，P95 在有效样本少于 500 时不应解释为正式性能结论。

Crashlytics 原始事件量不能替代稳定性问题率。当前稳定性图只统计 Fatal，并通过 `firebase_session_id → session_id` 的同包关联获得受影响主体代理；真实登录账号用户占比仍需服务端活跃用户分母或已批准的统一匿名用户键后才能发布。

## 使用建议

1. 先打开 V4：使用 P95 对比、版本、设备和运营商条形图快速定位候选异常。
2. 再打开 V3：按日期、端侧、包体、版本和国家筛选，核对样本量、数据截止时间、状态与行为影响范围。
3. H5 没有性能数值时，视为监测缺口，而不是性能正常。

## 不做的事情

- 不返回或下载原始事件、用户标识、会话标识、设备唯一标识、完整 URL、订单、支付明细或堆栈；
- 不写入 BigQuery、Firebase 或生产数据源；
- 不从客户端行为事件推导服务端业务成功率。

## 本机服务可用性

Metabase 已配置为当前 macOS 用户下的启动服务：`com.waje.metabase.local`。它只监听 `127.0.0.1:3010`，使用同一份本地 H2 数据文件，并在异常退出后自动重启。

可用性检查：

```bash
curl http://127.0.0.1:3010/api/health
```

返回 `{"status":"ok"}` 后即可打开 V4。启动服务定义位于：

```text
/Users/robin/Library/LaunchAgents/com.waje.metabase.local.plist
```
