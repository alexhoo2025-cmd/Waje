# 起源敏捷分析：轻量化游戏专题模板

所有模板以“起源ID”为分析主体，使用产品默认时区；执行时不保存书签，先导出聚合结果并记录筛选、日期和事件属性。

## 模板一：H5入口到游戏开始

```text
起始：Web元素点击或模块点击（大厅/轻量化游戏入口）
→ 游戏开始
窗口：30分钟
分组：分包渠道、归因媒体、终端、页面/模块属性、游戏属性
```

目的：区分入口吸引力与点击后的启动阻断。

前置：确认入口事件的页面、模块、游戏标识属性；没有可区分轻量化游戏的属性时，结果标记`blocked`。

## 模板二：游戏开始到结算

```text
起始：游戏开始
→ 游戏结束
→ XZ结算奖励
窗口：30分钟
分组：game_id、玩法、分包渠道、归因媒体、端、版本
```

目的：识别“已启动但未完成”与结算异常。

限制：当前事件中心未确认`game_id`、round_id和版本属性，不能直接将不同游戏混合比较。

## 模板三：游戏开始后的留存

```text
起始事件：游戏开始（按game_id过滤）
回访事件：用户活跃事件 / 游戏开始
展示：D1、D3、D7
分组：渠道、端、版本、用户付费状态
```

目的：检验进入某款游戏后是否关联更高复玩和后续活跃。

限制：未补齐进入前用户特征和真实版本时，只能写观察性关联。

## 模板四：局数深度与后续留存

控制来源：`BQ-局数分布及留存`（报表ID 131）。

固定分层：0局、1局、2–3局、4–10局、11局+。

目的：判断轻量化是否降低0局、提高首局后继续参与，而非只提升点击。

## 模板五：Web性能与转化护栏

控制来源：GA4 Web页面加载时长、起源设备监控、敏捷Web页面加载时长。

观察：P75/P90/P95加载耗时、白屏/崩溃、浏览器、OS、屏幕、网络、低端机，以及对应游戏开始/结束率。

前置：设备监控SQL修复；补齐Web Vitals、前端错误、game_ready和bet_ready事件。
