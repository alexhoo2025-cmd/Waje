# TC 指标的正确业务逻辑与因果边界

## 结论

每日 TC 是**当日现金流结果指标**：

```text
Daily TC(D) = 当日成功提现金额 ÷ 当日成功充值金额
```

它可用于观察当天资金流入与流出的比例，**不能**据此推导“当日充值金额变化导致当日提现变化”。

## 博彩真金业务中的提现来源

玩家的成功提现必须来自其已经形成的可提现资产，而不是当天失败的充值订单。可提现资产的来源包括：

```text
期初可提现余额
+ 历史及当期成功充值到账
+ 游戏最终结算赢利 / 玩家筹码池分配
+ 已满足流水条件后的资产转换
+ 经批准的退款、补偿或人工调整
- 历史及当期成功提现
= 期末可提现余额
```

因此：

- 充值 `status=4 Failed` 没有到账，不产生余额，不影响 TC 分子或分母；
- 玩家可以今天提现前几天充值、前几天游戏赢得的余额；
- 单日 TC 可以大于 100%，并不自动代表资损；
- 留存余额、结算节奏和提现批次会影响单日 TC，但长期稳定性仍取决于经济系统、RTP、玩家资金池和真实成功充值。

## 正确的高 TC 诊断顺序

1. **描述性拆分**：确认 TC 的算术变化来自成功提现上升、成功充值下降，或两者共同变化。此步骤不做因果判断。
2. **资产来源审计**：对成功提现按已入账资产来源聚合：期初余额、历史成功充值、当期成功充值、游戏结算赢利、转换资产、调整资产。
3. **游戏经济审计**：检查有效真金下注、最终派彩、RTP、大奖、配置版本、异常局、重复结算和资产转换。
4. **时间与批次审计**：检查提现审核/打款批次、跨日结算、余额释放与提现申请的时间分布。
5. **渠道与用户结构审计**：分析渠道的玩家生命周期、历史充值存量、赢利玩家占比和提现能力，而不是把渠道当天充值视为提现的唯一来源。

## 已废止的错误解释

> 大量失败充值 `status=4` 造成成功充值分母变小，因此导致 TC 偏高。

失败充值没有到账，也不能产生相应提现；它不进入 TC 分母是正确口径，不能被当作“漏记成功充值”或高 TC 的原因。

## 需要补齐的事实层

```text
fact_player_asset_daily
  business_date, channel, asset_type,
  opening_balance, success_recharge_in, game_settlement_in,
  conversion_in, approved_adjustment_in,
  successful_withdraw_out, closing_balance

fact_game_settlement_daily
  business_date, event_time_channel, game, game_version, config_version,
  effective_cash_bet, final_cash_payout, valid_rounds, rtp
```

在没有上述事实层前，TC 的变化只能作为监控和下钻入口，不可直接作出“充值导致提现”或“某渠道资损”的因果判断。
