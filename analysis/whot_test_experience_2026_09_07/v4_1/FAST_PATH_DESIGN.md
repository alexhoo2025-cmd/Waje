# WHOT 6001 快速出牌执行链设计

状态：待实现与在线校准，不宣称已解决超时。

用户确认优先级：操作及时与合法性第一，获胜策略第二。校准固定第一张已确认合法牌；影子评分与复杂策略不进入实时关键路径。连接恢复优先刷新原测试标签，再重开同一页面，但先保存未结算状态。

## 根因与边界

重开后页面连接恢复；对局截图之间仍跨过多个动作。模型逐帧判断、工具往返和截图等待仍位于关键路径，不能靠减少策略评分弥补。页面提示行动窗口为 8 秒。观察时间不可替代回合开始时间。

## 两层执行

- 慢路径：模型负责规则校准、异常复盘和批次报告；浏览器连接恢复仅在日志保存且确认当前对局状态后进行。
- 快路径：同一常驻进程内完成内存帧读取、手牌与特殊状态识别、合法动作、固定策略、输入与确认。每个回合不调用模型、不生成报告、不启动截图子进程。
- 只在普通 Chrome 测试域名和 6001 路由生效，BET 1 校准；没有认证前不续局、不升档。

## 时限目标（非已测成绩）

| 阶段 | 目标预算 |
|---|---:|
| 可行动状态检测及新帧 | 250 ms |
| 局部识别及合法动作 | 350 ms |
| 固定策略选择 | 20 ms |
| 输入前状态核验及提交 | 180 ms |
| 余量 | 200 ms |

首次动作目标 1 秒，实测可行动至点击 P95 不超过 2 秒。确认单独计时，不把工具返回时长当作端到端时长。

## 核心调度

1. 大厅预热采集器、模板及规则；检测链通过后才允许匹配。
2. 最新帧队列容量 1；8 Hz 观察可行动状态，等待阶段 2 Hz。丢弃过期帧。
3. 所有门禁通过后才生成候选；固定策略是纯函数。缺少牌面、图案或明确控制来源时不点击。
4. 建议绑定 match_id、state_seq、action_id、帧时间和坐标版本；提交前再次检查焦点、域名、布局和期限。
5. 一个待确认动作；跟踪牌离手和桌牌变化。选中动画不是确认。点击结果未知不重发。
6. 特殊窗口独立处理；普通合法出牌不能覆盖强制摸牌或选图案窗口。
7. 剩余少于 2 秒时跳过影子策略，只执行当前已验证且未过期的固定策略动作；不使用过期预计算动作。
8. 每动作轻量日志入队并持久化；结算原子保存。录像/图片写入与控制线程分离，日志背压触发停止续局。

## 验收与安全停止

- 至少 3 局试运行、10 局连续校准；每局零托管、零非法动作、结算完整及明确确认终态。
- 回合覆盖分母独立验证；不能以记录条数作全部回合。
- 托管即取消策略样本资格；两次同类识别/确认失败停止续局并回放修复。
- 18/18 角标回放结果不是整张牌/整局识别认证。须补方形、十字、万能牌、遮挡与特殊状态。
- 原生输入适配器仍未启用；该调整与 CUA-only 方案不同，需要确认后才能接入。
- 不充值、不提现、不接触隐藏牌、账户凭证或资金接口。

## 当前最小下一步

先完成快路径的文件回放与无点击 shadow run，核对状态和期限；再启用限定 BET 1 的输入校准。连接问题可刷新/重开，但对局中不得为恢复连接盲目刷新。
