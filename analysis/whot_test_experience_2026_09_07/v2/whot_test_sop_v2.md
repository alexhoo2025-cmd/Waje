# WHOT 测试标准流程 V2

适用于 `test-h5.wajew.com` 的 WHOT 6001 测试。目标是稳定完成受控对局、采集可审计样本、评估正常玩家策略和机器人可观察行为。测试筹码只用于 QA；不充值、不提现、不进入其他游戏或站内系统。

## 1. 单一浏览器与入口门禁

1. 只使用普通 Chrome 的既有登录标签，禁止 PWA、内置浏览器和新建测试窗口。
2. 开始前确认域名精确为 `test-h5.wajew.com`，账号区显示测试筹码余额。
3. 关闭促销、每日筹码和提现提示，仅点击弹窗自身的关闭按钮。
4. 只通过首页 `data-game-id=6001` 的 Whot 卡片，或站内搜索 `Whot` 进入。
5. 点击后必须确认 URL 为 `/game/6001-whot`；不满足时立即返回并将该段标记为 `invalid_scope`。
6. 禁止使用地址栏、Google 搜索、PWA“在应用中打开”、推荐区旧编号、相邻卡片或其他游戏页面恢复会话。

## 2. 对局状态机

```text
LOBBY
→ MATCHING
→ DEALING
→ OPPONENT_TURN
→ PLAYER_TURN
→ SPECIAL_RESOLUTION
→ SETTLEMENT
→ NEXT_MATCH
```

- 只有画面明确出现 `ZAMU YAKO` 才允许点击手牌或牌堆。
- 头像光环、动画、手牌亮度和牌背移动只能作为辅助信号。
- 出现 `PICK 2`、WHOT 选图案、Last Card、SUSPENSION、SOKO LA WOTE 或托管时，先进入 `SPECIAL_RESOLUTION`，不得按普通回合处理。
- URL 变化、窗口丢失、结算缺失或状态无法判定时，不继续猜测点击。

## 3. 五秒决策预算

| 阶段 | 预算 | 动作 |
|---|---:|---|
| 读取 | 0–0.8 秒 | 单次截图；识别顶牌、可见手牌、对手牌数和特殊状态 |
| 规则过滤 | 0.8–1.0 秒 | 生成同数字、同图案或 WHOT 20 的合法动作集合 |
| 策略选择 | 1.0–1.3 秒 | 按本局预先指定的策略臂选择动作 |
| 执行与确认 | 1.3–2.2 秒 | 点击一次；验证手牌数、顶牌或特殊状态发生变化 |
| 恢复余量 | 2.2–5.0 秒 | 只允许一次受控重试或 WHOT 图案选择 |

取消固定等待和重复截图轮询。只有画面明确显示“牌已选中但尚未打出”时才进行第二次点击；禁止盲目双击。动作未被接受时记录 `action_accepted=false`，最多重试一次。

## 4. 特殊状态优先级

1. `auto_play`：立即恢复人工控制，本局标记 `mixed_auto_play`，不进入人工策略主样本。
2. `pick_two`：按规则执行强制摸牌，记录实际摸牌张数。
3. `whot_shape_selection`：选择自己剩余手牌中数量最多的图案，并记录 `target_shape`。
4. `last_card_declaration`：完成宣告并记录响应时间。
5. `last_card_catch`：在可见抓罚窗口内执行并记录服务端结果。
6. `suspension` / `soko_la_wote`：等待特殊状态完成，确认下一位行动者后再继续。
7. 未识别状态：截图重读一次；仍无法识别则记录 `unresolved_turn`，不随机点击。

V2 规则配置只认证实际确认的 `2 → PICK 2` 和 `20 → WHOT 选图案`。其他特殊牌效果由画面的 `pending_effect` 显式传入，直至产品规则映射完成认证。

## 5. 受控策略

每局在匹配前从排期中领取一个固定策略，局中不得根据输赢改变：

- `first_legal_play`：按手牌从左到右选择第一张合法牌。
- `reduce_high_point_cards`：存在非 WHOT 合法牌时优先清理点数最高的牌；WHOT 仅在没有普通合法牌时使用。
- `retain_special_or_wild_cards_until_needed`：有普通合法牌时保留已认证特殊牌和 WHOT，再按点数清理普通牌。

当前自动选优冻结。只有相同规则版本、房间、下注档位下，每组至少25局且通过覆盖、托管、非法动作和时延门禁后，才允许比较策略。

## 6. 每回合记录

至少记录：

- `event_seq`、观察时间、是否我方回合、当前特殊状态；
- 顶牌数字和图案、我方可见手牌数、合法动作数；
- 对手可见剩余牌数；
- 预定策略、实际动作、牌和 WHOT 目标图案；
- 从回合可操作到点击的 `decision_latency_ms`；
- `policy_compute_ms`、动作是否接受、是否超时/托管；
- 截图置信度和异常说明。

不保存隐藏牌、牌堆顺序、原始对手名称、账号、Cookie、Token、完整请求或响应。

## 7. 结算与样本资格

结算页一次性记录：

- 胜负、结束原因、双方点数和剩余牌数；
- 房间、下注显示单位、结算显示单位；
- 结算前后测试筹码余额；
- 托管回合数、人工控制比例和特殊事件；
- 结算截图哈希、来源时间、规则与策略版本。

样本状态：

- `eligible_controlled`：结算完整、无托管、逐回合覆盖≥95%、下注档位已知。
- `mixed_auto_play`：至少一次我方托管；只进入托管/机器人观察。
- `partial_turn_capture`：完成局但回合上下文不足。
- `missing_stake`：下注档位缺失。
- `incomplete_settlement`：有胜负动画但没有结算字段。
- `baseline_unknown`：历史局无法证明执行了哪种受控策略。
- `incomplete`：未完成或胜负未知。

## 8. RTP 与测试筹码

正式 RTP 仅在 `stake`、`gross_return`、`fee` 和 `net_delta` 口径认证后计算：

```text
RTP = SUM(gross_return) / SUM(stake)
```

必须逐局满足 `balance_after = balance_before + net_delta`。当前 `+360/-200`、`+1.8/-1` 仅保留为页面显示变化，不称为 RTP。高倍房测试应使用测试环境余额种子或重置，不通过长时间低倍局攒筹码替代测试准备。

## 9. 机器人评估

只评估可观察行为：合法出牌合规、响应时延、特殊牌处理、Last Card、我方剩余1–2张时的阻断行为、托管、重复动作和停顿。每个机器人动作必须带顶牌、对手可见牌数、合法动作上下文和状态结果；不足100个完整机器人动作时不评级智能水平。

## 10. 异常恢复与缺陷分级

- 窗口控制失败：重新绑定同一个普通 Chrome 标签，并重新校验域名与 URL；不得打开 PWA 或使用地址栏。
- 首页重绘：重新读取页面结构，只点击 `data-game-id=6001`。
- 提现/充值/付费奖励：关闭并记录，不进入流程。
- P0：真实资金路径可执行、余额跨环境串用、重复结算或非法扣款。
- P1：测试环境反复展示提现入口、结果/余额不一致、非法出牌。
- P2：托管、重连、动画或特殊状态阻断操作。
- P3：可访问性、布局、文案和一般性能问题。

## 11. 批次结束门禁

- 普通 Chrome、测试域名、WHOT 6001 三项门禁全程通过。
- 100局只计完成且范围正确的局；托管和结算缺失局需要补测。
- 数据库、运行回执、质量检查和报告数字一致。
- 每组策略至少25个合格完整局；结算覆盖≥95%、逐回合覆盖≥95%、托管率0、非法动作率0、决策到点击 P95≤2秒。
- 未认证 RTP、机器人智能和套利机制明确显示 `blocked` 或 `provisional`。
