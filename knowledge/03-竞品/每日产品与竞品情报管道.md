# 每日产品与竞品情报管道

## 目标

每天 19:33（Asia/Hong_Kong）收集 Waje 及主要竞品的产品、运营、商业化、市场、用户舆情和稳定性信息，保存原始证据，形成可追溯的日报，并累积到知识库供 Robin 后续分析和运营任务使用。

## 采集范围

| 主题 | 重点内容 |
|---|---|
| 产品动态 | 新玩法、版本更新、页面结构、登录、充值、提现、Cash Out、活动入口 |
| 运营动态 | 首存、返现、礼包、任务、排行榜、VIP、节日活动和渠道活动 |
| 商业化数据 | 下载量、评分、评论量、支付方式、促销门槛、公开收入/规模信号 |
| 用户舆情 | Google Play 评论、公开社媒/论坛反馈、支付和提现投诉、稳定性问题 |
| 市场资讯 | 尼日利亚及非洲博彩、支付、监管、竞品融资或重大合作动态 |
| 稳定性 | 加载、弱网、断线、白屏、崩溃、版本兼容和设备体验信号 |

## 执行链路

```text
数据源
  ↓
资讯/数据采集脚本
  ↓
原始快照（不可覆盖）
  ↓
清洗、标准化、去重
  ↓
主题分类、实体识别、情绪与重要性分析
  ↓
日报、周报、竞品变化报告
  ↓
知识库更新与代码图谱刷新
  ↓
Agent 查询、问题诊断和运营任务生成
```

## Google Play 用户评价子管道

- 配置：`config/play_reviews.json`；采集：`scripts/collect_play_reviews.mjs`。
- 公开页面评价采用浏览器懒加载滚动，原始快照保存至 `data/raw/play_reviews/YYYY-MM-DD/`，不保存登录凭据。
- Play 评价专项任务每日 20:20（Asia/Hong_Kong）执行 `scripts/run_play_reviews_pipeline.py --period daily`，使用 SQLite 索引 `data/processed/play_reviews/review_index.sqlite3` 按稳定评价 ID 去重，向历史回溯直到新增评价达到 200 条；历史未抓取内容不足时标记 `shortfall`。
- 每周一 08:00 执行 `scripts/run_play_reviews_pipeline.py --period weekly --skip-collect`，汇总上周一至周日并生成专项 HTML 周报；现有总周报仍在 10:00 运行并读取专项摘要。
- `--mode incremental` 不再等同于“最新 200 条”；专项入口传入 `--min-new-reviews 200 --backfill-unseen`。`--mode full` 仍用于人工全量回填或结构验证。
- 标准化、分析、质量回执和知识库输出分别由 `scripts/normalize_play_reviews.py`、`scripts/analyze_play_reviews.py`、`scripts/assess_play_reviews_quality.py` 和 `scripts/build_play_reviews_knowledge.py` 完成。
- 日报输出到 `knowledge/01-产品/Google Play用户评价/日报/`，周报输出到 `knowledge/01-产品/Google Play用户评价/周报/`；HTML 图表均有表格回退。
- 评价属于 D 级公开证据，只用于用户线索和运营优先级判断；资金、结算和故障结论必须用内部订单、客服和服务日志复核。

## 入库规则

- 原始网页、响应摘要和抓取时间保存到 `data/raw/YYYY-MM-DD/`，不覆盖历史快照。
- 经过清洗和去重的条目保存到 `data/processed/YYYY-MM-DD/`。
- 每日分析结果保存到 `data/outputs/YYYY-MM-DD/analysis.json`。
- 日报保存到 `knowledge/03-竞品/日报/`，只写入有来源的事实、推断和建议。
- 每日质量回执保存到 `data/outputs/YYYY-MM-DD/quality.json`，记录来源成功率、失败来源、去重率、旧新闻过滤量和人工复核量；公众号采集降级时在 `run-log.json` 中保留阶段状态。
- 只有经过人工或高可信来源确认的稳定结论，才回填到产品、数据或竞品主题笔记。

## 周一 HTML 周报

每周一 10:00（Asia/Hong_Kong）由独立本地任务 `robin-waje-html` 执行 `scripts/build_weekly_intelligence_html.py`，统计上周一至周日的日采集结果，产出：

- `knowledge/03-竞品/周报/YYYY-MM-DD-Waje竞品情报周报.html`：自包含可读 HTML，包含指标卡、原生图表、重点情报表、失败来源表和行动建议。
- `output/html/Waje-weekly-report.html`：ASCII-only 稳定预览入口，每次周报生成后自动刷新，适合浏览器重复打开，避免中文路径编码和旧 404 页面缓存问题。
- `data/outputs/weekly/YYYY-MM-DD/artifact.json`：canonical Data Analytics report 工件，供后续复用和二次发布。
- `data/outputs/weekly/YYYY-MM-DD/delivery-receipt.json`：校验、打包、浏览器验证状态及缺失日期回执。

报告对缺失日期或降级来源明确标记 `partial`，不补造数据；`P0/P1` 仍表示规则筛选候选，进入决策前必须回到原始公开页面核验。若本机无 Chromium，portable builder 会完成结构校验和打包，但回执会标记 `verification: structural_only`，需要在具备浏览器的环境补做视觉验收。

## 重要性分级

- P0：支付/提现异常、重复扣款、重大产品故障、监管变化、重大安全事件。
- P1：核心玩法或商业化变化、重要活动、明显用户投诉聚集、竞品版本变化。
- P2：普通活动、页面调整、单条评论、一般市场资讯。

## Agent 使用方式

Agent 默认先读取：

1. 最近 7 天日报；
2. 对应实体的历史情报；
3. 竞品分析报告和 JSON 工件；
4. 起源平台语义层和数据质量说明；
5. H5 稳定、弱网和资金链路相关规范。

回答时必须区分：原始事实、跨来源归纳、分析推断和建议动作，并返回来源与抓取时间。

配置入口：[`config/intel_sources.json`](../../config/intel_sources.json)、[`jobs/manifest.json`](../../jobs/manifest.json)。
