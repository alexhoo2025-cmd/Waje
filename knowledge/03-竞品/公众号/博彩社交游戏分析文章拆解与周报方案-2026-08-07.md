## 2. 后续精读时采用的文章拆解框架

### 2.1 分析逻辑

按以下顺序识别文章的推理链，而不是只摘录结论：

```text
问题/现象
  ↓
目标用户与产品场景
  ↓
关键假设与指标定义
  ↓
数据来源、样本和时间窗
  ↓
分群/漏斗/队列/对比分析
  ↓
机制解释与证据校验
  ↓
产品或运营动作
  ↓
验证指标与复盘周期
```

逐篇文章至少抽取：

- 研究问题：是在解释增长、留存、付费、玩法差异，还是判断市场机会。
- 分析对象：用户、游戏、渠道、活动、版本、地区、支付方式或社交关系。
- 分析单位：注册用户、活跃用户、付费用户、局、下注、订单、会话或社交关系。
- 分母与口径：留存分母、付费转化分母、RTP 的 stake/payout 口径、收入是否扣除奖金和退款。
- 证据等级：原始数据、平台公开数据、访谈/案例、作者推断或营销性观点。
- 结论到动作：结论是否能对应到产品改版、活动调整、支付优化或监控指标。

### 2.2 产品/业务分析骨架

用于 Waje 的默认报告骨架：

1. **结论先行**：用 2–4 条结论回答“发生了什么、影响多大、应该做什么”。
2. **用户与场景**：新用户、回流用户、付费用户、重度用户、不同包/渠道/地区。
3. **产品结构**：大厅、首局、任务、福利、玩法、资金、社交、消息和提现。
4. **核心链路**：曝光 → 注册 → 首次进入玩法 → 首次下注 → 首次奖励 → 首充 → 复访/复购。
5. **玩法对比**：Fish、Slots、Whot、Crash、Roulette、Blackjack 等按机制和目标拆分。
6. **商业化与资金链路**：首存、礼包、BonusChip/Coin、有效下注、提现门槛和失败率。
7. **留存与生命周期**：D1/D3/D7、首局后留存、首充后留存、不同玩法迁移和 LTV。
8. **异常与验证**：加载、扣款、奖励、RTP、版本、弱网、提现和埋点完整性。
9. **动作与验收**：P0/P1/P2、责任方、预计收益、验证指标和回归周期。

## 3. 排版与图表借鉴规范

在获得原文截图后，再补充原文章的具体字体、颜色、段落间距和图表样式。当前先定义团队可复用的排版规范：

### 3.1 排版

- 标题直接表达结论或决策问题，不使用空泛标题。
- 标题后先放 Executive Summary，再放口径和证据，避免先讲方法让读者失去主线。
- 每个大段采用“结论标题 → 证据 → 解释 → so what → 下一步”的固定节奏。
- 一段只承担一个核心观点；长文使用 3–5 行的短段落和小标题。
- 精确数字放表格，趋势和差异放图表，方法细节放附录/来源信息。
- 每张图表紧邻一段解释，明确读法、分母、时间窗和限制。

### 3.2 推荐图表形式

| 分析问题 | 推荐图表 | 适用字段/指标 | 解释重点 |
|---|---|---|---|
| 新手转化漏斗 | 漏斗图 | 注册、首局、首充、复访、提现 | 每一步转化和最大流失点 |
| D1–D30 留存 | 队列热力图/折线图 | 注册日期、活跃日期、留存率 | 版本、渠道、玩法入口差异 |
| 玩法收入/下注结构 | 堆叠柱状图 | 游戏、stake、payout、收入 | 规模和结构不能混为一谈 |
| RTP/真实回报 | 控制图/分布图 | 理论 RTP、实测 RTP、样本量 | 置信区间、异常日和版本切换 |
| 玩法难度 | 气泡散点图 | 首局耗时、操作步骤、失败率、复玩率 | 易学性与复玩价值的权衡 |
| 付费与生命周期 | LTV 阶梯/队列折线 | D0/D1/D3/D7/D14 LTV | 首充、复购和奖金成本影响 |
| 渠道质量 | 分组柱状/箱线图 | 新增、付费率、LTV、留存、退款 | 避免只按新增量排名 |
| 异常定位 | 时间序列 + 版本标记 | 加载失败、扣款失败、奖励失败 | 识别发版或配置变更关联 |

## 4. 博彩/社交游戏重点指标层

### 4.1 玩法层

- 局数、下注额、有效下注额、派奖额、净输赢、理论 RTP、实测 RTP、命中率、波动代理指标。
- 首局进入率、首局完成率、玩法迁移率、复玩率、玩法间交叉渗透。
- 玩法加载成功率、加载耗时、iframe 错误、断线重连成功率。

### 4.2 新手与生命周期层

- 注册 → 首次登录 → 首次进入游戏 → 首次下注 → 首次奖励 → 首充 → D1/D3/D7 留存。
- 首充用户与非首充用户的留存、LTV、玩法偏好和提现行为。
- 任务完成率、福利领取率、奖励到账率、奖励后的有效下注率。

### 4.3 商业化与资金层

- 充值成功率、支付方式成功率、支付回调延迟、充值金额分布、礼包购买率。
- BonusChip、Chip、Coin 分开统计：发放、消耗、转换、过期、撤回和余额占比。
- 提现申请率、成功率、失败率、处理时长、失败原因和人工介入率。

### 4.4 社交层

- 邀请、好友关系、组队/房间、排行榜、分享、聊天/互动触发率。
- 社交行为发生后的 D1/D7 留存、付费率和玩法复玩率。
- 社交关系强度与用户价值之间的相关关系，避免把相关性直接当成因果。

## 5. 数据质量与 RTP 口径

理论 RTP 必须优先取 GM/配置数据；实测 RTP 只用于发现偏差和版本异常：

```text
实测RTP = Σ payout / Σ valid_stake
净回报率 = (Σ payout - Σ valid_stake) / Σ valid_stake
命中率 = payout_rounds / valid_rounds
```

所有概率和 RTP 报告都必须同时保留：游戏、版本、币种、下注档位、用户类型、时间窗、有效样本量、奖金是否计入 payout、取消/重试/重复订单处理规则。

## 7. 周报模板与执行计划

### 7.1 周报固定结构

1. 本周新增文章与主题变化。
2. 一篇重点文章的逻辑/框架/排版精读。
3. 博彩/社交游戏产品趋势：玩法、留存、付费、支付、提现、社交机制。
4. 对 Waje 的可迁移启示：产品、数据、运营、研发各 1–3 条。
5. 本周新增指标或可复用图表模板。
6. P0/P1 风险和待核验事实。
7. 下周跟踪清单。

### 7.2 执行计划

- 每日 19:33（Asia/Hong_Kong）采集；每周五 19:33 汇总生成专项周报。
- 先读取本文件、过去 4 周周报和每日情报数据，再采集公开新增文章。
- 通过公众号/内容平台提供的只读授权 API 获取文章列表和正文 HTML；若 API 尚未接通，使用研发提供的授权 HTML/JSON/ZIP 导出作为等价输入。
- 保存原始快照，清洗、去重、提取指标和图表类型，追加知识库并生成周报。
- 指定公众号文章若仍无法访问，周报中明确列为“待人工提供正文/截图”，不编造文章结论。
- 认证信息只通过环境变量或密钥管理注入，不保存 AppSecret、Token、Cookie、密码或个人数据。
