## 1. 目录摘要

“版本数据分析”不是单一版本报表，而是一组历史分析工作簿和专题文档，覆盖以下分析链路：

`用户/渠道 → 启动与埋点 → 充值/提现 → 游戏参与 → TC/RTP/TX → 留存/LTV → 风控/KYC`

当前共识别 14 份子文档：

- 10 份以飞书表格为主，适合后续导出后建立结构化数据集。
- 4 份以正文、附件或分析图为主，适合沉淀业务规则、漏斗定义和结论。
- 时间范围混合 2025 年 10–11 月、2026 年 3–7 月，以及未明确日期的历史工作表；不能直接拼接为一条连续趋势。

## 3. 已确认的字段与指标线索

### 3.1 充值/提现与玩家价值

在 `waje游戏tc比分析` 当前可见表头中，至少包含：

| 字段 | 业务含义线索 | 使用注意 |
|---|---|---|
| 玩家id | 玩家级关联键 | 需确认是账号 ID、起源 ID 还是其他内部 ID |
| 当天充值金额/当天提现金额 | 当日资金行为 | 需要明确统计日期、成功状态和币种 |
| 历史充值金额/历史提现金额 | 历史累计资金行为 | 不能与当前日窗口直接混用 |
| 当天充值比/历史充值比 | 充值相对其他资金指标的比例 | 正式分子、分母待确认 |
| 当天累计充值总额/历史累计充值总额 | 累计金额 | 需区分订单成功、到账和退款/冲正 |
| 当天充值档位/历史充值档位 | 充值分层 | 需要保留档位边界和版本生效时间 |

### 3.2 额外赠送货币规则

`额外赠送货币统计` 正文提供了可直接沉淀的业务规则：

- 统计各类型额外赠送货币，并加入起源分析。
- 基础 chip 之外的额外 chip 计入；Bonus 不计入。
- 白银升级版周卡需特殊处理：示例为充值 39,999 = 38,000 chip + 4,000 chip + 30 chip × 7。
- 正文给出的计算示例：额外 chip = 4,000 + 30 × 7 − 2,000 = **2,210 chip**。
- 黄金升级版周卡说明为同理处理，但具体商品规则需要从商品字典或订单明细复核。

这组规则目前应视为“历史业务口径”，正式用于资产、LTV 或利润分析前，需要补充商品 ID、订单状态、发放时间、资产类型和冲正规则。

### 3.3 KYC/人脸识别漏斗

两个 KYC 文档使用相近但不完全相同的表述：

1. 风险 TX 触发 KYC 校验。
2. 用户填写 BVN/NIN，完成身份验证。
3. 用户通过 BVN/NIN 中至少一项。
4. 用户在身份验证后进一步完成人脸识别。

`人脸识别分析报告` 正文确认 2026-07-24 统计中有 1,052 名玩家进入身份验证流程；后续阶段数据主要位于附件或图片中，尚未将图片中的完整数字转录入库。KYC 分析应至少保留以下事件和分母：`kyc_triggered`、`identity_started`、`bvn_or_nin_passed`、`face_requested`、`face_passed`、`face_failed`、`face_abandoned`。

## 5. 入库后的统一口径要求

后续将这些历史文档转成可复用数据集时，建议每张表增加以下元数据字段：

`source_doc`、`source_url`、`sheet_name`、`snapshot_date`、`analysis_date_start`、`analysis_date_end`、`platform`、`app_version/package`、`user_key_type`、`currency`、`metric_definition_status`。

重点统一：

- **用户键**：账号 ID、起源 ID、设备 ID、玩家 ID 不可默认互换；每张表必须登记实际去重键。
- **时间**：历史累计、当日窗口、cohort 日期、自然新增日期和文档修改日期分开保存。
- **金额**：充值、提现、下注、返利、赠送和收益必须标注币种、单位、成功状态和正负方向。
- **端与版本**：App/H5、新包/旧包、软件版本、热更新版本和渠道包需拆成独立维度。
- **玩法**：游戏、玩法、模式、场次、下注档位和串关不能只用展示名关联，需补 ID 或字典映射。
- **漏斗分母**：首充留存、TX 留存、KYC 转化和人脸识别通过率必须保留每一层起始人数。

| Naira Slot | 传统老虎机，转轮/图案组合触发派奖 | 学习成本低、节奏快、连续旋转，反馈强但决策少 | 结果通常由符号权重、线路/投注档位和奖表决定；重点看理论 RTP、命中率、波动率、大奖尾部，不应只看短期实际 RTP | 转轮权重、奖表、线路、Bonus/免费转、理论 RTP |
| Roulette | 轮盘押注，单号、颜色、区间等多种投注 | 规则直观，单局快；高赔率投注带来强波动，低赔率投注更平滑 | 不同投注区的命中概率和赔率不同；零/双零规则会形成固定庄家优势，需区分欧式/美式及各投注区 RTP | 轮盘类型、零位规则、各投注区赔率、单局结果 |
| Jack or Better | 视频扑克，发牌后保留/替换牌，以达到最低牌型获奖 | 有明确策略空间，玩家会感知“选择影响结果”；节奏中等 | 概率取决于牌型赔率、换牌规则和玩家策略；应区分随机理论 RTP 与最优策略 RTP，不能按老虎机口径直接比较 | 牌型奖表、牌堆、换牌次数、策略/自动选择逻辑 |
| Fish | 捕鱼/射击类，消耗炮弹击打目标并按目标掉落奖励 | 动作反馈、连续击打、目标追逐和奖励掉落带来沉浸感；高频重复投入 | 概率由鱼种权重、击杀概率、炮倍/消耗和奖励表共同决定；重点是每炮期望、命中率、单位下注 RTP 和波动率 | 鱼种/倍率、炮倍、击杀判定、掉落表、多人房间影响 |
| Dice | 骰子/颜色/区间等结果上的概率投注 | 极易理解、单局极短、适合快速重复下注；风险反馈非常直接 | 可枚举结果空间，赔率与命中概率直接决定理论 RTP；应检查随机数、结果分布和不同下注选项的理论回报是否一致 | 结果空间、投注选项、赔率、RNG、理论 RTP 配置 |
| Tada-Fortune Coins | 金币/转盘/奖励触发类短局玩法（具体规则待核验） | 主题化、即时奖励和轻量操作，通常比传统桌面玩法更偏“抽取反馈” | 概率重点在奖励层级、触发频率、大奖尾部和保底/限额机制；需区分基础奖励与活动/赠送奖励 | 触发条件、奖励池、保底、活动加成、实际 RTP |
| Tada-Money Coming | 以金币/现金流入为主题的奖励型短局玩法（具体规则待核验） | 正向反馈强，容易形成连续点击和追奖体验 | 重点看中奖频率、奖励金额分布、长尾大奖和玩家净输赢；名称不能推断真实回报率 | 奖励分布、触发概率、封顶/限额、派奖状态 |
| Tada-Chicken Dash | 以鸡/闯关或躲避推进为主题的短局玩法（具体规则待核验） | 过程感和即时决策可能强于纯老虎机，适合短周期连续游玩 | 若存在逐步加奖或提前结束机制，风险由停止时点和结果分布共同决定；应分析不同阶段的退出率、倍率和尾部损失 | 阶段/格数、提前结束、倍率曲线、失败概率、RTP |

### 横向结论

- **低学习成本、高频型**：Naira Slot、Dice、Tada 系列通常更适合快速循环；核心体验指标是首局启动率、局间间隔、连续局数和短期复投。
- **动作沉浸型**：Fish 依赖视觉反馈、击打反馈和奖励掉落；不能只看局数，应按“炮/次下注”计算消耗、命中和 RTP。
- **规则/策略型**：Whot、Jack or Better、Roulette 的体验更受规则理解和选择影响；应同时看不同玩家层级、投注选项或策略的表现。
- **概率透明度差异**：Dice、Roulette 的结果空间和理论概率相对容易解释；Slot、Fish、Tada 系列通常依赖隐藏权重、奖表、触发器或阶段机制，必须取得配置才能判断是否正常。
- **RTP 不等于体验好坏**：RTP 反映长期期望回报，不代表单日或小样本结果。比较时至少同时观察下注额、局数/炮数、命中率、基础回报比、真实回报比、波动率、P5/P50/P95 回报和大额异常。

### 建议的统一比较指标

| 维度 | 指标 |
|---|---|
| 规模 | 活跃人数、参与人数、局数/炮数、下注额 |
| 回报 | 基础回报比、真实回报比、派奖额、毛利 |
| 概率 | 命中率、中奖频率、理论 RTP、实际 RTP、RTP 偏差 |

| 分层 | 游戏、玩法/投注档位、日期、版本、分包渠道、归因媒体、生命周期 |

## 9. 新包与生命周期分析执行口径

### 已确认口径

- 导数时剔除不完整天；具体应记录数据截止时间，并避免将未结算日期纳入趋势、留存或生命周期结论。
- 导出的结果中剔除值为 0 的记录；但需保留“0 是真实值还是缺失/默认值”的判断说明，不能无条件把 0 当作缺失。
- 新包分析入口：起源 → 报表集市 → 新增付费用户分析。
- 渠道筛选：按“分包渠道”和“归因媒体”切分。例如分析 `wajespecial` 包的 Facebook 数据时，筛选分包渠道=`wajespecial`、归因媒体=`facebook`；若只看包维度，则只筛选分包渠道。
- 生命周期重点关注：下注额、基础回报比、真实回报比；导出原始数据后再按游戏、日期、版本/包和渠道分析。

### 待确认与执行记录

- “新包”是否仅指 H5 版本，还是同时包含新版 App 包，需在分析前明确端类型、软件版本和包名范围。
- Ryan 数据通常多久返回尚未确认；应补充数据请求时间、返回时间、数据截止时间和完整日标记，形成可追踪的 SLA 记录。
- 若找不到“新增付费用户分析”，先核对报表权限、报表集市分组、BQ/非 BQ 版本及关键词；仍无法定位时记录页面截图或 URL，避免把权限问题判断为数据缺失。
