# Waje TC异常、RTP与资产流水诊断框架

> 适用场景：全站或某个包体、渠道、游戏的提充比突然升高，需要判断是否来自正常大额赢钱、游戏回报异常、奖励资产、账务/服务器问题或风险用户结构变化。

## 1. 核心原则：从宏观异常走到微观资产解释

    提充比异常
      → 核对统计口径与完整日
      → 拆分充值、提现、RTP、Bonus、游戏和渠道
      → 判断是否由少数大额赢家集中贡献
      → 在受限环境核对异常用户的资产流水
      → 找到每一笔可提现资产的合法来源
      → 输出正常波动 / 奖励影响 / 需排查Bug或风险

**目标不是把高提充比直接定义为羊毛或Bug。** 目标是解释资金为什么流出，并确认每一笔可提现资产都能追溯到现金充值、有效游戏结算、合法奖励、退款/冲正或明确的后台调整。

## 2. 指标定义与关系

| 指标 | 公式 | 回答的问题 | 不能说明什么 |
|---|---|---|---|
| 平台日TC / 提充比 | 成功提现金额 ÷ 成功现金充值金额 | 当日资金流出相对流入是否异常 | 不等同用户盈利率，不等同RTP |
| 首充后T+k TC | T0至T+k成功提现 ÷ T0至T+k全部成功现金充值 | 某一首充批次的短期资金流出结构 | 分母不能只用首充金额 |
| 用户TC | 单用户窗口成功提现 ÷ 同窗口成功现金充值 | 高提充人群是否集中 | 高于100%不自动等于异常 |
| 实际RTP | 最终派奖合计 ÷ 有效真金下注合计 | 游戏回报是否偏离预期 | 不包含未纳入结算口径的资产变动 |
| 预期RTP | 1 − 预期盈利合计 ÷ 有效下注合计 | 当前配置下理论回报基线 | 不能代替实际服务端结算 |
| GGR | 有效下注 − 最终派奖 | 游戏毛收入与派彩方向 | 不等同现金流或净利润 |
| Bonus贴水/补贴影响 | 完全实际RTP − 基础实际RTP | 奖励、补贴对玩家回报的增量 | 不等同RTP偏离或TC |

### RTP 与 TC 的非线性关系

RTP偏高会增加玩家赢钱和可提现资产的可能性，因此可能推高TC；但两者**不是线性关系**。

- RTP正常、TC升高：少数玩家中了大奖；历史余额在本期提现；奖励资产转为可提现；退款/补发进入提现；提现与充值跨日；或存在未进入RTP公式的资产异常。
- RTP偏高、TC未升高：玩家继续下注、未达提现门槛、提现仍审核中，或资金尚未转为现金可提资产。
- RTP正常不能排除服务器Bug：少量无来源资产可能几乎不影响全站下注和派彩，却足以拉高提现金额。

## 3. 标准四层诊断

### 第一层：宏观核验——确认异常真实存在

固定先输出最近7个完整自然日，并与前7日或同星期基线对比：

| 指标 | 核验要求 |
|---|---|
| 成功现金充值人数/金额 | 排除失败、退款、冲正、Bonus和测试订单 |
| 成功提现人数/金额 | 只计最终打款成功；申请、审核中、拒绝单独展示 |
| 平台TC | 先汇总金额后计算，禁止平均每日TC |
| 实际/预期RTP、GGR | 按有效下注和最终派奖重算 |
| Bonus发放/消耗/转可提现 | 现金、不可提奖励、可提奖励必须分开 |
| 完整日、时区、延迟 | 当前日、未结算日、迟到分区不进正式结论 |

**先查口径，不先找原因。** 若提现分子混入申请单、充值分母只取首充、退款重复扣减或日期不完整，先修正指标，不能进入业务诊断。

### 第二层：结构拆分——找出异常贡献来自哪里

每项指标至少按日期、端/包体、渠道/媒体、游戏/玩法、版本/配置、新老用户/首充批次、首充金额档位、KYC/风险状态、提现状态拆分。每组同时展示金额、人数、占比、TC、实际RTP与样本量。

优先回答：

1. 哪个游戏、玩法、版本或渠道贡献了提现增量？
2. 是实际RTP偏离、Bonus增加，还是资金行为结构改变？
3. TC上升来自大额提现金额、提现人数上升，还是充值金额下降？
4. 变化发生在所有人群，还是集中于一个小分组？

### 第三层：尾部贡献——区分正常大奖与结构异常

必须同时观察：

- 用户TC的P50、P90、P99；
- TC大于100%、大于200%用户占比；
- Top 1%、Top 10%用户对提现增量的贡献；
- 高TC用户的有效下注、有效局数、Bonus占比、提现时延与审核结果；
- 单游戏最大派彩、下注额、实际RTP、预期RTP和大额派奖次数。

| 结构特征 | 初步解释 | 下一步 |
|---|---|---|
| 少数高下注、高派奖用户集中贡献，结算/账本可对上 | 正常大奖或高波动 | 持续观察 |
| 多个中小额用户同时高TC，且有效游戏参与低 | 奖励套利、风控漏检或资产异常候选 | 进入受限用户核查 |
| 某游戏实际RTP持续偏离预期，且有效下注/局数充足 | 数值、结算或配置异常候选 | 按玩法、版本、配置复核 |
| 资产增加找不到充值、结算、奖励、退款或后台调整来源 | 账务/服务器完整性异常 | P0排障，冻结相关结论 |

### 第四层：受限用户级流水审计——解释资产来源

只有在宏观和结构层发现异常后，才在企业BigQuery或外部生产Metabase的受限环境中，以匿名用户键关联，不导出用户明细。

    期初资产
    → 成功现金充值
    → Bonus / 免费资产 / 补偿
    → 有效下注
    → 最终结算 / 派奖
    → 退款 / 冲正 / 后台调整
    → 可提现余额变化
    → 提现申请 / 审核 / 打款成功
    → 期末资产

每个资产类型单独对账：

    期末余额 - 期初余额
    = 现金充值 + 合法奖励 + 最终派奖 + 退款/调整
    - 有效下注 - 成功提现 - 手续费

若存在无法解释的残差、无来源可提现资产、结算重复、订单状态矛盾或余额守恒失败，标记为 **P0资金完整性异常**。用户级流水只用于受限核查；报告仅展示脱敏聚合、异常数量和原因分类。

## 4. Bonus 与奖励资产专项检查

免费奖励不能只看发放金额。必须分别核对：

| 核查项 | 目的 |
|---|---|
| 奖励来源、活动、配置版本 | 判断是否来自预期运营机制 |
| 奖励资产类型 | 区分不可提现Bonus、可玩代币、现金和可提现资产 |
| 发放、消耗、过期、回收、转现金金额 | 识别多发、重复发放或转换异常 |
| 奖励后有效下注与结算 | 判断是否形成真实游戏行为 |
| 奖励转可提现的路径和金额 | 排查奖励套利或错误资产转换 |
| 单用户/单设备/单活动领取次数 | 排查重复领取和规则绕过 |

正常活动带来的奖励增发、已配置的首充带币、人工补偿、退款/冲正都不能直接判为Bug；必须先核对配置生效范围和账务原因码。

## 5. RTP 审计规则

1. 使用服务端最终结算和有效下注，先汇总金额再计算RTP；不得平均每日RTP。
2. 同时展示基础/完全口径、实际/预期口径、差异（pp）、有效局数、参与人数和下注额。
3. 必须按日期 × 游戏 × 玩法 × 配置版本 × 端/包体拆分；样本不足只作观察，不判异常。
4. 单日RTP超过100%可能是正常波动；判断持续偏离时必须结合下注额、局数、最大派彩和连续天数。
5. 退款、取消局、未结算局、免费注、Bonus注、机器人和测试账号必须有明确纳入/排除规则。
6. RTP只解释纳入游戏结算口径的回报，不替代现金流、提现或资产完整性审计。

## 6. 数据来源与优先级

| 主题 | 控制来源 | 角色 |
|---|---|---|
| 充值、提现、资产、订单状态 | 企业BigQuery服务端订单/账本；受控Metabase核查 | 资金事实 |
| 下注、结算、派奖、RTP | GM Lifecycle Pool V2 / 起源BQ游戏报表 / 服务端游戏账本 | 游戏事实 |
| 版本、配置、活动、Bonus规则 | 配置快照、发布记录、命中日志 | 解释线索，不能替代事实 |
| 渠道、媒体、包体、KYC、风险规则 | 用户维表、归因事实、KYC/审核服务端记录 | 分组和归因 |
| 客户端埋点、GA4、Firebase | 页面、性能、行为路径 | 体验诊断，不替代资金/结算事实 |

来源冲突时，优先级为：**服务端账本/订单 > 服务端结算 > 认证汇总View > 起源/GM报表 > 客户端埋点 > 配置文档/沟通记录**。

## 7. 结论标签、报告结构与门禁

| 标签 | 使用条件 | 行动 |
|---|---|---|
| 正常波动 | 大奖集中、账本与结算完整对账，无异常资产残差 | 保留监控 |
| 奖励/运营影响 | Bonus或活动配置与资金变化同向，资产来源可解释 | 评估成本与风控护栏 |
| 需复核 | TC/RTP/提现结构异常，但资产来源未完整解释 | 补齐维度和受限核查 |
| P0资金完整性异常 | 无来源资产、余额不守恒、重复结算、订单/账本矛盾 | 立即排障，冻结相关结论 |
| 数据阻断 | 口径、日期、资产类型、配置版本或关联键不完整 | 显示 blocked / N/A，不作业务判断 |

固定报告结构：

    核心结论
    → 宏观资金与RTP趋势
    → 游戏/渠道/版本拆分
    → 大奖集中度与用户TC分布
    → 奖励与资产解释
    → 受限流水核查结果
    → P0/P1动作
    → 附录：口径、完整日、版本/活动节点、阻断项

高TC本身不是风险标签。只有高TC与至少一项独立信号同时出现时，才进入异常核查：低有效游戏参与、Bonus依赖、无来源资产、快速提现、关联风险命中、异常结算或账本残差。

## 8. 必备字段与质量门禁

P0字段：匿名用户键、订单/提现/账本流水键、服务端时间、游戏/玩法/局/配置版本、现金充值、Bonus、有效下注、最终派奖、资产类型与变动原因、期初期末余额、提现/审核状态、包体/渠道/媒体/版本。

硬门禁：

- 成功充值、成功提现、账本和结算使用唯一订单/流水键去重；
- 金额、币种、最小单位、手续费、退款/冲正规则已经确认；
- 订单—账本—资产关联率不低于99%，金额差异不高于0.1%；
- 资产期初期末守恒；不能解释的残差单独输出；
- 当前日、未结算日、迟到分区不进入正式TC/RTP结论；
- 小分组少于30名相关用户不展示，或标记为小样本；
- 不导出用户、银行卡、KYC、生物特征、IP或设备标识明细。
