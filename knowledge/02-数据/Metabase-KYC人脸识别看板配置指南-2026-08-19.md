# Metabase｜KYC 人脸识别看板配置指南

> 适用对象：Robin、数据分析、产品、风控及 Metabase 管理员。  
> 目标：使用当前已接入的 KYC 脱敏日汇总，配置“认证漏斗、趋势、失败诊断、BVN/NIN 与端包对比”看板；不访问或展示敏感身份与生物特征明细。

## 1. 先确认权限与数据源

### 1.1 最小权限

| 权限 | 谁开通 | 作用 |
|---|---|---|
| Collection `Curate` | Metabase 管理员 | 创建、保存、编辑问题和仪表盘 |
| KYC 聚合数据集的查看与创建查询权限 | 数据平台管理员 | 用查询构建器创建图表、修改问题 |
| 禁止原始敏感列和下载 | 数据/风控负责人 | 隔离 BVN/NIN、手机号、人脸/证件、三方原始响应 |

> 仅有 Collection `Curate` 不足以创建图表；还必须对底层聚合数据集拥有查询权限。

### 1.2 推荐目录

```text
Waje
└── Risk & KYC
    └── 人脸识别
        ├── Models
        ├── Questions
        ├── KYC 人脸识别运营与体验监控 V1
        └── 羊毛分析（受限）
```

所有 KYC 问题与仪表盘保存在同一 Collection，避免看板因跨 Collection 权限不足出现“锁定卡片”。

### 1.3 数据源核对

在 Metabase 左侧“浏览数据”中找到已接入 KYC 日汇总表或 Model，确认至少存在：

```text
日期、流程、端、包名、每日触发人数、实际调用BVN/NIN人数
BVN/NIN调用/通过/失败、请求人脸人数与次数
最终人脸成功/失败、当前保留失败原因、成功后清除失败原因
```

字段不存在时，先停止配置对应卡片，不使用 0 或模拟值替代。

## 2. 建立基础 Model

### 2.1 名称与字段设置

创建或复用一个 Model：`KYC 人脸认证日汇总`。

| 原字段 | 显示名 | 类型/展示建议 |
|---|---|---|
| 日期 | 统计日期 | Date |
| 流程 | 认证流程 | Category：提现触发、主动认证 |
| 端 | 终端 | Category：App、H5 |
| 包名 | 包体 | Category/Search |
| 每日触发人数 | 触发认证人数 | Number，整数 |
| 请求人脸识别人数 | 请求人脸人数 | Number，整数 |
| 最终人脸识别成功人数 | 最终人脸成功人数 | Number，整数 |
| 最终人脸识别失败人数 | 最终人脸失败人数 | Number，整数 |

描述中明确：所有人数当前为“每日按用户去重后再累计的人次”；跨日不能视作独立用户数。

### 2.2 计算字段

在“自定义列”或“汇总 > 自定义表达式”中增加：

```text
最终人脸结果人数 = 最终人脸成功人数 + 最终人脸失败人数
无最终结果人数 = 请求人脸人数 - 最终人脸成功人数 - 最终人脸失败人数
认证启动率 = 实际调用BVN/NIN人数 / 每日触发人数
人脸成功率（请求口径） = 最终人脸成功人数 / 请求人脸人数
人脸成功率（结果口径） = 最终人脸成功人数 / 最终人脸结果人数
端到端成功率 = 最终人脸成功人数 / 每日触发人数
```

除法分母为 0 时显示为空值或 `N/A`，不要显示 `0%`。

## 3. 创建 7 个保存问题

统一保存位置：`Waje / Risk & KYC / 人脸识别 / Questions`。名称以 `KYC V1 -` 开头。

### Q01｜核心 KPI

- **查询：** 汇总触发、实际调用、请求人脸、最终成功、无最终结果。
- **图表：** Number，五张独立指标卡。
- **说明：** 无最终结果率＝`无最终结果人数 ÷ 请求人脸人数`。
- **默认筛选：** 最近 30 个完整自然日。

### Q02｜认证全流程漏斗

- **阶段：** 触发认证 → 实际调用 BVN/NIN → 请求人脸 → 最终人脸结果 → 最终人脸成功。
- **首选图表：** Funnel。
- **前提：** 漏斗数据必须为两列结构：`阶段名称`、`阶段人数`，并按阶段顺序返回。
- **无 SQL 权限时：** 使用横向条形图或 KPI 序列替代，不将多个独立数字卡伪装成 Funnel。

### Q03｜每日效率趋势

- **查询：** 按统计日期分组，汇总认证启动率、BVN 通过率、NIN 通过率、人脸成功率（请求口径）、无最终结果率、端到端成功率。
- **图表：** 多序列 Line；仅保留 4–6 条线，避免不可读。
- **建议拆分：** 效率趋势与无最终结果率分两张图，避免量纲和颜色过多。

### Q04｜失败原因趋势

- **查询：** 按日期汇总人像不匹配、请求接口失败、三方接口错误。
- **图表：** Stacked bar；另建 Donut 展示所选时间内构成。
- **醒目说明：** 当前字段是失败尝试次数，不是失败用户数；成功后部分原因会被清除。

### Q05｜流失阶段

- **计算：**
  - 触发后未调用＝触发－实际调用。
  - 调用后未请求人脸＝实际调用－请求人脸。
  - 请求后无最终结果＝请求人脸－最终成功－最终失败。
  - 最终失败＝最终人脸失败。
- **图表：** Bar；按流程、端、包体比较。

### Q06｜BVN / NIN 认证统计

- **查询：** BVN/NIN 调用、通过、失败、仅 BVN、仅 NIN、双调用。
- **图表：** Grouped bar + Table。
- **规则：** BVN 与 NIN 分开计算通过率，禁止合成单一身份认证通过率。

### Q07｜端与包体对比

- **查询：** 按端、包体分组，显示触发、请求人脸、最终成功、人脸成功率（请求口径）、无最终结果率。
- **图表：** Table；按无最终结果率倒序。
- **扩展：** 渠道、版本、配置版本字段接入后，增加为筛选器，不复制新看板。

## 4. 组合仪表盘

### 4.1 创建步骤

1. 点击右上角 **+ New → Dashboard**。
2. 名称填写：`KYC 人脸识别运营与体验监控 V1`。
3. 保存到 `Waje / Risk & KYC / 人脸识别` Collection。
4. 在编辑状态逐一添加 Q01–Q07。
5. 添加一个 Heading/Text 卡片，写入数据口径、数据状态和敏感信息限制。

### 4.2 推荐布局

```text
第一行：触发｜实际调用｜请求人脸｜最终成功｜无最终结果率
第二行：认证全流程漏斗（宽）｜流失阶段（窄）
第三行：每日效率趋势（宽）｜失败原因构成（窄）
第四行：失败原因趋势（宽）｜BVN/NIN 统计（窄）
第五行：端与包体对比表（全宽）
```

将 Dashboard Width 设置为 Full width；日汇总数据不启用高频自动刷新，默认手动或 D+1 更新。

## 5. 配置全局筛选器

| 筛选器名称 | 类型 | 默认/选项 | 连接卡片 |
|---|---|---|---|
| 日期 | Date range | 最近 30 个完整自然日 | Q01–Q07 |
| 认证流程 | Category，多选 | 提现触发、主动认证 | Q01–Q07 |
| 端 | Category，多选 | App、H5 | Q01–Q07 |
| 包体 | Search box | 按包名模糊检索 | Q01–Q07 |
| 渠道 | Category，多选 | 字段接入后启用 | Q01–Q07 |
| 版本 | Search box | 字段接入后启用 | Q01–Q07 |

每新增一个 Dashboard filter，都必须手动连接到每张相关卡片的同名字段。若采用原生 SQL 问题，日期与类别筛选需使用 Field Filter；只用普通变量会限制多选和日期范围能力。

建议关闭 Auto-apply filters：同时调整流程、端、包体时，用户点击 Apply 后再刷新，可减少多卡并发查询。

## 6. 2.20 SDK/V2 增强页

2.20 人脸 V2 与 SDK 数据稳定后，在同一看板新增 Tab：`SDK 体验与提现结果`。

| 区域 | 新增指标 |
|---|---|
| SDK 拉起 | SDK 拉起成功率、黑屏/相机拉起失败率、启动耗时 |
| 摄像头与活体 | 权限同意/拒绝、活体开始/成功、超时率 |
| 人证比对 | FaceMatch 通过率、失败码、重试挽回率、每日限额触发率 |
| 提现结果 | 认证后再次提现率、提现提交率、审核率、提现成功率、拦截率 |
| 发布诊断 | 端、包体、APP/H5 版本、渠道、配置版本、风险规则版本 |

SDK 页面必须用 `withdraw_id`、`request_id`、`trace_id` 关联服务端结果；不以客户端“成功页”替代服务端认证或提现事实。

## 7. 发布前检查

- [ ] Q01–Q07 均保存在同一 KYC Collection。
- [ ] Dashboard 筛选器已逐卡连接并测试 App/H5、流程、包体组合。
- [ ] Metabase 数值与现有 KYC 日汇总按日期、流程、端、包体逐日对账。
- [ ] “无最终结果”单独显示，未被计为主动放弃或失败。
- [ ] 失败原因卡片注明“尝试次数”且标明历史不完整。
- [ ] 任何原始身份、人脸、证件和三方响应都未出现在普通看板、筛选器或导出中。
- [ ] V1 标记为 `provisional`；2.20 数据接入并对账后再提升为正式监控。
