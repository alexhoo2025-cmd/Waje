# 轻量化游戏分析：指标口径与数据验证清单

## 一、建议固定的分析漏斗

```text
新注册用户
  → 游戏入口曝光
  → 游戏入口点击
  → 游戏加载成功
  → 首局开始
  → 首局完成
  → 第 2—3 局
  → 11 局以上/深度游戏
  → D1/D3/D7 留存
  → 首次付费/复购
```

## 二、核心指标定义草案

| 指标 | 建议定义 | 关键分母/限制 |
|---|---|---|
| 新注册用户数 | 统计日完成注册的去重用户数 | 统一使用 user_id，不使用设备 UV 替代 |
| 游戏入口点击 UV | 新注册用户中至少触发一次入口点击的去重用户数 | 需固定入口事件 ID 和时间窗口 |
| 点击用户率 | 游戏入口点击 UV / 新注册用户数 | 按注册日 cohort 计算 |
| 0 局玩家率 | 新注册用户中游戏局数 = 0 的去重用户数 / 新注册用户数 | 明确局数事实来源、截止时间和异常局处理 |
| 非 0 局玩家率 | 新注册用户中游戏局数 > 0 的去重用户数 / 新注册用户数 | 与 0 局玩家率应互补，允许异常/缺失单独列出 |
| 首局开始率 | 首局开始用户数 / 点击入口用户数 | 区分点击后加载失败和主动退出 |
| 首局完成率 | 完成首局用户数 / 首局开始用户数 | 明确局结束事件和中断/退款规则 |
| 深度游戏率 | 11 局以上用户数 / 新注册用户数 | 固定“11 局+”阈值，避免不同报告改口径 |
| D1/D3/D7 留存 | cohort 用户在对应成熟观察日再次活跃的用户数 / cohort 新增用户数 | 未达到观察窗口的 cohort 不进入成熟总体分母 |
| 首付率 | cohort 首次成功充值用户数 / cohort 新注册用户数 | 服务端订单成功为事实源 |

## 三、当前已观察到的口径风险

1. 点击用户率的页面结论已经按“新注册用户点击占比”解释，但原始 H5 表格中的字段、分母和统计截止时间仍需登记。
2. 0 局与非 0 局分析的前后窗口并不完全一致，点击结论还剔除了 5/11、5/18；正式复盘需要统一观察窗口。
3. 页面只展示比例和均值，缺少各渠道每日样本量、置信区间和显著性检验，暂时不能把小幅变化直接归因于轻量化改造。
4. `wajeH5`、`wajeh5pww`、`wajebetH5` 需要绑定到统一渠道、包体、版本和投放批次，防止渠道名变化导致错配。
5. 0 局的定义需要明确是“服务端游戏局数为 0”，还是“客户端 GAMEEND 未收到”；两者不能混用。
6. 非 0 局占比提升与点击用户率下降并存，说明必须做用户级漏斗，而不是只看三个独立汇总指标。

## 四、建议新增/核验的事件与字段

### 事件

- `new_user_register_success`
- `game_entry_view`
- `game_entry_click`
- `game_load_start`
- `game_load_success`
- `game_load_fail`
- `game_start`
- `game_round_start`
- `game_round_end`
- `game_round_invalid`
- `game_session_end`
- `recharge_success`

### 公共字段

`event_uid`、`event_version`、`client_ts`、`server_ts`、`user_id`、`device_id`、`session_id`、`package`、`channel`、`app_version`、`client_type`、`game_id`、`mode_id`、`page_id`、`module_id`、`round_id`、`result`、`error_code`、`request_id`、`order_id`、`device_model`、`device_tier`、`os_version`、`network`、`load_ms`。

### 关键归因字段

- `cohort_date`：用户注册日期；
- `lightweight_version`：轻量化方案/版本；
- `experiment_id`、`variant_id`：实验或灰度组；
- `traffic_source`、`media`、`campaign_id`：投放来源；
- `first_entry_ts`、`first_game_start_ts`、`first_game_end_ts`：首局时间链路；
- `is_paid_user`、`payment_status`：付费身份和订单状态。

## 五、建议建设的分析看板

1. 轻量化新手漏斗：新增、点击、加载、首局开始、首局完成、2—3 局、11 局+、首付。
2. 渠道对比：`wajeH5`、`wajeh5pww`、`wajebetH5` 的点击率、0 局率、非 0 局率和 D1 留存。
3. 版本/设备/H5 体验：加载成功率、加载耗时、白屏、JS/API 错误、首局失败和低端机分层。
4. 数据质量：注册数、点击数、GAMESTART/GAMEEND 接收量、入库量、异常量、去重率和延迟。

## 六、验证优先级

### P0

- 统一 cohort、渠道、版本和客户端类型字段；
- 核对点击 UV、0 局、非 0 局的分母是否一致；
- 打通入口点击到首局开始的用户级链路；
- 检查 GAMEEND 异常是否造成 0 局误判；
- 将 5/11 前后窗口统一重算，并补充样本量。

### P1

- 增加首局耗时、加载失败和错误码；
- 建立低端机/H5 体验切片；
- 计算 1 局、2—3 局和 11 局+ 的转化及留存；
- 以 `wajebetH5` 作为高意图对照组，验证改造是否伤害基线。

### P2

- 建立版本灰度/实验对照；
- 评估点击意愿、首局爽感和付费之间的关系；
- 将 COLOR GAME、JADE 的概率/限制/资产弹窗事件纳入统一游戏事实层。
