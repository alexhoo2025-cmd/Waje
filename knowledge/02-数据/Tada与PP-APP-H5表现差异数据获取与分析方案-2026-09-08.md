# Tada与PP在APP／H5的表现差异｜数据获取与分析方案

## 一、先回答什么

**以下注金额占比为主线，把投注、RTP、局数、渗透、活跃、回访和TC一起看。** 最终解释差异来自用户规模、内容构成、入口分配、加载体验，还是投注深度，而不是只做TC对比。

**“PP资源较小，但APP内Tada下注更多”是待检验观察。** 资源体积指游戏加载资源，不是游戏数量或推荐资源。目录大小、实际下载量、加载耗时分别度量；曝光和内容组合同时作为解释变量。

**本版交付的是可执行分析设计，不是本期经营结论。** 已结合游戏字典、上报设计、报表与历史报告确定取数路径；BigQuery连接本次仍返回授权缺失，正式字段绑定与生产取数待恢复。模拟测试只验证计算规则。

![从差异识别到原因验证的分析链路](../../analysis/tada_pp_app_h5_plan_2026_09_08/analysis-flow.png)

先统一游戏与实际端，再验证从曝光到下注的过程。结算解释游戏回报，TC作为共享钱包的人群资金对照，两者分别统计。

## 二、固定比较范围

| 项目 | 采用口径 |
|---|---|
| 业务与产品 | Waje新包真金产品；保留APP和浏览器H5，独立金币产品不并入 |
| 时间 | Africa/Lagos业务日；以已确认完整日C为截止，主窗口C−29至C，对照C−59至C−30 |
| 日期示例 | C为2026年9月7日时，主窗口8月9日—9月7日，对照7月10日—8月8日；C尚待来源完整性确认 |
| 人群 | 每个窗口分别固定新增、老用户、注册日期未知；全体包含以上三类。新增指在该窗口注册，窗口内不会逐日变成老用户 |
| 厂商 | Tada、PP分别展示；同端全部游戏分母还包含其他厂商与厂商未知记录 |
| 实际端 | APP＝Android＋iOS，APP内WebView仍归APP；浏览器H5独立；可识别PWA及端未知单列 |
| 资产 | 每个币种独立；现金、奖励资产分列。可验证同币种混合资金时另给合计，笔数与人数重新去重 |
| 观察起点 | 用户在每个“窗口×端×厂商”内的首次有效下注日为第1日，不称历史首次 |

**两种份额并列，但绝不混用分母。** 同端全站份额回答“在这个端有多重要”，Tada＋PP内部份额回答“两个厂商之间如何分配”。APP和H5分别去重，同一用户可出现在两端；全平台人数另行去重。

## 三、核心指标字典

以下各项均按同一窗口、同一人群、实际端、币种和资产范围计算。明细字段、来源依赖和质量状态见本地配套字典。

| 主题 | 指标 | 计算口径 | 回答的问题 |
|---|---|---|---|
| 投注 | 有效下注额 | 已接受下注金额减生效退款／撤销金额；未受理请求除外 | 实际投注规模 |
| 投注 | 同端全站下注份额 | 厂商有效下注额÷同端全部游戏有效下注额 | 厂商在该端的规模占比 |
| 投注 | 两厂商内部份额 | 厂商有效下注额÷同端Tada与PP有效下注额合计 | 两厂商之间的投注结构 |
| 渗透 | 下注人数渗透率 | 厂商有效下注去重人数÷同端同人群活跃人数 | 活跃用户中有多少参与下注 |
| 活跃 | 进入人数、下注人数、投注活跃天数 | 游戏成功打开用户数、有效下注用户数；逐用户计算有投注的业务日数 | 尝试、实际参与及参与持续性 |
| 深度 | 下注笔数、有效局数 | 交易键去重计笔；认证局标识去重计局，另给用户局数 | 每人参与频次；局与笔是否不同 |
| 深度 | 人均、笔均与局均下注 | 下注额÷下注用户／下注笔数／有效用户局数，各自标明分母 | 单用户、单笔及单人单局的投注强度 |
| 回报 | 实际RTP | 同批已完成结算的最终派奖÷该批对应的有效下注 | 游戏回报比例 |
| 回报 | 游戏毛收入 | 上述已结算下注减最终派奖，另列结算覆盖率 | 对应已结算投注形成的毛收入 |
| 回访 | 同端同厂商下注回访率 | 第N日在同端同厂商下注者÷已成熟且观察数据完整的起点用户 | 参与后是否回来继续下注 |
| 资金 | TC及资金规模 | 同窗口成功提现÷成功现金充值，同时列分子分母与付费人数 | 对应人群钱包现金流 |
| 加载 | 成功、失败与超时率 | 同批已到观察截止的打开尝试为分母；结果未知另列 | 玩家能否顺利进入游戏 |
| 加载 | P50／P75／P95与首笔转化 | 成功打开耗时分位数配成功样本量；同次成功打开后首笔有效下注尝试÷成功打开尝试 | 加载体验和后续参与情况 |

### 必须一起展示的边界

- **份额用全部有效下注，RTP用已结算子集。** 若部分下注未结算，分别给出全部有效下注、已结算下注和未结算下注；未结算派奖保留未知。两期RTP优先比较已充分结算且同成熟条件的子集，注明共同数据截点。
- **混合资金先分金额，再重算笔数。** 一笔下注同时消耗现金和奖励时可拆金额；资产分项的用户数／笔数不能直接相加。派奖无法按认证规则分配到资产时，资产级RTP留缺项。
- **多人共局与一局多笔分开。** 厂商局数以厂商＋游戏＋局键去重；人均／局均深度用用户局数。Fish等局标识未认证时仅报下注笔数，保留局数缺口。
- **曝光、打开与下注按同次链路关联。** 首笔发生在对应打开后、会话结束或下一次打开前；多次打开有歧义时计入未关联，不能把时间接近当作确定关联。跨统计窗口的打开尝试只进入所属起点窗口。
- **资产分层避免事后筛选。** 曝光与加载只有在打开前已知资产模式时才分资产；不能按用户后来是否现金下注来筛选打开分母。回访严格版先固定币种与资产范围，再求起点和复访；产品级合计另行去重。
- **活跃分母独立验收。** 固定可证明的端内启动／大厅／游戏活跃事件集合。下注人数超过活跃人数或活跃来源缺失时，先排查覆盖，渗透率保持待核；不靠补分母掩盖缺失。
- **零和缺失分开。** 来源完整且确认零量可报0；分母为0、权限不足、日期未成熟、端或币种不明均显示相应状态，而非零值。

## 五、汇总表与维度设计

**先做可比较总览，再下钻重要差异。** 以下是查询输出契约，不要求在BigQuery创建新表；可通过只读查询形成临时聚合结果和本地脱敏工件。

| 输出 | 行粒度 | 核心结果 | 聚合注意 |
|---|---|---|---|
| 日表现／期表现 | 期间、日期或窗口、实际端、人群、厂商、分析层级、币种、资产 | 下注、人数、笔数、局数、活跃天数、已结算下注与派奖、两种份额 | 日期汇总与窗口去重分别计算；层级包含厂商、品类、游戏，避免混加 |
| 入口与加载 | 日期、端、厂商／游戏、入口、位置、资源版本、缓存、网络、设备分档 | 曝光、点击、打开、成功／失败／超时／未知、分位数、首笔转化 | 每种指标使用对应事件唯一键；P95从样本分布重算，不能平均分组P95 |
| 回访 | 窗口、起点日期、起点端、厂商／游戏、人群、观察日、回访状态 | 起点人数、成熟人数、数据完整人数、回访人数、未知状态人数 | 第N日为起点＋N−1，观察日为2、3、7、14、30 |
| 资金对照（补充） | 窗口、人群、互斥厂商参与组、币种；端可认证时再分端 | 成功充值、提现、付费人数、TC、资金端未知覆盖 | 全部金额按账号去重关联；不解释为厂商直接贡献 |
| 来源质量（配套） | 日期、源、厂商、端、指标族 | 完整日、重复、映射／端／资产未知、迟到、结算覆盖、对账差 | 输出总覆盖和分组覆盖，作为发布条件 |

每项结果携带来源、过滤版本、窗口、数据截止日、分子、分母及质量状态。BigQuery内可使用受控账号键做关联；落地报告只保留聚合结果，小于10人的组隐藏或合并，并检查总计与子项差分是否泄露小组信息。

### 下钻顺序

1. **基础四组合：** Tada／PP × APP／H5，每组展示全体、新增、老用户；APP保留Android／iOS。
2. **内容：** 品类、游戏、头部／长尾、实际可玩天数。共同上线范围按分析期每日可玩状态核对。
3. **产品路径：** 首页、分类、搜索、收藏、推荐及位置；包内打开、远程打开、缓存命中分别看。
4. **用户：** 包名、自然／投放、注册周、历史付费状态；状态取行为之前已发生的事实。
5. **体验与投注：** 资源版本、网络、设备、加载结果、下注档位、频次与金额集中度。

## 六、回访与TC的特殊处理

### 回访：有回访证据优先，未知信息不判流失

分母固定为同一端与厂商的窗口内首笔下注用户。先判断第N日是否成熟、对应数据是否完整，再按下表顺序分类。

| 互斥状态 | 判定 | 如何展示 |
|---|---|---|
| 同端同厂商 | 有同端同厂商有效下注，即使当天也跨端 | 计入主回访分子；另记同时跨端标志 |
| 无法判定是否同端回访 | 未命中上一行，但存在可能属于目标端／厂商的未知记录 | 留在总分母，展示未知占比；不归入流失 |
| 仅跨端同厂商 | 未命中上述状态；同厂商只在其他已知端下注 | 单列迁移；即使还玩其他厂商也归此类 |
| 仅其他厂商 | 没有目标厂商回访；仅其他已知厂商下注 | 单列内容转移 |
| 未观察到有效下注 | 观察数据完整且没有任何有效下注证据 | 只说明未观察下注；不等于平台完全不活跃 |

主回访率＝确认同端同厂商回访人数÷成熟且数据完整的起点人数；端未知保留分母，因此这是确认回访下限，可另展示“确认回访＋未判定”的上限。任一状态可疑时不宣称是真实流失。

“同端且跨端”是同端回访中的附加标志，不再作为一份人数相加。同游戏回访、平台活跃回访独立计算。来源日期不完整的成熟批次不进入有效分母，另报排除人数；只展示有观察日的结果，未成熟保持N/A。

本期与上期分别按窗口固定人群与起点；各观察日既给最大有效批次，也给两期间相同起点偏移范围的对照。若数据完整截止就是窗口末日，第30日仅窗口最早一天成熟，需明确样本范围；不据小范围代表整月长留。

### TC：描述人群现金流，不归因到某个厂商

默认按全体、新增、老用户计算窗口TC。厂商参与辅助分为只下注Tada、只下注PP、两者都下注、两者均未下注；存在厂商不明下注且可能改变分组时，加“参与归属未明”组。这里的“只”指在Tada和PP二者之间，可以参与其他厂商。

分组全集为窗口内活跃或存在有效投注／成功现金充值／提现的研究范围账号；各参与组互斥，未知注册仍单列。用户共用钱包时只计算一次现金流。资金事件缺少实际端时保留账号总体与端未知金额，不按注册端、最近登录端或下注额分摊充值提现。

窗口内参与分组是回顾性描述，会受到自选择影响；TC较高不能证明某厂商引发提现。零充值时TC为N/A，但提现金额仍展示。

## 七、分析怎么推进

| 步骤 | 实际分析 | 输出判断 |
|---|---|---|
| 核实差异 | 绝对下注额、两个份额、同比较期变化、APP与H5百分点差 | 差异是持续存在还是局部几天造成 |
| 拆规模 | 端活跃人数×下注渗透率×人均笔数×笔均金额 | 是更多用户、更多参与、更高频次还是更大单笔 |
| 拆内容 | 同品类、同游戏跨端、共同可玩范围、头部游戏和去头部结果 | 厂商差异是否主要由游戏组合或少数头部驱动 |
| 拆资源链路 | 同游戏、近似版本、设备、网络、缓存条件下比较下载量、打开成功和首笔下注 | 资源大小与参与差异是否存在可重复关联 |
| 看持续性 | 新增与老用户回访、参与天数、跨端迁移、同游戏回访 | 高下注是否伴随持续参与，而非一次性大额 |
| 看价值 | 已结算RTP、毛收入、金额集中度及人群TC | 规模优势是否同时形成回报与资金差异 |

四因子分解仅在分母完整且大于0时执行：对四因子的24种替换顺序取平均贡献，贡献之和还原总下注差额。因子缺失或零分母时改用明确的规模表，不强行补出归因数字。

内容校正使用同品类和共同游戏集合；用户校正按新老、历史付费与渠道分层，采用合并样本的固定权重作对照。无共同支持的新增／消失游戏单列。大额用户用分位组与Top1%金额占比作敏感性检查，不公开名单，不从主结果默默删除。

**资源体积只是一条待验证原因。** PP较小的目录包不能直接证明其真实加载更快；预加载、压缩、缓存、CDN、打开失败和入口曝光都可能改变实际体验。观察性差异先写为关联，实验或更强识别证据出现后再讨论因果。

## 八、只读查询执行顺序

| 编号 | 取什么 | 前置与输出 |
|---|---|---|
| Q00 | 元数据与来源范围 | 恢复原企业连接；列数据集／表／字段，确认获批范围，不返回用户记录 |
| Q01 | 完整日、版本及金额口径 | 确认共同截止C、分区、币种单位、交易终态、映射和端覆盖 |
| Q02 | 下注与结算对账聚合 | 对同批下注汇总最终状态；有效下注与结算子集分开 |
| Q03 | 日／窗口表现与份额 | 先保留全厂商分母，再取Tada／PP；日UV与期UV独立去重 |
| Q04 | 内容与大额集中度 | 品类、共同上线游戏、头部及金额分位组；按影响选择细钻 |
| Q05 | 曝光—打开—首笔下注 | 只关联认证链路；未关联率与来源覆盖同时输出 |
| Q06 | 资源与加载 | 目录和实际量分开，按缓存／网络／设备分层，分位数从基础时长重算 |
| Q07 | 固定起点回访 | 分窗求首笔、逐观察日分类，输出分母及未知状态 |
| Q08 | TC与互斥参与组 | 订单成功事实先去重，再与参与人群一对一关联，避免资金重复 |
| Q09 | 同口径差异与敏感性 | 两期、跨端、同品类、共同游戏、用户结构及去头部对照 |
| Q10 | 发布验收 | 来源、对账、隐私、日期成熟度与结论证据核对 |

执行前先估算分区扫描量：单查询超过5GiB、整次超过25GiB则缩小窗口／分批或等待确认；聚合输出不超过3,000行，超过时调整粒度，不直接截断后宣称全量。任何写表、导出用户明细、改埋点或调整产品配置均不属于本方案。

## 十、验收与缺口处理

- **映射与去重：** 同名不同ID、厂商ID重复、重发事件、跨资产拆行、一局多笔、多人共局均有测试；交易键或金额含义未认证时阻断对应金额结果。
- **端与人群：** APP内WebView仍APP；同用户跨端分别计端内行为、总体去重；新增＋老＋注册未知还原全体；画像里的未来首充不改写此前状态。
- **金额与资金：** 部分退款、全额撤销、延迟派奖、零充值、混合资产、用户同时玩两厂商不造成金额重复。现网对账差按金额与比例列出，差异解释完毕后才形成确定结论。
- **回访：** 同端与跨端同时存在、仅跨端、仅其他厂商、端未知、未成熟和缺失观察日均验证；互斥状态还原有效分母，同端回访不超过任意端目标厂商回访。
- **资源与漏斗：** 目录大小与下载量区分；缺少关联键只输出阶段规模；超时和未知有独立状态，成功时长不代替整体成功率。
- **交付：** 飞书与本地方案正文、指标字典和接口一致；附来源清单、只读SQL模板、模拟测试结果与缺口台账。模拟测试通过只证明规则在用例内一致，不证明生产数据完整。

当前需补齐的执行条件：BigQuery企业连接授权、联运下注／结算字段认证、实际端与注册事实覆盖、分析期游戏可玩清单、第三方打开／加载日志及资金事件归属。缺哪个指标的必要证据，就限制哪个指标；其余分析继续。

本版已执行本地模拟规则测试。独立模型审查因授权未通过而未取得结果，保留失败回执；未将该审查计为通过。正式来源认证及业务结论验收仍由数据与业务负责人完成。
