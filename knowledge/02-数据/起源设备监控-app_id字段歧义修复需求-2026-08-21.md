# 起源设备监控：`app_id`字段歧义修复需求

## 问题描述

起源“设备监控”报表（报表ID 134）在Waje Special产品下查询时，返回：

```text
BigQueryException during runQuery
Column name app_id is ambiguous at [1:2745]
```

设备健康总览、核心业务链路、页面性能、稳定性、网络质量、设备与版本、游戏体验和异常告警均显示 `No Data`。

## 业务影响

- 无法判断H5轻量化游戏的首局流失是否集中于低端机、弱网、浏览器或版本。
- 无法验证首页/启动耗时、白屏率、崩溃率、游戏进入成功率、充值成功率等护栏。
- 轻量化效果分析只能停留在渠道与留存结果，不能定位产品与技术原因。

## 建议修复方式

1. 检查报表SQL中所有引用 `app_id` 的事实表、维表和子查询。
2. 在每一处引用中显式增加表别名，例如 `event_fact.app_id`、`app_dim.app_id`；禁止依赖未限定的裸字段名。
3. 如不同表的 `app_id` 语义不同，明确选择用于产品、包体、客户端或数据流筛选的字段，并在查询注释中记录。
4. 校验联接条件，避免同一事件因多对多联接被重复计数。
5. 修复后回填至少最近14个完整自然日，并刷新报表缓存。

## 验收标准

| 验收项 | 标准 |
|---|---|
| SQL执行 | 不再出现 `app_id is ambiguous` 或同类字段歧义错误 |
| 数据返回 | 八个设备监控页面均返回非空结构化结果；真实为零时需明确显示零而非No Data |
| 时间范围 | 最近14个完整自然日连续可查；当前部分日单独标记 |
| 维度 | 可按手机品牌、浏览器品牌、终端、APP/H5版本、分包渠道切分 |
| 核心指标 | 至少可返回P95首页/启动耗时、白屏率、崩溃率、异常用户数、游戏进入成功率、核心业务成功率 |
| H5专题 | 可单独筛选H5/PWA及目标分包渠道，并输出受影响用户数和分母 |
| 对账 | 同日活跃/游戏进入量与起源其他BQ报表量级一致；差异需说明口径 |

## 后续数据需求

设备监控恢复后，建议同时确认或补充：`surface_type`、`h5_build`、`release_id`、`game_id`、`entry_context_id`、`session_id`、`network_type`、`device_tier`、`load_ms`、`error_code`、`retry_count`。这些字段是轻量化游戏“入口→可玩→首局→结算”性能归因的最小条件。
