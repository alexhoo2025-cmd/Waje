## 2. 各版本内容拆解

### 2.1 APP 2.11.1：钱包支付、KYC 文案和动态页签

报告确认的版本信息：2.11.1，2025/11/10 发版，包体 49.6 MB，热更量 0.8 M。

更新内容：

- PP 和 Opay 默认走拉起钱包支付；只有新版本包玩家走该逻辑。
- APP KYC 认证界面增加姓名填写特殊说明。
- 动态页签支持通过配置增加或减少页签，待 iOS 发版后一起配置。

相关配置：

| 配置路径 | 字段 | 作用 |
|---|---|---|
| `Config_X → clientconfig` | `OpayMethod = OpayWalletNG` | Opay 默认钱包支付方式 |
| `PSG.Config_X → realtime` | `BVNName` | APP KYC 认证界面的姓名填写规则 |

发布后重点验证：新旧包支付入口是否按版本分流、Opay 钱包拉起成功率、KYC 姓名填写错误率、动态页签配置在 iOS 上线后的兼容性。

### 2.2 H5 2.0.5：全量开放 Opay 钱包拉起

报告确认：2.0.5，2025/11/10 发版。

- PP 和 Opay 默认走拉起钱包支付，且说明为所有玩家均可拉起。
- 配置：`Config_X → clientconfig → OpayMethod = OpayWalletNG`。

与 APP 2.11.1 的差异：APP 报告写明仅新版本包玩家走拉起；H5 2.0.5 写明所有玩家均可拉起。后续分析必须按平台和版本拆分，不能把两者合并为同一个支付策略。

### 2.3 H5 2.0.6：充值、提现、快捷方式和登录链路优化

报告确认：2.0.6，2025/11/24 发版。

更新内容：

- H5 特殊充值。
- 商城默认选择渠道逻辑：记录玩家上次使用的渠道。
- 自定义 TX 功能优化 2.0：KYC 解锁条件关闭时不能解锁自定义 TX。
- 快捷方式优化：增加快捷方式进入奖励。
- 从 Opay App 跳转 H5 登录时弹窗快捷绑定 Opay 账号。
- Opay 登录打点，且登录入口增加开关。
- Web 大厅搜索优化。
- 免费玩家游戏尚未结算时，不允许首充。

相关配置：

| 需求 | 配置路径 | 字段 | 正式配置/含义 |
|---|---|---|---|
| 自定义 TX 2.0 | `PSG.Config_X → flow_withdraw → web_customize_withdraw` | `kyc_verify_open` | KYC 通过是否解锁自定义 TX；`true` 开、`false` 关；报告正式配置为 `FALSE` |
| Opay 登录入口开关 | `PSG.Config → opay` | `loginOpen` | 登录页是否展示 Opay 登录入口；报告正式配置为 `TRUE` |
| 快捷方式 | `PSG.Config → web_shortcut_act` | `duration_template` | 领取间隔模板；报告默认配置为 `060102` |

发布后重点验证：上次支付渠道是否正确回填、KYC/TX 解锁逻辑是否符合开关、Opay 登录打点是否完整、未结算免费玩家是否被正确拦截首充、快捷方式奖励是否重复发放。

### 2.8 金币场分析：AB 测试的业务解释

报告附件为 `金币场游戏详情.xlsx`，正文将 AB 测试问题重新定义为：**金币场是否应该对所有用户开放？**

核心验证目标：

1. **留存**：防止 Cash 输光后用户流失。
2. **Cash 消耗节奏**：观察是否延长用户生命周期。
3. **Cash 回流**：观察额外 Cash 奖励是否失控。

正文结论：

- 游戏人数 **+32%**，局数 **+26%**，被解释为金币场对用户具有“接住用户”的留存作用。
- 人均活跃/人均局数下降，被解释为补位用户质量较低的合理现象，而不是直接判定金币场失败。
- 业务解释是：原本 Cash 输光后会流失的用户，现在可以用 Coin 继续玩，符合金币场的设计初衷。

需要保留的分析限制：正文未显示 AB 测试的实验分组、样本量、观察窗口、显著性、Cash/Coin 口径和额外奖励成本；“+32%/+26%”只能作为报告中的描述性结果，不能直接解释为因果提升。

## 4. 发版报告可复用的标准字段

后续建议把每次发版报告统一成以下字段，便于和起源平台、埋点质量及版本数据分析关联：

| 字段 | 说明 |
|---|---|
| `platform` | APP、H5、Android、iOS |
| `version` | 版本号，如 2.11.2 |
| `release_date` | 正式发版日期 |
| `report_updated_at` | 发版报告修改日期 |
| `package_size` / `store_size` | 包体或商店展示大小，分开记录 |
| `hot_update_size` | 热更量 |
| `feature_type` | 支付、KYC、TX、金币场、活动、埋点、客服、体验等 |
| `change_type` | 新功能、老逻辑优化、Bug 修复、配置变更 |
| `config_path` | 配置路径，如 `Config_X → clientconfig` |
| `config_key` | 字段名，如 `OpayMethod`、`kyc_verify_open` |
| `config_value` | 正式配置值及生效时间 |
| `owner` | 负责人 |
| `experiment_id` / `variant` | AB 测试实验与分组 |
| `validation_metric` | 发布后应验证的指标 |

## 5. 发布后验证清单

- [ ] 按 `platform × version × release_date` 记录版本，不用单独版本号替代跨端版本键。
- [ ] 支付：验证 Opay/PP 入口曝光、钱包拉起、订单创建、支付成功和 500 报错。
- [ ] KYC/TX：验证姓名填写、BVN/NIN、OTP、KYC 解锁自定义 TX 和风险用户状态机。
- [ ] 金币场：验证入口、玩法、金币获得/消耗、弹窗队列、奖励和 AB 分组一致性。
- [ ] 活动：验证 banner、Promo 入口、Tada 跳转、资源加载、弹窗频控和下线时间。
- [ ] 新手：验证快捷方式奖励、Risk-Free Bet、新手礼包、救济金和免费玩家首充限制。
- [ ] 埋点：版本相关功能需补充 PV/点击/成功/失败/配置命中事件，并与 GAMEEND、ORDER、TX、KYC 事件对账。
- [ ] 经营指标：版本上线前后至少观察支付成功率、首充率、TX 成功率、游戏人数、局数、D1/D7 留存、RTP 和投诉/失败率。
