# Waje 埋点事件与属性字典

> 本文是 [[Waje全链路数据需求与埋点设计总表-2026-08-11]] 的字段级附录。`现有`表示平台当前已看到的定义，`目标`表示为后续研发和报表需要补齐的契约，`待确认`表示不能仅依据页面名称推断的业务口径。

## 1. 字段状态与命名规则

| 标记 | 含义 | 研发动作 |
|---|---|---|
| 现有 | 起源平台或项目文档已出现 | 保持兼容，补充版本和 owner |
| 目标 | 本次设计要求 | 新增前完成产品/研发/数据评审 |
| 待确认 | 需要研发、数据或业务确认 | 不得直接作为硬校验或 KPI 口径 |
| 兼容 | 历史字段或旧版本仍需解析 | 标注 schema 版本和下线日期 |
| 废弃候选 | 与其他字段重复或无法解释 | 先观察 7–14 个完整日，再决定下线 |

事件编码统一使用大写下划线，如 `GAMEEND`、`SCENE_ENTERED`。属性名统一使用小写下划线；展示名可中文，但不能作为 SQL 关联键。金额字段必须明确最小单位、币种和正负方向。

## 2. 通用事件信封

### 2.1 核心身份字段

| 字段 | 类型 | 必填 | 说明与校验 |
|---|---|---:|---|
| `event_name` | string | 是 | 元事件或业务事件编码；必须在字典中 |
| `event_version` | string | 是 | 事件契约版本，例如 `v1` |

### 4.2 `GAMEEND` 目标校验

| 校验组 | 规则 |
|---|---|
| 身份 | `user_id`、`xl_id`、`uuid` 至少一个；登录用户必须能关联 `user_id` |
| 局身份 | `unique_id` 非空且可去重；同一局重试不生成新业务键 |
| 玩法 | `game_type`、`play_id`、`mode_id`、`room_id` 按玩法矩阵校验 |
| 结果 | `status`、`end_action_state` 使用字典枚举；未知值隔离，不映射为“其他” |
| 计数 | 所有计数类字段为非负整数；不适用字段不强制填 0，需有 N/A 规则 |
| 金额 | `bet_num`、`service_charge`、`refund_num`、`cash_settlement` 必须有币种、资产和最小单位 |
| 时间 | `game_time` 与 `leave_time` 单位/格式统一；客户端和服务端时间分列 |
| 版本 | `app_version/package_name/schema_version/source` 非空可映射 |
| 链路 | `GAMESTART → GAMEEND → BETREWARD → ASSET` 能按 `round_id/unique_id` 关联 |

## 8. 虚拟事件目录与规则

当前平台虚拟事件页已观察到以下样例：

| 事件标识 | 展示名 | 分类 | 作用 |
|---|---|---|---|
| `event_base_cost` | 投放成本 | 广告投放类 | 投放成本口径 |
| `view_metaevent_audit_fail` | TX 失败 | 资产变动类 | 从审核事件筛选失败 |
| `view_metaevent_order_fisrtpay` | 用户首充 | 资产变动类 | 从订单事件识别首充 |
| `user_events` | 新增用户 | 服务器基础事件 | 新增用户归并 |
| `view_metaevent_changed` | 远程控制配置变化 | 待确认 | 配置变化分析 |
| `view_metaevent_register` | 账号注册 | 服务器基础事件 | 注册归并 |
| `active_events` | 用户活跃事件 | APP流量类 | 活跃口径归并 |
| `view_metaevent_pv` | 页面进入 | APP流量类 | 页面行为归并 |
| `view_metaevent_mc` | 模块点击 | APP流量类 | 模块点击归并 |
| `view_metaevent_mv` | 模块曝光 | APP流量类 | 模块曝光归并 |

虚拟事件 SQL 应遵守：

```text
原子事件/事实表
  → 明确字段投影 ${FIELDS}
  → 明确业务日期与时区 ${DAYWITHTIMEZONE}
  → 明确产品过滤 ${APPIDFILTERS}
  → 明确日期边界 ${STD}/${END}/${STDDAY}/${ENDDAY}
  → 明确业务筛选 ${FILTERSTR}
  → 输出稳定字段名、来源和版本
```

禁止在虚拟事件 SQL 中隐式改变币种、用户去重键、成熟窗口和支付状态。每个虚拟事件必须补充：关联元事件、筛选条件、去重键、分母、数据源、更新时间、owner 和版本。

## 10. 变更流程

```text
产品需求
  → 事件/属性申请
  → 数据产品审查命名、类型、必填和口径
  → 客户端/服务端评审触发与事实源
  → QA 样例和异常场景
  → Ares 元事件/功能埋点配置
  → 埋点测试与小流量验证
  → BQ 标准化/质量监控
  → 报表映射与验收
  → 发版后 24 小时/7 日回归
```

任何字段删除、改类型、改枚举、改去重键或改含义，都必须升高为 schema 版本变更；旧版本兼容窗口、回填和下线时间必须记录。
