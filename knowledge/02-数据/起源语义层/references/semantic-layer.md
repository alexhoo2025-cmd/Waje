# Waje Game 起源数据语义层

## Quick Reference

- Area: Waje Game / 起源分析平台
- Intended users: 数据产品、数据分析、产品、运营、增长和研发
- Coverage level: 页面级结构、指标目录、当前快照、部分样例数据；尚未覆盖底层表、SQL 和完整计算公式
- Source inventory: `references/source-inventory.md`

- Freshness expectation: 以页面展示的数据更新时间为准；日报必须标识是否完整日
- Default timezone: Asia/Hong_Kong（平台展示时间需与数据仓库时区再次确认）

## Entity Clarification

| Entity | Means | Does Not Mean | Primary IDs | Grain Notes | Sources |
|---|---|---|---|---|---|
| 起源ID | 平台用户口径之一 | 不等于账号 ID 或设备 ID | xl_id / 起源统计 ID | 需确认跨产品和跨包去重规则 | 新增日活、LTV、ROI |
| 账号ID | 用户轨迹和服务端用户识别 | 不等于设备 | user_id | 适合用户级轨迹、登录、付费分析 | 用户属性、用户轨迹 |
| 设备 | 终端/设备维度 | 不等于用户 | uuid、品牌、系统、包名 | 同一用户可能多设备 | 设备终端、启动分析 |
| 页面 | 功能埋点中的页面实体 | 不等于报表页面 | page_id | 页面下挂模块和事件 | 页面列表、页面分析 |
| 模块 | 页面内可交互/曝光单元 | 不等于元事件 | module_id / 埋点 ID | 模块触发事件后进入事件分析 | 模块列表、模块分析 |
| 元事件 | 原子采集事件 | 不等于虚拟事件 | 事件标识 | 接收、入库、异常可按事件统计 | 元事件管理、数据质量 |
| 虚拟事件 | 多元事件组合或带条件事件 | 不等于原始上报事件 | virtual event id | 用于分析层归并 | 虚拟事件 |
| Cohort | 按新增/首充/付费日期形成的用户组 | 不等于全量日活 | target_day 或首充日期 | D1/D7/D30 必须等成熟后比较 | 基础留存、首充累计留存、LTV |

## Query Patterns

- 日报：先选完整日期，核对数据更新时间，再按“活跃 → 游戏 → 付费 → 提现 → 利润”顺序读取。
- Cohort：按新增或首充日期分组，只比较成熟到 N 日的 cohort，并保留 cohort 起始人数。
- ROI：同时取 LTV、投放/CAC、提现/资金成本和 N 日营收；遇到成本为 0 先阻断结论。
- 埋点质量：按事件和上报源比较接收、入库、异常、抛弃；再按版本、包、玩法和时间切片。
- 玩法诊断：使用 play_id/mode_id 连接游戏概况、场次分析、收益留存、模块分析和 TC 详情。

## Gotchas

- 2026-08-03 为当前日的部分数据，运营周报和 TC 详情出现负利润或高 TC 比，不应直接解释为趋势。
- ROI 当前出现汇总 CAC=0、ROI=NaN；必须修复成本入库/除零规则。
- 数据质量总错误率 3.30164%，GAMEEND 异常 130,874 条，是当前优先级最高的埋点问题。
- 报表集市 `BQ-` 版本使用 BigQuery 新引擎；非 `BQ-` 版本为旧引擎并将逐步废弃。迁移期间仍需核对刷新延迟、数据截止时间和口径差异。
- 用户分群和部分元数据最后更新时间停留在 2023–2024，不能当作当前用户规模或当前规则。
- 设备品牌存在 `samsung`、`TECNO`、`tecno mobile limited`、`INFINIX MOBILITY LIMITED` 等不同大小写/命名，做终端排名前需标准化。
- 货币配置 NGN 1:1 的更新时间为 2023-03-23，需确认当前订单金额和多币种规则仍有效。
