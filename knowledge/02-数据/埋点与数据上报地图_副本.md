# 埋点与数据上报地图

该笔记承接埋点梳理工作。2026-08-04 已通过 Lark 读取并入库《事件模型概念介绍》，并通过起源平台「元事件管理」读取当前 Waje Special 元事件清单。字段级详情仍需逐项对账。

## 事件分层

| 层级 | 示例事件 | 关键字段 |
|---|---|---|
| 生命周期 | 注册、登录、回流、流失 | user_id、时间、渠道、设备 |
| 玩法 | 进入玩法、开始一局、结束一局 | game_id、session_id、结果、下注额 |
| 资金 | 充值、提现、派奖、冲正 | order_id、asset_type、金额、状态 |
| 激励 | 领取奖励、完成任务、使用 BonusCash | reward_id、来源、过期时间 |
| 体验 | 加载失败、断线、接口错误 | error_code、页面、网络、版本 |

## 每个事件需要核对

- 触发时机是否唯一且稳定？
- 是否有匿名用户到登录用户的关联？
- 金额、币种、资产类型是否明确？
- 客户端上报与服务端事实是否能对账？
- 重试、重复上报、延迟上报和时区如何处理？
- 是否能支撑起源、GM 生命周期 V2、Metabase 玩家资产分析？

## Lark 事件模型基线（2026-08-04 核验）

历史事件模型将客户端行为分成应用、页面、模块三类，共六种基础事件：`AL` 应用启动、`AQ` 应用退出、`PV` 页面曝光、`PD` 页面退出、`MV` 模块曝光、`MC` 模块点击。`MV` 以模块露出屏幕 1px 为曝光条件，加载但未展示不计入曝光；页面和事件 UV 口径以设备标识为主。

预置属性覆盖包名、APP/热更新版本、渠道/子渠道、OS、设备品牌/型号、分辨率、系统版本、运营商、网络、电量、内存和推送设置。业务参数覆盖广告、联运、金币/资产、活动以及前端控件位置、ID、内容、类型和选择器。

该基线能支撑页面/模块流量分析，但不能单独支撑新手生命周期和付费分析。必须补充统一用户标识、session、事件唯一 ID、事件版本、客户端/服务端时间、去重/重试/迟到规则，以及注册、游戏、首充、复购、提现、H5 和故障事件。

## 与当前重点的对齐缺口

| 目标 | 现有基线 | 必须补齐 |
|---|---|---|
| 新手生命周期 | AL/PV/MV/MC 可描述访问行为 | 首登、注册、首局、关键步骤完成、首充、D1/D7 归因字段 |
| 付费 | 资产/订单类业务参数有历史设计 | 客户端意图 + 服务端订单状态 + 回调/冲正/对账字段 |
| 低端机适配 | 设备、内存、电量、网络字段存在 | 设备档位、性能耗时、崩溃、卡顿、启动/进局失败 |
| H5 优化 | 页面模型可复用但未定义 Web 特有字段 | URL/路由、WebView、白屏、资源、JS、接口和加载耗时 |
| 故障定位 | 页面/事件错误状态未形成统一模型 | error_code、request_id、trace_id、错误阶段、版本、设备、网络 |

## 近期埋点治理动作

1. 以 `event_name + event_version + event_uid` 作为事件治理最小单元，禁止只以展示名维护事件。
2. 将设备 UV 与用户 UV 分离，留存、首付和复购统一使用用户口径，并保留设备关联分析。
3. 所有资金事件以服务端订单/账务为事实源，客户端事件只用于漏斗和体验诊断。
4. 为 H5、低端机和故障事件增加公共性能字段，并接入事件接收、入库、异常和丢失监控。
5. 将 `GAMEEND` 异常纳入事件模型回归验收，要求接收量、入库量、异常量和有效字段完整度可追踪。
