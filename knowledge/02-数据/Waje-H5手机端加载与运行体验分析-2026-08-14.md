# Waje H5 手机端加载与运行体验分析

## 结论

- 450条成功加载记录覆盖7个机型、13款游戏；机型08–10为空模板。测试横跨 2026-07-24 至 2026-08-06（9个测试日期），设备差异混入日期效应。
- 整体点击游戏入口到可玩的P75为 **8.8s**，P90为 **12.4s**；P90较动效玩法6.5秒红线高 **5.9s**。
- 最大耗时阶段为 **Logo页资源加载**，占阶段和 **37.5%**。
- 最慢3款游戏为 **FISH、Red Green、Bacca Whot**；最慢设备为 **Redmi Note 4X**，P90为 **21.0s**。
- 玩法瓶颈不同：FISH的解析/脚本/连接服务中位为 **7.1s**；Red Green的画面到可玩中位为 **3.6s**；Bacca Whot的解析连接中位为 **2.5s**。
- 89个同机型同游戏组合可比较冷热启动，缓存中位节省 **5.6s（60.1%）**，但不能消除全部等待。
- 450条记录全部是Wi-Fi；每个设备×游戏通常只有1次冷启动；只记录成功到达可玩的样本，不能计算真实可玩率、弱网差异或生产转化影响。

## 问题总结

1. **Logo公共资源链路是第一优先级。** 该阶段占累计阶段耗时37.5%，P75为3.4s、P90为5.2s，已接近或超过部分玩法的整链路目标。
2. **FISH是最明确的单游戏专项。** 总耗时P90为24.0s，解析/脚本/连接中位为7.1s，66.7%的成功记录超过6.5s。
3. **低端机放大等待与稳定性风险。** Redmi Note 4X P90为21.0s；TECNO KG5j有95.0%的记录超过6.5s，但两台设备慢的阶段结构不同。
4. **Red Green与Bacca Whot需采用不同优化路径。** Red Green主要卡在画面到可玩，Bacca Whot主要卡在解析与连接。
5. **缓存有效但暖启动仍未达标。** 冷启动P75为14.8s，暖启动P75为7.2s；不能以“二次更快”替代发布门禁。
6. **线上风险尚未量化。** 当前只有Wi-Fi成功样本，缺少失败、超时、退出、弱网与资源明细，暂不能计算真实可玩成功率和转化影响。

### 验证与数据闭环

- 建立5款游戏×5类设备×3类网络×10次冷启动+10次热启动的1,500次测试矩阵，失败样本必须保留终态。
- 统一 `game_load_id`，串联入口点击、资源、脚本、连接、`game_ready`、`bet_ready`、失败、超时和退出；字段完整率≥99.5%，开始到终态关联率≥98%。
- FPS自动采集覆盖≥95%，建议P10≥30、P50≥45，单次>500ms Long Task=0。
- 修复浏览器字段、K/N列误引用和P95漏行；新增P75/P90、失败率与样本量，汇总和明细抽样复算一致率100%。

### 两个迭代的执行顺序

1. 第0-2天：冻结版本映射、玩法门禁分类与基线，补齐资源瀑布和阶段日志。
2. 第1周：完成Logo公共资源首轮优化、FISH首轮拆分及低端机快速回归。
3. 第2周：完成FISH第二轮、Red Green/Bacca Whot专项和缓存策略优化。
4. 发布后7天：按设备×游戏×网络复盘P75/P90、可玩成功率、FPS和退出率。

## 方法与边界

- `game_ready代理` = 前四阶段和；`bet_ready代理` = 五阶段和。源表起点是游戏入口点击，并非严格的浏览器 `navigationStart`。
- 玩法族不等同于简单/动效门禁分类；正式门禁前需冻结映射。
- 设备、OS、浏览器和CPU彼此混杂，当前结论是相关性定位，不是因果归因。
- 源表共识别35处汇总公式问题：浏览器字段误引用RAM、部分统计误引用K列、P95范围漏掉FISH；本报告依据450条阶段明细独立重算。
- 需求背景标注H5 v2.6，源表构建字段为H5-V2.16.0；正式复盘与回归前需确认版本映射。
