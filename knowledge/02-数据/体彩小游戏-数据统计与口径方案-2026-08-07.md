# 体彩小游戏：数据统计与口径方案

## 一、产品范围

体彩小游戏为独立产品，需同时支持以下访问入口：

- APP 版本/包体入口
- H5 版本入口

统计时应将“产品”和“访问平台/渠道”拆分：同一款体彩小游戏使用统一 `product_id`，通过 `platform`、`package`、`channel` 区分 APP、包体和 H5 来源，避免重复统计或无法归因。

## 二、建议的数据维度

- 用户：`user_id`、用户类型（免费/付费）、注册时间、首充状态
- 产品：`product_id`、游戏版本、规则版本
- 入口：`platform`（APP/H5）、包体、渠道、归因媒体
- 投注：`bet_id`、`round_id`、下注时间、下注金额、选项、下注状态
- 资产：扣款金额、退款金额、宣公资产、用户余额、资产流水号
- 结果：结算状态、输赢金额、有效投注额、异常状态

## 三、核心统计指标

### 1. 访问与参与

- 游戏曝光人数/次数
- 游戏进入人数/次数
- 首次进入人数
- 参与投注人数及投注率
- APP、包体、H5 分平台参与情况

### 2. 投注与结算

- 投注笔数、投注用户数、投注金额
- 有效投注笔数、有效投注额
- 投注成功率、结算成功率
- 人均投注金额、投注频次
- 输赢金额、平台收益及 RTP（需明确财务口径）

### 3. 用户与留存

- 免费玩家与付费玩家的参与率、投注率和投注金额
- 首次参与后的 D1/D3/D7 留存
- APP 与 H5 用户的参与和留存对比
- 首充前后体彩参与行为变化

## 四、关键计算口径

1. **有效投注**：仅统计服务端受理成功、具备完整投注选项、生成唯一 `bet_id` 并进入结算流程的投注。
2. **投注金额**：按资产流水实际扣款金额统计；失败、撤销、退款订单不得重复计入有效投注额。
3. **结算金额**：以最终结算流水为准，区分输赢、退款、撤单和待处理状态。
4. **用户归因**：优先使用服务端记录的渠道/媒体归因；缺失时标记为“未知”，禁止用入口名称直接推断渠道。
5. **用户类型**：需明确免费玩家、低额充值玩家和付费玩家的判定时间窗口及金额阈值。
6. **重复统计**：以 `user_id + round_id + bet_id` 去重，避免重试、重复上报造成投注人数和金额膨胀。
7. **异常投注**：用户已扣款但未选择 high/low 的投注，单独统计为异常订单，不直接计入有效投注或平台收益，直至明确处置结果。

## 五、会议涉及的重点风险

- 体彩拟移除联运框架限制，允许免费玩家及少量充值玩家参与；当前免费玩家下注上限为 500，后续需验证改为 0 后的实际效果。
- “已扣款但未完成选项”的下注会影响资产归属、水位及概率计算，需要建立待处理、退款、补偿和最终结算状态。
- 9011、Hero 等相关下注逻辑需重点监控，避免出现资产悬空、重复扣款或概率计算异常。
- 首充、宣公资产扣除和体彩下注流水需要关联核对，尤其关注余额异常及资产处理时点。

## 六、建议的一期看板

1. **总览页**：DAU、进入人数、投注用户数、有效投注额、结算成功率、异常订单数。
2. **平台对比页**：APP/包体/H5 的用户数、投注率、金额、留存和异常率。
3. **用户分层页**：免费、低额充值、付费用户的参与、投注和留存对比。
4. **资产与异常页**：扣款、退款、待处理、未选项、资产悬空及余额异常明细。
