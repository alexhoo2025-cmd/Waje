# 起源埋点设计细节：元事件清单

> 本文基于 2026-08-04 访问起源分析平台「数据管理 → 事件埋点 → 元事件管理」整理。范围包括当前 Waje Special 产品下可见的 34 个元事件列表，以及 `MC` 事件详情样本。  
> 证据边界：本次未执行任何保存或同步操作；「导出方案」按钮在页面中为禁用状态；批量打开编辑详情容易超时，因此除 `MC` 外，其余事件先以列表层信息入库，字段级详情后续应从「事件属性」「埋点参数」或平台导出补齐。

## 一、平台结构

当前数据管理下和埋点相关的入口包括：

| 模块 | 作用 | 当前观察 |
|---|---|---|
| 埋点手册 | 埋点模型和上报说明 | 与飞书历史方案可互相校验 |
| 数据质量 | 接收、入库、异常、抛弃 | 已用于定位 `GAMEEND` 异常 |
| 埋点测试 | 测试轨迹或明细 | 后续可用于单用户排查 |
| 元事件管理 | 原子事件字典 | 本文主来源 |
| 虚拟事件 | 元事件组合/条件归并 | 用于用户活跃、新增、首充等分析口径 |
| 用户属性 | 用户维度字典 | `user_id`、`uuid`、设备、账号等口径需要对账 |
| 事件属性 | 事件维度字典 | 玩法、金额、页面、模块、提现、下注等字段 |
| 页面列表/模块列表/埋点参数 | 功能埋点实体 | 支撑页面、模块、点击、曝光分析 |

## 三、已读取的 `MC` 详情样本

`MC` 是模块点击事件，当前详情中显示：

| 属性分组 | 属性名 | 显示名 | 类型 | 状态 | 备注 |
|---|---|---|---|---|---|
| 事件属性 | `element_content` | 元素内容 | String | 可见 | 点击内容 |
| 事件属性 | `asset_id` | 资产类型 | Integer | 可见 | 可用于充值、礼包、资产入口分析 |
| 事件属性 | `element_type` | 元素类型 | Integer | 可见 | 与元素分类口径相关 |
| 事件属性 | `element_id` | 元素ID | String | 可见 | 点击行为核心定位字段 |
| 事件属性 | `element_name` | 元素名称 | String | 可见 | 点击行为核心解释字段 |
| 事件属性 | `play_id` | 玩法id | Integer | 可见 | 玩法入口与游戏分析关联键 |
| 事件属性 | `elements` | 元素类型 | String | 可见 | 与 `element_type` 可能存在重复定义，需核验 |
| 事件属性 | `activity_name` | 邀请活动 | String | 可见 | 活动入口与邀请链路 |
| 用户属性 | `uuid` | 设备id | String | 可见 | 设备口径 |
| 用户属性 | `user_id` | 账号id | String | 可见 | 用户口径 |

对产品分析的含义：

| 分析问题 | 可用字段 | 口径提醒 |
|---|---|---|
| H5/APP 游戏入口点击率 | `MC` + `element_id`/`element_name`/`play_id` | 必须固定入口埋点 ID，不能只用模块名称模糊匹配 |
| 新手首日路径 | `REGISTER`/`LOGIN` + `PV`/`MV`/`MC` | 需要统一 `user_id`、`uuid` 与起源 ID 的映射 |
| 轻量化游戏入口转化 | `MC` → `GAMESTART` → `GAMEEND` | 点击和开始局之间需要 session/round/玩法键对齐 |
| 活动/邀请入口效果 | `activity_name` | 需确认活动字段是否全入口覆盖 |

## 四、面向新手生命周期的事件链路

建议把当前事件分为 5 段：

| 阶段 | 可用元事件 | 分析用途 | 当前缺口 |
|---|---|---|---|
| 安装/初始化 | `INSTALL`、`AL` | 新包拉新、首启、投放归因 | 需要广告渠道、包、设备档位、版本 |
| 注册/登录 | `REGISTER`、`LOGIN`、`BINDACCOUNT` | 新增、登录成功、账号绑定 | 注册与首登需区分；游客/匿名链路需映射 |
| 页面与入口 | `PV`、`PD`、`MV`、`MC`、`AUTOPV`、`AUTOMC` | 页面访问、模块曝光、点击、H5 行为 | H5 自动事件当前入库量低，需要确认是否接入新包 |
| 开局/完局 | `GAMESTART`、`GAMEEND`、`BETREWARD` | 0 局/非 0 局、完局、玩法深度 | `GAMEEND` 曾有高异常，修复前不能直接作为事实口径 |
| 留存/活跃 | `AL`、`APPONLINE`、`LOGIN`、虚拟事件用户活跃 | D1/D7、活跃、在线 | 留存必须按 cohort 达到统计窗口后再计算 |

## 五、面向付费和资金的事件链路

| 阶段 | 可用元事件 | 分析用途 | 当前缺口 |
|---|---|---|---|
| 付费意图 | `MC`、`PV`、`TRIGGERGIFT` | 商城/礼包/首充入口曝光与点击 | 需要识别首充入口、礼包 ID、活动 ID |
| 订单 | `ORDER` | 下单、支付成功 | 当前展示说明混合“创建成功订单”和“支付成功”，需拆状态 |
| 资产变动 | `ASSET`、`GETITEM`、`USEITEM`、`BETREWARD` | 充值到账、派奖、道具和虚拟币流转 | 资金事实应以服务端订单/账务为准，事件用于漏斗和体验 |
| 提现 | `WITHDRAW`、`AUDIT` | 提现申请、审核 | 需补提现状态、失败原因、审核结果、到账状态 |
| 激励任务 | `FINISHTASK`、`RECEIVETASK` | 新手任务、奖励转化 | 需补任务 ID、奖励类型、任务阶段 |

## 六、数据质量和治理风险

1. `GAMEEND` 是游戏生命周期中最关键的事实事件，但此前起源数据质量页显示其异常集中，必须优先复核字段缺失、类型、枚举、版本和来源。
2. `ORDER` 当前说明同时覆盖订单创建和支付成功，容易把“下单率”和“支付成功率”混在一起；建议拆成订单创建、支付提交、支付成功、支付失败、退款/冲正。
3. H5 自动事件 `AUTOPV`、`AUTOMC`、`AUTOPD`、`PAGELOAD` 当前昨日入库量接近 0，不足以支撑 H5 优化判断；需要确认 H5 新包是否另有上报链路。
4. `MC` 同时存在 `element_type` 和 `elements` 两个“元素类型”语义字段，需确认是否历史字段、枚举字段或重复字段。
5. 元事件列表只显示展示名、分类、昨日入库量和描述，缺少事件版本、生效时间、下线时间、owner、必填规则和质量阈值。

## 七、后续补齐优先级

| 优先级 | 动作 | 目标 |
|---|---|---|
| P0 | 补齐 `GAMESTART`、`GAMEEND`、`BETREWARD`、`ORDER`、`ASSET`、`WITHDRAW` 详情字段 | 新手生命周期、付费、局数和资金分析的事实层 |
| P0 | 确认 `user_id`、`uuid`、起源 ID、账号 ID 的映射和去重优先级 | 解决留存、付费率、复购率口径漂移 |
| P0 | 对 `GAMEEND` 建立事件级异常监控 | 防止完局、玩法深度和收益归因被异常事件污染 |
| P1 | 为 H5 补齐 `PAGELOAD`、`AUTOPV`、`AUTOMC`、JS 错误、接口错误和白屏字段 | 服务低端机适配、H5 优化和故障定位 |
| P1 | 将入口 `element_id` 固化成游戏入口/商城入口/首充入口字典 | 支撑新手路径、入口转化和活动效果 |
| P2 | 推动起源平台元事件导出权限或接口读取 | 形成可自动更新的埋点资料库 |
