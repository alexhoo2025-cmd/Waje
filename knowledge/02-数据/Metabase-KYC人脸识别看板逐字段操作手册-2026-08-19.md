# Metabase｜KYC 人脸识别看板逐字段操作手册

## 0. 配置前检查

### 管理员开通项

1. Collection：`Waje / Risk & KYC / 人脸识别` 的 **Curate** 权限。
2. KYC 日汇总数据集和羊毛分析数据集的 **View data + Create queries** 权限。
3. 禁止普通用户访问或下载 BVN/NIN、手机号、人脸、证件、生物特征和第三方原始响应。

> 只有 Curate 仍不能创建问题；必须同时拥有底层数据查询权限。

### 创建目录

```text
Waje / Risk & KYC / 人脸识别
├── Models
├── Questions - V1
├── KYC 人脸识别运营与体验监控 V1
└── 羊毛分析 - KYC（受限）
```

## 1. 建立统一数据 Model

### 操作路径

1. 左侧点击 **浏览数据**，选择已接入的 KYC 日汇总表。
2. 点击 **新建问题**，选择 **查询构建器**。
3. 暂不添加行级用户字段，只保留日期、流程、端、包体和下列数值字段。
4. 点击 **保存**，名称：`KYC 人脸认证日汇总`，位置：`Models`。
5. 如果菜单中有 **Turn this into a model / 转为 Model**，执行转换；没有则保留为保存问题并作为统一来源。
6. 点击 **编辑元数据**，按下表设置显示名与字段类型。

| 当前字段 | 显示名 | 类型 | 筛选输入 |
|---|---|---|---|
| `日期` | 统计日期 | Date | Date range |
| `流程` | 认证流程 | Category | 多选下拉 |
| `端` | 终端 | Category | 多选下拉 |
| `包名` | 包体 | Category | Search box |
| `每日触发人数` | 触发认证人数 | Number | 不筛选 |
| `实际调用BVN/NIN人数` | 实际调用人数 | Number | 不筛选 |
| `BVN调用人数`、`BVN通过人数`、`BVN失败人数` | BVN 指标 | Number | 不筛选 |
| `NIN调用人数`、`NIN通过人数`、`NIN失败人数` | NIN 指标 | Number | 不筛选 |
| `请求人脸识别人数`、`请求人脸识别次数` | 人脸请求指标 | Number | 不筛选 |
| `最终人脸识别成功人数`、`最终人脸识别失败人数` | 人脸最终结果 | Number | 不筛选 |
| `当前保留-*次数` | 失败尝试次数 | Number | 不筛选 |

Model 描述固定写入：

> 所有人数为每日按用户去重后累计的人次，跨日不能视为独立用户。无最终结果＝请求人脸－最终成功－最终失败。失败原因是尝试次数，且成功后可能被清除。认证成功不等于提现成功。

## 2. 统一筛选基线

每张 V1 保存问题都按以下顺序设置：

1. **Filter → 统计日期 → 过去 30 天**；若数据源没有完整日标识，先手工排除当天未完成数据。
2. **Filter → 认证流程**；保留提现触发、主动认证两个值。
3. **Filter → 终端**；保留 App、H5。
4. **Filter → 包体**；只在排查时传值，不设默认包体。

## 3. 保存问题：逐张配置

统一保存位置：`Questions - V1`；所有题目以 `KYC V1 -` 开头。

### KPI：5 张指标卡

| 保存名称 | Summarize 选择 | 图表 | 显示格式 |
|---|---|---|---|
| `KYC V1 - KPI - 触发认证人数` | `Sum of 每日触发人数` | Number | 整数、千分位 |
| `KYC V1 - KPI - 实际调用人数` | `Sum of 实际调用BVN/NIN人数` | Number | 整数、千分位 |
| `KYC V1 - KPI - 请求人脸人数` | `Sum of 请求人脸识别人数` | Number | 整数、千分位 |
| `KYC V1 - KPI - 最终人脸成功人数` | `Sum of 最终人脸识别成功人数` | Number | 整数、千分位 |
| `KYC V1 - KPI - 无最终结果率` | `Custom Expression`，见下方 | Number | Percent，1 位小数 |

无最终结果率表达式：

```text
(Sum([请求人脸识别人数])
 - Sum([最终人脸识别成功人数])
 - Sum([最终人脸识别失败人数]))
/ Sum([请求人脸识别人数])
```

分母为 0 或无数据时，设置为空值；不能显示为 `0%`。

### Q02：认证全流程漏斗

#### 路线 A：SQL/Model（推荐）

1. 点击 **+ New → SQL query**。
2. 输入下方模板。输入 `{{#` 后从 Metabase 搜索并选择 `KYC 人脸认证日汇总`，不手填 Model ID。
3. 点击每个变量，设置为 **Field Filter** 并映射：`stat_date→日期`、`flow_type→流程`、`platform→端`、`package_name→包名`。
4. 点击运行，图表选择 **Funnel**。
5. 在 Data 设置中：步骤列选 `stage_name`，指标列选 `stage_users`，按 `stage_order` 升序。
6. 保存名：`KYC V1 - 认证全流程漏斗`。

```sql
WITH source AS (
  SELECT * FROM {{#KYC 人脸认证日汇总}}
  WHERE 1 = 1
  [[AND {{stat_date}}]]
  [[AND {{flow_type}}]]
  [[AND {{platform}}]]
  [[AND {{package_name}}]]
)
SELECT 1 AS stage_order, '1. 触发认证' AS stage_name,
       SUM(`每日触发人数`) AS stage_users FROM source
UNION ALL
SELECT 2, '2. 实际调用BVN/NIN', SUM(`实际调用BVN/NIN人数`) FROM source
UNION ALL
SELECT 3, '3. 请求人脸识别', SUM(`请求人脸识别人数`) FROM source
UNION ALL
SELECT 4, '4. 形成最终人脸结果',
       SUM(`最终人脸识别成功人数`) + SUM(`最终人脸识别失败人数`) FROM source
UNION ALL
SELECT 5, '5. 最终人脸成功', SUM(`最终人脸识别成功人数`) FROM source
ORDER BY stage_order;
```

#### 路线 B：仅 Query Builder

宽表不能直接做可靠 Funnel。没有 SQL/Model 权限时：

1. 保留 5 张 KPI 卡。
2. 新建 `KYC V1 - 认证阶段人数（非原生Funnel）`，用横向 Bar 展示 5 个阶段数。
3. 图表说明写明：`因当前宽表与权限限制，本卡为阶段人数替代图，不是原生漏斗。`

### Q03：每日认证效率趋势

1. 数据源：`KYC 人脸认证日汇总`；使用统一筛选基线。
2. 点击 **Summarize → Custom Expression**，依次增加下列 5 项。
3. 点击 **Group by → 统计日期 → Day**。
4. 图表选 **Line**；所有指标格式设为 Percent，保留 1 位小数。
5. 保存名：`KYC V1 - 每日认证效率趋势`。

```text
认证启动率 = Sum([实际调用BVN/NIN人数]) / Sum([每日触发人数])
BVN通过率 = Sum([BVN通过人数]) / Sum([BVN调用人数])
NIN通过率 = Sum([NIN通过人数]) / Sum([NIN调用人数])
人脸成功率（请求口径） = Sum([最终人脸识别成功人数]) / Sum([请求人脸识别人数])
无最终结果率 = (Sum([请求人脸识别人数])-Sum([最终人脸识别成功人数])-Sum([最终人脸识别失败人数])) / Sum([请求人脸识别人数])
```

若折线超过 5 条，将无最终结果率拆成单独折线图，避免不可读。

### Q04a：失败原因每日趋势

1. 使用统一筛选基线。
2. **Summarize** 添加：
   - `Sum of 当前保留-人像不匹配次数`
   - `Sum of 当前保留-请求接口失败次数`
   - `Sum of 当前保留-三方接口错误次数`
3. **Group by → 统计日期 → Day**。
4. 图表选 **Stacked bar**。
5. 保存名：`KYC V1 - 失败原因每日趋势`。
6. 卡片说明：`失败原因是尝试次数，不是失败用户数；成功后部分原因会被清除。`

### Q04b：失败原因构成

复制 Q04a，删除日期分组，图表改为 **Donut**，保存名：`KYC V1 - 失败原因构成`。仅用于展示构成，不用于判断用户失败率。

### Q05：流失阶段

1. 使用统一筛选基线。
2. **Summarize → Custom Expression**，依次增加：

```text
触发后未调用 = Sum([每日触发人数]) - Sum([实际调用BVN/NIN人数])
调用后未请求人脸 = Sum([实际调用BVN/NIN人数]) - Sum([请求人脸识别人数])
请求后无最终结果 = Sum([请求人脸识别人数]) - Sum([最终人脸识别成功人数]) - Sum([最终人脸识别失败人数])
最终人脸失败 = Sum([最终人脸识别失败人数])
```

3. 图表选 **Bar**，按值降序。
4. 保存名：`KYC V1 - 流失阶段`。
5. 卡片说明：`当前没有独立“身份通过人数”，调用后未请求人脸只是代理阶段。`

### Q06：BVN/NIN 认证统计

1. 使用统一筛选基线。
2. **Summarize** 添加 BVN 调用/通过/失败、NIN 调用/通过/失败、仅 BVN、仅 NIN、双调用。
3. 图表选 **Grouped bar**；若过密，拆为“成功失败”和“调用方式分布”。
4. 再创建一张同查询的 **Table**，用于查看数字。
5. 保存名：`KYC V1 - BVN NIN 认证统计`。
6. BVN 与 NIN 必须分开计算通过率，禁止混为单一身份认证通过率。

### Q07：端与包体对比

1. 数据源：`KYC 人脸认证日汇总`；只保留日期和流程筛选。
2. **Summarize** 添加：触发、实际调用、请求人脸、最终成功、无最终结果率、人脸成功率（请求口径）。
3. **Group by** 依次选 `端`、`包名`。
4. 图表选 **Table**，按无最终结果率降序。
5. 保存名：`KYC V1 - 端与包体对比`。

## 4. 创建仪表盘与布局

### 操作路径

1. 点击 **+ New → Dashboard**。
2. 名称：`KYC 人脸识别运营与体验监控 V1`。
3. 描述：`V1 使用 KYC 日汇总；人数为累计人次；无最终结果独立展示；认证成功不等于提现成功。`
4. 保存到 `Waje / Risk & KYC / 人脸识别`。
5. 点击铅笔，添加 Q01a–Q01e、Q02、Q03、Q04a、Q04b、Q05、Q06、Q07。
6. 添加 Heading/Text 卡片，写入口径和敏感数据限制。

```text
第一行：Q01a｜Q01b｜Q01c｜Q01d｜Q01e
第二行：Q02 漏斗（2/3宽）｜Q05 流失阶段（1/3宽）
第三行：Q03 效率趋势（2/3宽）｜Q04b 失败构成（1/3宽）
第四行：Q04a 失败趋势（2/3宽）｜Q06 BVN/NIN（1/3宽）
第五行：Q07 端与包体对比（全宽）
```

在 **… → Edit settings**：

- `Dashboard Width`：选择 `Full width`。
- `Auto-apply filters`：关闭，多条件改完后点击 `Apply`。
- `Auto refresh`：日汇总 V1 默认关闭；不设置高频刷新。

## 5. 全局筛选器：逐卡绑定

进入编辑状态，点击筛选器图标后按下表配置；新增筛选器后必须在右侧边栏逐卡绑定。

| 筛选器 | 组件 | 绑定字段 | 必绑卡片 |
|---|---|---|---|
| 日期 | Date range；默认最近 30 个完整日 | `日期` | Q01a–Q07 |
| 认证流程 | Category，多选 | `流程` | Q01a–Q07 |
| 端 | Category，多选 | `端` | Q01a–Q07 |
| 包体 | Search box | `包名` | Q01a–Q07 |
| 渠道 | 暂不创建 | 字段未接入 | - |
| APP/H5版本 | 暂不创建 | 字段未接入 | - |

对 SQL 漏斗 Q02，筛选器应连接到 SQL 中的 Field Filter：`stat_date`、`flow_type`、`platform`、`package_name`。普通文本变量不能可靠支持多选与日期范围。

## 6. 羊毛分析 - KYC 受限专题

### 数据源

复用现有 Metabase `羊毛分析` 数据集/Model，不新建跨库明细关联。由数据管理员将下列逻辑字段映射到实际列：

| 逻辑字段 | 用途 |
|---|---|
| 统计日期 | 趋势与日期筛选 |
| 羊毛标签 | 风险/羊毛分层 |
| KYC 是否需要 | 计算“是否人脸KYC” |
| 最终人脸状态 | 成功、失败、无结果、未触发 |
| 提现/奖励行为 | 聚合观察后续处理结果 |
| 端、包体 | 分层比较 |

### 新增字段

在羊毛分析 Model 新建两个字段：

```text
是否人脸KYC = 是：无需认证 OR 最终人脸状态=成功
是否人脸KYC = 否：需要认证 AND 最终人脸状态≠成功

人脸KYC诊断状态 = 无需认证 / 已通过 / 未通过 / 无最终结果或处理中
```

主字段保留“是/否”二分类以满足业务需求；诊断字段保留处理中状态，避免将处理中误读为已判定风险。

### 羊毛专题保存问题

| 保存问题 | Query Builder | 图表 |
|---|---|---|
| `羊毛 KYC - 覆盖概览` | Group by 是否人脸KYC；汇总用户/记录数 | Number + Donut |
| `羊毛 KYC - 标签对比` | Group by 羊毛标签、是否人脸KYC；汇总人数 | Stacked bar |
| `羊毛 KYC - 提现奖励表现` | Group by 是否人脸KYC；汇总提现/奖励行为 | Table 或 Bar |
| `羊毛 KYC - 诊断状态趋势` | Group by 统计日期、人脸KYC诊断状态 | Stacked bar |
| `羊毛 KYC - 端包分层` | Group by 端、包体、是否人脸KYC | Pivot/Table |

所有羊毛问题保存至 `羊毛分析 - KYC（受限）` Collection。普通角色只看聚合比例与趋势，禁用用户级导出。

## 7. 对账与验收

历史验证窗口：`2026-07-23 至 2026-08-16`、流程=`提现触发`、全端、全包体。

| 指标 | 预期累计人次 |
|---|---:|
| 触发认证 | 34,909 |
| 实际调用 BVN/NIN | 28,467 |
| 请求人脸 | 23,767 |
| 最终人脸成功 | 16,894 |
| 最终人脸失败 | 2,457 |
| 无最终结果 | 4,416 |

上线前逐项确认：

- [ ] 每张卡的日期、流程、端、包体筛选均可生效。
- [ ] Metabase 与日汇总在以上窗口、流程、端、包体条件下逐日对账。
- [ ] 无最终结果单独显示，未被计为主动放弃或最终失败。
- [ ] 失败原因标注为“尝试次数、历史不完整”。
- [ ] 普通 KYC 与羊毛看板不显示或导出原始身份、人脸、证件、手机号和三方响应。
- [ ] V1 状态标记为 `provisional`；渠道、版本、配置版本、SDK 链路和最终提现结果接入前不做因果归因。
