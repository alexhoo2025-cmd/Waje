# Waje KYC 人脸识别 Metabase 看板 V1 与 2.20 埋点方案

## 1. 实施结论

KYC 数据已接入 Metabase，首期直接在 Metabase 配置专题看板是当前最快路径。

- **V1：** 基于已有日汇总数据配置认证漏斗、每日趋势、失败与流失诊断、BVN/NIN 统计。
- **2.20：** 人脸 V2 与 SDK 同步接入，补齐 SDK 拉起、权限、活体、黑屏/超时、退出和最终提现结果。
- **羊毛分析：** 单独放在受限 Collection，不进入日常 KYC 看板。

当前阻塞项是 Metabase 看板编辑权限及入口地址；BigQuery 只读连接也需重新授权，但不阻塞已在 Metabase 中的 V1 数据配置。

## 2. 权限申请

### 申请范围

| 权限 | 范围 | 用途 | 禁止项 |
|---|---|---|---|
| Collection Curator | `Waje / Risk & KYC / 人脸识别` | 创建、编辑、保存问题与看板 | 修改其他 Collection、数据源和成员权限 |
| 数据集只读 | 已接入的 KYC 脱敏聚合数据集 | 配置图表、筛选和下钻 | 原始人脸、证件、BVN/NIN、手机号、三方完整响应 |
| 导出 | 默认关闭 | 仅看板阅读与受控查询 | 导出用户级敏感明细 |

### 可直接发送的申请文案

> 申请 Metabase 中 `Waje / Risk & KYC / 人脸识别` 专题 Collection 的 Curator/编辑权限，以及已接入 KYC 脱敏聚合数据集的只读查询权限，用于配置认证漏斗、每日趋势、失败原因和提现触发统计看板。仅使用聚合字段，不申请 BVN/NIN、手机号、人脸图像、证件或原始三方响应的访问及导出权限。

## 3. V1 看板配置契约

### 3.1 看板与筛选器

- **看板名称：** `KYC 人脸识别运营与体验监控 V1`
- **默认时间：** 最近 30 个完整自然日。
- **可用筛选器：** 日期、认证流程（提现触发/主动认证）、端、包体。
- **待字段接入后启用：** 渠道、APP/H5 版本、配置版本、风险规则版本。
- **数据状态：** V1 标记为 `provisional`，直到 Metabase 日汇总与认证原始导出完成日级对账。

### 3.2 卡片清单

| 区域 | 图表/指标 | 计算口径 | V1 数据支持 |
|---|---|---|---|
| 顶部 KPI | 触发人数、实际调用人数、请求人脸人数、最终成功人数、无最终结果率 | 使用同日期/流程/端/包体分组汇总 | 支持 |
| 认证漏斗 | 触发 → 调用 BVN/NIN → 请求人脸 → 最终结果 → 最终成功 | 最终结果＝成功＋失败；无最终结果＝请求－成功－失败 | 支持 |
| 每日效率趋势 | 启动率、BVN/NIN 通过率、人脸成功/请求、成功/已形成结果、端到端成功率 | 每日先计算分子/分母，再汇总展示 | 支持 |
| 失败诊断 | 人像不匹配、请求接口失败、三方接口错误 | 当前为失败尝试次数；明确标注非失败用户数 | 支持，历史不完整 |
| 流失诊断 | 触发后未调用、调用后未请求人脸、请求后无结果、最终失败 | 各阶段差值与占总流失比例 | 支持，身份通过阶段为代理 |
| BVN/NIN 统计 | BVN/NIN 调用、通过、失败、仅 BVN、仅 NIN、双调用 | 各方式独立通过率，禁止合并成单一“身份通过率” | 支持 |
| 端与包体对比 | App/H5 的漏斗、无结果率、失败原因 | 按端、包体切分；渠道和版本待后续字段 | 支持 |

### 3.3 指标字典

| metric_id | 指标 | 公式 |
|---|---|---|
| `kyc_start_rate` | 认证启动率 | 实际调用 BVN/NIN 人数 ÷ 触发人数 |
| `kyc_bvn_pass_rate` | BVN 通过率 | BVN 通过人数 ÷ BVN 调用人数 |
| `kyc_nin_pass_rate` | NIN 通过率 | NIN 通过人数 ÷ NIN 调用人数 |
| `face_attempt_rate` | 人脸尝试率 | 请求人脸人数 ÷ 实际调用 BVN/NIN 人数 |
| `face_result_rate` | 人脸形成结果率 | （最终成功＋最终失败）÷ 请求人脸人数 |
| `face_success_request_rate` | 人脸成功率（请求口径） | 最终成功 ÷ 请求人脸人数 |
| `face_success_completed_rate` | 人脸成功率（结果口径） | 最终成功 ÷（最终成功＋最终失败） |
| `face_unresolved_rate` | 无最终结果率 | （请求－最终成功－最终失败）÷ 请求人脸人数 |
| `kyc_e2e_success_rate` | 端到端成功率 | 最终人脸成功 ÷ 触发人数 |

## 4. 当前字段支持与缺口

### 已有日汇总字段

`日期`、`流程`、`端`、`包名`、`每日触发人数`、`实际调用 BVN/NIN 人数`、BVN/NIN 调用/通过/失败、请求人脸人数与次数、最终成功/失败、历史失败次数、当前保留失败原因、成功后清除失败原因。

### 当前不能承诺的能力

1. 当前没有渠道、版本、配置版本和风险规则版本，不能做渠道/版本因果对比。
2. 当前没有身份通过人数，只能以“请求人脸”作为身份通过后的代理阶段。
3. 当前没有 SDK 拉起、摄像头权限、活体、黑屏、退出或弱网状态，无法定位人脸请求后无结果的真实原因。
4. 当前没有认证后提现提交、审核和最终提现结果，认证成功不能解释为提现成功。
5. 当前失败原因按尝试次数汇总，且成功后可清除，不能作为历史失败用户分布。

## 5. 2.20 SDK/V2 埋点补充

2.19 不新增；2.20 与人脸 V2 改造同步接入。

| 事件 | 最小字段 | 主要用途 |
|---|---|---|
| `KYC_RISK_DECISION` | `withdraw_id`、风险规则/配置版本、触发结果 | 区分未触发与被规则拦截 |
| `KYC_IDV_SUBMIT` / `KYC_IDV_RESULT` | 方法、结果码、耗时、`request_id` | BVN/NIN 质量与失败定位 |
| `FACE_GUIDE_VIEW` / `FACE_PERMISSION_RESULT` | 引导展示、授权同意/拒绝 | 定位相机前流失 |
| `FACE_LIVENESS_REQUEST` / `FACE_LIVENESS_RESULT` | SDK 拉起、活体结果、耗时 | 定位黑屏、超时和活体失败 |
| `FACE_MATCH_RESULT` | 匹配结果、结果码、阈值版本 | 人像不匹配和服务异常 |
| `FACE_RETRY` / `FACE_DAILY_LIMIT` | 重试序号、限额状态 | 重试挽回与成本控制 |
| `WITHDRAW_RECHECK` / `KYC_FACE_STATUS_UPDATE` | 认证后提现提交、审核/成功/失败状态 | 认证对提现结果的实际影响 |

所有事件带：`user_id`、`withdraw_id`、`request_id`、`trace_id`、端、APP/H5 版本、包体、渠道、配置版本、风险规则版本、服务端时间、结果码与失败阶段。客户端不得上传人脸图像、证件、BVN/NIN、手机号或三方原始响应。

## 6. 配置步骤与验收

1. 管理员开通 Collection Curator 与 KYC 聚合数据集只读权限。
2. Robin 在 Metabase 创建 7 个保存问题：KPI、漏斗、趋势、失败、流失、BVN/NIN、端/包体对比。
3. 建立 `KYC 人脸识别运营与体验监控 V1`，配置统一筛选器、卡片说明、数据状态和口径链接。
4. 以 2026-07-23 至 2026-08-16 已有报告复算结果，完成端、流程、日期、包体四维对账。
5. 2.20 SDK 上线后，增加体验诊断页并完成 H5/APP、版本、渠道及提现结果关联验证。

验收标准：

- 同一筛选条件下，Metabase 与现有人脸认证日汇总逐日可对账。
- 无最终结果独立展示；不得当作用户主动放弃或失败。
- 数据延迟、缺字段、无样本、未成熟窗口分别显示，不以 0 代替。
- 普通页面不暴露 KYC 原始敏感信息；羊毛专题单独授权、禁用非必要导出。
- 2.20 后能够定位 SDK、权限、活体、匹配、退出、网络或提现结果中的具体失败阶段。
