# 事件模型概念介绍

## 文档定位

文档定义客户端 `user_event` 事件模型、预置属性、业务参数和基础流量指标。正文中的事件模型说明更新时间为 2020-06-18，版本较早，不能直接视为当前 WajeGame 全量埋点标准。

## 事件模型

客户端行为抽象为 6 种事件，并按作用对象分为应用类、页面类、模块类：

| 事件 | 英文/缩写 | 触发规则 | 主要用途 |
|---|---|---|---|
| 应用启动 | `AL / applaunch` | APP 启动时由 SDK 自动上报 | 启动、活跃、会话开始 |
| 应用退出 | `AQ / app quit` | APP 退出时上报 | 会话结束、退出率 |
| 页面曝光 | `PV / page view` | 页面展示到屏幕时上报；返回页面通常再次上报 | 页面 PV/UV、路径 |
| 页面退出 | `PD / page disappear` | 页面从屏幕消失时上报 | 页面停留、退出 |
| 模块曝光 | `MV / module view` | 模块露出屏幕 1px 即上报；仅加载但未展示不算曝光 | 模块曝光、CTR 分母 |
| 模块点击 | `MC / module click` | 用户点击模块时上报 | 点击率、模块转化 |

事件标识由模块 ID 和事件类型组成，实体字段包括 `page_id`、`module_id`。文档示例链路为：`AL → PV → MV... → MC → PV → MV... → AQ`。

## 预置属性

SDK 或用户渠道接口提供的通用属性包括：

| 字段 | 含义 | 获取方式 |
|---|---|---|
| `common.package` | 包名 | SDK 初始化 |
| `common.appVersion` | APP 版本，可覆盖 | SDK 初始化 |
| `common.hotVersion` | 热更新版本，可覆盖 | SDK 初始化 |
| `common.channel` | 渠道，可覆盖 | 用户渠道接口 |
| `common.subChanel` | 子渠道，可覆盖 | 用户渠道接口 |
| `common.osType` | OS 类型 | SDK 初始化 |
| `common.power` | 电量 | 监听 |
| `common.memoryUsage` | 内存使用量 | SDK 初始化 |
| `common.memoryRemaining` | 内存剩余量 | SDK 初始化 |
| `common.deviceModel` | 设备型号，要求英文小写 | SDK 初始化 |
| `common.deviceBrand` | 设备品牌，要求英文小写 | SDK 初始化 |
| `common.screen` | 分辨率，宽×高 | SDK/设备 |
| `common.osVersion` | 系统版本 | SDK/设备 |
| `common.carrier` | 运营商 | SDK/设备 |
| `common.network` | 网络状态 | SDK/设备 |
| `common.pushSet` | 推送设置，0 未开、1 已开；iOS 无法获取时为 -9999 | SDK/系统 |

## 业务参数

文档将业务参数分为通用参数和自定义参数，并要求先注册、再使用；新参数需要大数据审批。

已列出的通用参数包括：

- 广告：`ad_type`、`ad_sid`、`ad_mid`、`ad_spot_id`、`pos_id`；
- 联运与场景：`app_key`、`path_id`；
- 资产与道具：`asset_id`、`item_id`、`change_type`；
- 活动：`activity_id`；文档指出当时公司尚未统一活动 ID 管理；
- 前端控件：`element_position`、`element_id`、`element_content`、`element_type`、`element_selector`。

业务参数的作用是还原用户行为，并作为流量分析的重要维度。文档给出的上报结构包含 `page_id`、模块与事件明细、通用业务参数和自定义参数。

## 基础指标口径

### 页面流量

- 页面 PV：页面曝光事件次数之和；
- 页面 UV：页面曝光事件去重用户数，文档注明基于设备标识；
- 人均访问 PV：页面 PV / 页面 UV；
- 有效页面次均停留时长：有效页面停留时长之和 / 有效页面 PV；有效页面要求 `page_stay_time > 0` 且 `< 2h`；
- 页面退出率：作为 Session 结束事件的次数 / 该页面事件发生次数。

### 事件流量

- 事件次数：事件上报次数之和；
- 事件 UV：事件去重用户数，文档注明基于设备标识；
- 事件人均次数：事件次数 / 事件 UV；
- 事件 UV / 页面 UV：事件触达页面用户的转化比例。

## 对当前数据平台的价值

这份方案可以作为起源平台事件字典的历史基线，但目前不足以直接支撑新手生命周期、付费、低端机/H5 和故障定位：

1. 事件模型偏客户端展示行为，缺少用户注册、首登、首局、首充、复购、提现和订单状态等业务事实事件。
2. UV 口径以设备标识为主，需与 `user_id`、`xl_id`、`uuid` 的统一用户口径区分，避免把设备 UV 直接用于用户留存和付费分母。
3. 未明确 `event_uid`、`event_version`、客户端时间/服务端时间、session_id、请求 ID、去重键、迟到和重试规则。
4. 未覆盖 H5 特有的页面加载、JS 错误、接口错误、白屏、资源失败和 WebView 环境信息。
5. 设备字段可支撑低端机分析，但需要统一设备档位规则、品牌/型号规范化、内存和系统版本分层。
6. 当前事件模型中“页面露出 1px 即 MV”需要和实际 SDK、页面生命周期、重复曝光防抖规则进行验证，否则 CTR 可能被放大或重复计数。
7. 文档较早，需补充生效版本、owner、下线时间、数据源、入库状态和异常监控。

## 建议补齐的 P0 事件

### 新手生命周期

`first_open`、`register_start`、`register_success`、`login_success`、`onboarding_start`、`onboarding_step_complete`、`game_enter`、`game_start`、`game_end`、`first_game_complete`、`first_pay_intent`、`first_pay_success`。

### 付费与资金

`recharge_submit`、`recharge_callback`、`recharge_success`、`recharge_fail`、`withdraw_submit`、`withdraw_success`、`withdraw_fail`、`order_settled`、`order_reversed`。资金事实必须与服务端订单和账务表对账，不能只依赖客户端事件。

### H5、低端机和故障

`h5_load_start`、`h5_load_success`、`h5_load_fail`、`js_error`、`api_error`、`resource_error`、`white_screen`、`game_start_fail`、`game_end_invalid`、`payment_error`、`app_crash`。建议补充加载耗时、接口耗时、错误码、请求 ID、设备档位、网络类型和版本。

## 建议统一的事件公共字段

`event_uid`、`event_name`、`event_version`、`client_ts`、`server_ts`、`user_id`、`account_id`、`device_id`、`uuid`、`session_id`、`page_id`、`module_id`、`package`、`channel`、`sub_channel`、`client_type`、`app_version`、`os_type`、`os_version`、`device_brand`、`device_model`、`network`、`result`、`status`、`error_code`、`request_id`、`order_id`、`game_id`、`mode_id`、`amount`、`currency`。
