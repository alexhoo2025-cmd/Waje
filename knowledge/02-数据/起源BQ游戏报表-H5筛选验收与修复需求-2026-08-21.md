# 起源 BQ 游戏报表 H5 筛选验收与修复需求

## 结论

`BQ-游戏概况` 具备游戏人数、局数、人均局数、真人下注次数和金额字段，但 H5 渠道/分包筛选当前未真正作用于结果集。不能将该报表数值用于 H5自然、PWA自然、H5 Facebook、H5 Google 的游戏游玩、局数或下注对比。

## 验收证据

| 项目 | H5 Google | H5 Facebook |
|---|---|---|
| 日期范围 | 2026-06-16—2026-08-16 | 2026-06-16—2026-08-16 |
| 用户类型 | 新用户 | 新用户 |
| 归因媒体 | `googleadwords_int` | `facebook` |
| 分包渠道 | `wajeh5ga` | `WajeH5` |
| 返回日记录 | 62 | 62 |
| 游戏列 | `Waje Special` | `Waje Special` |
| 游戏人数合计 | 17,247 | 17,247 |
| 游戏局数合计 | 1,671,213 | 1,671,213 |
| 真人下注次数 | 1,716,146 | 1,716,146 |
| 真人下注金额 | 334,459,722.83 | 334,459,722.83 |

两个筛选条件下的62日记录逐行一致。日期范围已生效；归因媒体和分包渠道没有产生可辨识的数据差异。

## 修复要求

1. 核查前端筛选参数是否实际传入 BQ 查询；禁止仅在控件中显示已选值。
2. 报表结果必须回显并可导出：`client_type`、`package_name`、`attribution_media`、`game_id`、`play_id`。
3. 明确“新用户”筛选的SQL定义；若用于首日分析，必须满足 `register_date = game_date`。
4. 为 `BQ-玩法详情` 与 `BQ-局数分布及留存` 做相同验收；三张报表都通过后才进入轻量化游戏报告。
5. 下注金额补充 `asset_type`、`currency`、最小单位和真人/机器人边界；未确认前不跨资产汇总。

## 修复验收标准

- H5 Google 与 H5 Facebook 同窗查询不能再返回逐行完全一致的结果，除非数据开发提供可验证的业务解释。
- 每条结果可定位到端、包体、媒体和游戏/玩法；未知维度显示 `unknown`，不混入其他渠道。
- `BQ-游戏概况` 与 `BQ-玩法详情` 的同日游戏人数、局数可对账；差异需有固定口径说明。
- 通过后输出聚合日表，不导出用户、设备、订单、支付或身份明细。
