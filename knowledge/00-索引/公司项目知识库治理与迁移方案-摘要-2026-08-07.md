# 公司项目知识库治理与迁移方案摘要

> 来源：[WajeGame 飞书知识库治理与迁移方案（v1.0）](https://ksg964l11fam.sg.larksuite.com/wiki/UrxcwfNBhivvAtkSy8tlgyH3gSd)

## 一、方案定位

通过“业务域目录 + 统一交付登记册”治理项目资料，使产品规则、需求决策、研发交付、测试发布和生产事实能够独立追溯。方案目前是本地正式规划，尚不代表飞书知识库已经完成迁移或调整。

## 二、核心原则

1. 不删除历史资料，不降低原有权限，不以批量移动解决资料混乱。
2. 会议纪要、草案、调研和历史资料不能直接作为当前生产事实。
3. “文档是否定稿”和“功能是否在生产”使用两条独立状态线。
4. 资金、支付、提现、KYC、AML、风控、游戏概率、玩家限制和生产配置变更必须保留审批、范围、验证、审计和回滚信息。
5. 未确认的生产事实统一标记为“生产状态待核验”，不得仅依据标题、排期或会议结论推断。

## 三、目标知识库结构

- `00_产品现状与现行规则`：只放已确认的当前说明和索引。
- `01_业务域`：账户/KYC、支付资产、风控、游戏数值、增长活动、数据指标、客户端/H5 等主文档。
- `02_研发交付规范与模板`：PRD、技术设计、测试、发布、回滚和复盘模板。
- `03_项目交付与发布`：统一交付登记册、测试验收、版本发布、事故复盘索引。
- `04_会议记录与决策`：会议纪要、逐字稿、决策和审批结论。
- `05_调研与外部参考`：用户、市场、竞品、供应商和数据分析材料。
- `99_历史归档`：旧版本、历史项目、HFYL、已替代或已废弃资料。

## 四、统一交付登记册

后续优先使用 Lark Base 承载，作为变更状态的唯一权威来源。每一行对应一个可独立发布、回滚或验收的变更单元。

必填字段包括：

- 变更 ID：`CHG-YYYY-NNNN`，创建后不复用、不改号。
- 变更名称、业务域、变更类型、风险等级。
- 文档状态、交付状态、现行性。
- 产品与范围：国家、端、包、渠道、环境、灰度和目标人群；未知必须写“待确认”。
- 文档版本与发布版本/构建号。
- Owner、关联文档、发布证据、最近验证日期和替代关系。

高风险数据或产品变更还需记录配置版本、审批人、影响范围、回滚值、审计日志、数据口径变化及下游报表影响。

## 五、状态管理要求

### 文档状态线

草案 → 评审中 → 已批准 → 已替代/已废弃。

### 交付状态线

未排期 → 开发中 → 测试中 → 待发布 → 灰度中 → 已发布待验证 → 生产已验证；异常时可进入已回滚或已下线。

“已批准 + 开发中”不代表功能已上线；“已批准 + 灰度中”不代表全量生效；会议纪要默认不能直接进入“已批准”或“生产已验证”。

## 六、生产事实门禁

只有同时具备已批准规则、唯一发布版本、测试结论、生产范围、生效时间、监控观察结果和可执行回滚方案，才能标记为“生产已验证”。资金、支付、KYC、游戏数值和风控规则还必须记录停用路径或回滚值。

## 七、迁移和维护方式

1. 批次一：建立目录、索引、变更 ID 和登记册，不移动原文。
2. 批次二：治理当前有效的支付、资产、KYC、风控、游戏数值和发布事项。
3. 批次三：归档历史、重复和已替代资料，保留原文件、原链接和权限。
4. 每周一 15:00（Asia/Shanghai）执行只读扫描，生成本地差异和待办，不直接写入飞书。
5. 出现链接失效、权限变化、版本误判或业务异议时，立即停止当前批次并按清单回滚入口。

## 八、Robin 工作执行要点

- 新增分析、看板、埋点和产品资料时，先标注业务域、Owner、状态、范围和来源。
- 会议纪要应归档为会议证据；形成正式决策后，再关联对应变更 ID或决策记录。
- H5、APP、包体、国家、渠道和版本必须分开记录，不能仅用产品名称判断范围。
- 数据指标变更必须记录口径、时间窗、重算影响和下游报表影响。
- 涉及营收、玩家、资产、概率、风控的内容按最小权限管理，敏感字段不进入普通索引或共享看板。
- 任何“当前规则”“已上线”“生产已验证”结论都要有负责人确认或可核验生产证据。

## 九、当前未实施事项

- 尚未在飞书创建或调整目录、Base、权限和自动化。
- 尚未执行批量迁移、移动、重命名或删除。
- 待确认统一交付登记册复用现有 Base 还是新建 Base，以及各业务域和高风险变更的具体审批人。
