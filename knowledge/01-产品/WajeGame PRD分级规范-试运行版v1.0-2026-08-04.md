# WajeGame PRD 分级规范（试运行版 v1.0）

## 文档定位

这是 WajeGame 的本地需求治理规范试运行版，不证明任何线上功能已经实现或发布。规范计划通过 4 周试运行验证模板成本、风险覆盖和交付质量，维护人是产品负责人。

## 核心分级规则

| 等级 | 适用范围 | 最低交付物 |
|---|---|---|
| L1 轻量 | 文案、样式、单页展示或局部配置；无新增规则、跨系统依赖、资金和合规影响 | L1 模板、验收点 |
| L2 标准 | 用户流程、状态、权限、接口、后台配置、数据埋点或跨团队协作 | L2 模板、测试清单、发布说明 |
| L3 高风险 | 资金、支付、风控、身份、合规、概率/RTP、账务、关键数据系统、关键第三方或大范围体验影响 | L3 模板、专项附录、测试/发布预案、审计证据 |

出现下列任一情况必须升为 L3：充值提现和账务、支付回调和补单、KYC/AML/责任博彩、游戏概率/RTP/结算、自动化风控或经营决策数据系统、关键第三方链路、监管/隐私/审计要求。

仅展示类数据看板可按 L2 处理；如果看板结果用于自动限制、资金决策、风控决策或合规报送，则按 L3 处理。

## 统一需求头信息

所有需求必须具备：需求名称与编号、等级与理由、需求状态线、交付状态线、产品/研发/测试/发布负责人、业务目标、影响范围、风险与依赖、附录与证据、版本记录。

全链路变更建议使用 `CHG-YYYY-NNNN`，让 PRD、任务、代码、测试和发布记录能够关联。

## 对数据产品和埋点的直接约束

L2 模板明确要求补充：

- 数据与埋点：事件、属性、指标口径、数据负责人、验证方式；
- 页面、接口和字段：字段定义、必填规则、枚举、展示逻辑和接口契约；
- 测试与验收：异常、权限、兼容、回归和上线后验证；
- 发布计划：监控项、灰度范围、回滚条件和责任人。

数据系统专项附录还要求：

1. 指标字典：名称、定义、公式、粒度、时区、币种、过滤条件、负责人和变更历史。
2. 数据血缘：源系统、表/事件、加工逻辑、更新频率、依赖、输出和消费者。
3. 数据质量：完整性、唯一性、及时性、准确性、一致性、告警阈值、责任人和处理时限。
4. 权限与隐私：数据分级、最小权限、脱敏、导出限制、审计日志和保留策略。
5. 失败恢复：迟到、重复、回填、重跑、历史修正、版本兼容和下游通知。
6. 验收与发布：对账样本、历史回放、口径签字、性能容量、监控面板和回滚/停用条件。

## 交付流程与状态线

标准流程为：需求澄清 → Open Spec → Product Design → PRD → 开发 → 测试验收 → 发布 → 发布后验证。

每个需求必须同时维护两条状态线：

- 需求状态线：草拟、评审中、已批准、暂缓、已取消；
- 交付状态线：未排期、开发中、测试中、待发布、灰度中、已发布待验证、生产已验证、已回滚、已下线。

只有交付状态为“生产已验证”且具备验证证据，才可以对外描述为完成上线验证。

## 试运行指标

规范建议记录：分级覆盖率、分级一致率、一次评审通过率、需求返工率、验收缺项率、L3 风险覆盖率、发布后异常率和文档准备周期。所有指标需要注明样本范围、统计周期和数据来源。

## 数据平台建设解读

这份规范为起源数据平台重构提供了治理要求：数据看板、指标服务、告警和自动化分析不应只交付页面，还必须交付指标字典、血缘、质量规则、权限、监控和发布后验证。后续新手生命周期、付费、低端机/H5 和故障定位项目，至少按 L2 处理；涉及资金决策、风控限制或自动化动作时，应按 L3 + 数据系统专项附录评审。
