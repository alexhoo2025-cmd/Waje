# Waje H5轻量化游戏新增用户行为与留存影响分析（持续更新）

> 本地归档已由 [Dn Day 版](./Waje-H5轻量化游戏新增用户行为与留存影响分析-DnDay-2026-09-01.md) 接替。旧稿保留用于追溯 2026-08-21 的原始分析过程；不再作为跨平台留存口径的正式引用。

数据范围：

- 历史留存：2026年6月16日—8月16日；
- GA4行为最新完整日：2026年8月27日；
- 新增留存最新完整日：2026年8月29日；
- 分析对象：H5自然、PWA、H5 Facebook、H5 Google；产品Top Games九款。

> **数据截止差异：** 新增留存已更新至8月29日；GA4游戏页面行为仍只到8月27日。8月30日尚未形成完整日数据，不补零、不以部分日代替完整日。

## 核心结论

1. **轻量化上线后的改善没有覆盖全部渠道。** 两个等长28天窗口显示，H5自然D1/D3/D7分别提升 **7.6/4.8/3.8个百分点**，H5 Google提升 **3.8/4.0/1.0个百分点**；Facebook D7下降0.2个百分点，PWA在新增扩大97.6%的同时D7下降3.1个百分点。正向信号集中在自然量和Google，不能概括为“H5整体改善”。

2. **近期五款游戏中，Limbo页面触达最大；Plinko重复进入强度最高。** 8月21—27日，GA4记录 **1,140,489** 条Web事件和 **7,513** 名首次访问用户。进入目标游戏页面的新访客为：Limbo **647人**、Color Dice 413人、Plinko 365人、Keno 271人、Hilo 184人；Plinko人均页面浏览 **6.27次**。页面进入不等于开局或局数。

3. **进入游戏页后的短期回访存在差异，但尚不能判断单游戏效果。** Keno的D1应用回访 **36.4%** 最高，Hilo为34.4%、Plinko为31.3%；D3以Plinko **17.3%**、Hilo **16.7%** 较高。Limbo为D1 29.0%、D3 13.9%；各游戏D7尚未成熟。

4. **首充用户普遍有游戏行为，短板集中在Facebook。** 上线后首充用户7天内有任意游戏记录的比例为 **96.0%**；H5自然、Google分别为99.0%、98.8%，Facebook仅90.2%。当日新增首充用户7天游戏参与率为95.4%，明显高于当日新增未付费用户的42.1%。这说明问题不是“首充用户普遍不玩”，而是Facebook渠道的承接明显偏弱。

5. **完整的“加载—可玩—下注—结算”漏斗仍不可用。** 起源已有GAMESTART、GAMEEND和BETREWARD等服务端事件，但H5专用GAME_LOAD、GAME_READY、BET_READY尚未落地；入口与游戏缺少稳定关联，GAMEEND异常率约6.13%。缺失环节不能计为用户流失。

## 6. 新增用户完整漏斗：哪些可用，哪些仍缺

![新增用户全链路数据可用性](../../analysis/h5_lightgame_report_reorg_2026_08_31/charts/05_新增用户全链路数据可用性.png)

| 阶段 | 状态 | 当前能回答什么 |
|---|---|---|
| 新增注册、H5访问 | 可用 | 注册规模、页面访问和短期回访 |
| 游戏页面进入 | 部分可用 | 进入路由，不代表点击或开局 |
| 入口曝光/点击 | blocked | H5来源、入口和game_id关联未通过 |
| GAME_LOAD / GAME_READY / BET_READY | blocked | H5专用事件尚未落地 |
| GAMESTART | 覆盖不完整 | 不能把未命中解释为未玩 |
| 有效下注 | 部分可用 | 只有首充用户累计快照 |
| 首局结算 | blocked | GAMEEND异常约6.13%，未与结算事实完成对账 |
| D1/D3应用回访 | 可用 | GA4首次访问批次的后续访问 |
| D7/D15 | 分源/未成熟 | 历史渠道留存可用；当前单游戏为N/A |

**准确结论：** H5加载和可玩状态缺少专用上报；下注、结算服务端事件已经存在，但尚未完成与H5入口、用户、游戏及局次的稳定关联。因此不能把缺失阶段计为用户流失，也不能据此判断加载慢或游戏不可玩。

## 7. 设备与体验：优先排查哪些环境

GA4设备基线显示：

- 移动端事件占97.94%，Android占73.85%；
- Chrome与Safari合计占96.68%；
- Tecno、Infinix、itel合计占移动端事件35.38%。

Android Chrome、iOS Safari、Tecno、Infinix、itel应作为首批回归组合。当前只能比较行为量，不能判断哪个设备加载慢或更容易失败：Firebase Web App未关联Analytics流，Web Performance无数据，GA4也没有Web Vitals和加载错误事件。

## 8. 结论与后续计划

1. **P0｜优先修复Facebook承接。** 用同媒体计划、同入口和同设备条件复测“注册→首充→返回大厅→游戏页→7天有游戏”；同时监控首充与未付费两组。
2. **P0｜补齐H5前端链路。** 上报入口曝光/点击、GAME_LOAD、GAME_READY、BET_READY、错误、重试和恢复，并携带game_id、入口、会话、H5版本和配置版本。
3. **P0｜建立认证游戏过程事实。** 按注册日×游戏×渠道输出首日进入、有效下注、首局结算、局数分层及D1/D3/D7复玩。
4. **P0｜修复GAMEEND并完成服务端对账。** GAMESTART→GAMEEND→BETREWARD→ASSET关联通过、异常率降至1%以下后，再恢复首局完成和结算漏斗。
5. **P1｜继续追踪Hilo/Plinko。** D7/D15达到统计口径后，按相同上线年龄比较；小样本和未达到D15/D30统计口径的数据不下结论。
