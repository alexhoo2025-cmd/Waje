# Waje H5轻量化游戏上线后留存与活跃度效果分析 V4（阶段性）

> 数据窗口：2026年6月16日—8月16日；观察日：2026年8月19日；四渠道共同覆盖62个注册日期批次。本报告只讨论新增、游戏参与、留存和活跃度，不纳入其他指标。

## 核心结论

1. **轻量化上线后的留存改善并不一致。** H5自然在等长窗口中D1/D3/D7分别提升 **+7.6pp / +4.8pp / +3.8pp**；H5 Google提升 **+3.8pp / +4.0pp / +1.0pp**。H5 Facebook的D7微降 **-0.2pp**，PWA自然下降 **-3.1pp**。

   **D15追踪方向相同但样本更短：** H5自然 **+1.7pp**，H5 Facebook **+0.3pp**，H5 Google **-0.2pp**，PWA自然 **-4.4pp**。上线后D15只覆盖截至8月4日注册的用户，用于方向性观察。

2. **整体D7在后续发布阶段走高，但不能归因到单一游戏。** 全体D7从上线前基线的 **8.9%**，在Color Dice阶段升至 **10.2%**、Opera埋点期升至 **10.5%**；同期叠加版本、KYC、活动、投放和故障，结论只能说明阶段变化。

3. **Facebook是最大规模但最低留存的渠道。** 62天新增 **365,038**，D1/D3/D7为 **27.7% / 15.0% / 6.8%**；其规模不能代表轻量化体验已改善。8月15—16日投放账户封禁导致新增骤降，相关日期不用于体验判断。

4. **现有数据还不能把游戏人数、局数或下注归因到H5/PWA渠道。** 2026年8月21日现场验收中，H5 Google与H5 Facebook在“新用户＋62天日期范围”条件下返回的游戏报表62日明细完全相同；归因媒体与分包渠道未真正进入查询结果。设备监控仍报 `app_id` 歧义，事件也缺少可玩、版本和标准游戏关联字段。当前应先修复证据链，而不是扩大单游戏结论。

| H5自然 | 206,167 | 35.2% | 20.9% | 11.7% | 5.3% | 3.2% | 可用 |

**解读：** H5 Google在各留存节点领先标准H5 Facebook；PWA自然在D1/D3保持领先，但到D7与H5自然接近。渠道结构、入口和运行形态不同，因此不能把PWA与标准H5的差异直接写成产品优劣。

## 二、轻量化上线前后：H5自然和Google改善，Facebook与PWA未同步

比较窗口：上线前6月16日—7月13日；上线后7月14日—8月10日；两个窗口均为28天。

| 渠道/运行形态 | 新增变化 | D1 / D3 / D7变化 | D15变化 |
|---|---:|---:|---:|
| H5自然 | -5.1% | +7.6pp / +4.8pp / +3.8pp | +1.7pp |
| H5 Facebook | +16.6% | -1.8pp / -0.1pp / -0.2pp | +0.3pp |
| H5 Google | -52.3% | +3.8pp / +4.0pp / +1.0pp | -0.2pp |
| PWA自然 | +97.6% | -2.4pp / -2.3pp / -3.1pp | -4.4pp |

**解读：** 轻量化后的正向留存信号集中在H5自然和Google；Facebook没有改善，PWA自然出现反向变化。后续不应按“全H5统一有效”推进，而应拆渠道、入口和运行形态验证。

> **D15观察边界：** 上线后仅纳入7月14日—8月4日注册、截至观察日已完整走满15天的用户。各渠道上线后样本为17—20个注册批次，少于D1/D3/D7的28日窗口；D15用于方向性追踪，不与首周结论作同等强度比较。

## 五、活跃与游戏参与：当前可以看到什么，尚缺什么

### 已可用：GA4页面活跃快照

**页面进入已可见，但尚不能替代“游戏开始、首局完成或结算”。** 2026年7月23日—8月19日（Africa/Lagos），`www.wajegame.com`记录 **39,468** 名活跃用户、**174,925** 次会话和 **4,383,373** 次事件。Limbo 9008页面的活跃用户和人均页面浏览均高于Color Dice 9003；两款游戏的上线时间与曝光条件不同，这一差异只能说明页面访问规模不同，不能直接判断玩法效果。

| 游戏页面 | 活跃用户 | 页面浏览 | 人均页面浏览 |
|---|---:|---:|---:|
| Limbo 9008 `/game/9008` | 4,708 | 16,047 | 3.41 |
| Color Dice 9003 `/game/9003` | 2,082 | 4,989 | 2.40 |

两页均可用于观察页面进入和重复浏览；目前不能据此判断游戏开始、首局完成或玩法优劣。

移动端有 **38,564** 名活跃用户；其中Android **32,641**、iOS **6,084**。浏览器结构以Chrome **30,075** 名活跃用户为主，其后为Safari **4,242**、Samsung Internet **2,205**、Opera **1,214**、Phoenix Browser **1,082**。这为后续按浏览器、操作系统和页面做体验排查提供了优先顺序。

![GA4轻量化游戏页面活跃快照](../../analysis/h5_lightgame_effect_report_v4_2026_08_21/assets/GA4轻量化游戏页面活跃快照.png)

> **边界：** Keno页面ID尚未确认。GA4页面数据不等于游戏开始、首局完成、局数或结算；相关结论需等待起源事件链路和H5筛选门禁通过后补充。

| 维度 | 当前可用证据 | 状态 | 本报告处理方式 |
|---|---|---|---|
| 新增规模 | 四渠道每日新增与趋势 | 可用 | 用于解释渠道结构变化 |
| 网站与游戏页面活跃 | GA4活跃用户、会话、页面浏览、浏览器和操作系统 | 部分可用 | 已用于页面访问与设备结构汇总 |
| 入口点击 | Web元素点击、模块点击 | 部分可用 | 可建立漏斗起点，需确认入口属性 |
| 游戏开始/结束/结算 | 起源敏捷事件 | 部分可用 | 可建立行为链路，需补标准游戏关联键 |
| 0局、1局、2–3局、11局+ | BQ局数分布及留存具备报表入口 | 阻断 | H5筛选验收失败，不呈现数值 |
| 游戏人数、局数与真人下注 | BQ-游戏概况、BQ-玩法详情 | 阻断 | 渠道/分包筛选未生效，不能写入H5/PWA结论 |
| 单游戏参与和首局完成 | 游戏开始/结束事件 | 阻断 | 缺game_id、版本、入口和会话关联 |
| 低端机、弱网、浏览器、版本 | 设备监控与GA4 | 阻断/部分可用 | 设备监控修复前不做归因 |

敏捷分析当前可建立的最短可信链路：

```text
H5首页/模块曝光
→ 模块点击或Web元素点击
→ 游戏开始
→ 游戏结束
→ 结算奖励
→ 当日复玩
→ D1/D3/D7留存
```

但`game_ready`、`bet_ready`、失败码、重试、标准`game_id`、真实H5版本和配置版本尚未覆盖。报告不以缺失环节推断用户未玩原因。

## 六、游戏游玩与下注数据：H5筛选验收未通过

**结论：** 起源 `BQ-游戏概况` 已有游戏人数、游戏局数、人均局数、真人下注次数和真人下注金额字段；但当前不能把它们写入本报告的 H5自然、PWA自然、H5 Facebook 或 H5 Google 对比。

现场在同一查询中设置日期 `2026-06-16—2026-08-16`、用户类型“新用户”，分别使用以下两组条件：

| 验收项 | H5 Google | H5 Facebook | 判断 |
|---|---|---|---|
| 归因媒体 / 分包渠道 | `googleadwords_int` / `wajeh5ga` | `facebook` / `WajeH5` | 控件显示已选中 |
| 返回日记录 | 62日 | 62日 | 日期范围生效 |
| 游戏列 | 均为 `Waje Special` | 均为 `Waje Special` | 未下钻至实际游戏/包体 |
| 游戏人数合计 | 17,247 | 17,247 | 62日逐行完全相同 |
| 游戏局数合计 | 1,671,213 | 1,671,213 | 62日逐行完全相同 |
| 真人下注次数 / 金额 | 1,716,146 / 334,459,722.83 | 1,716,146 / 334,459,722.83 | 62日逐行完全相同 |

以上数字仅作为**筛选验收指纹**，不代表任一 H5 渠道的真实游戏表现，不能用于渠道排名、轻量化效果或下注结论。“新用户”是否严格等于“注册首日用户”也尚需数据开发确认。

### 需要修复后补充的正式数据

1. `BQ-游戏概况`、`BQ-玩法详情`、`BQ-局数分布及留存` 的归因媒体、分包渠道、终端和游戏/玩法筛选必须真实参与查询，并在结果中回显 `client_type`、`package_name`、`attribution_media`、`game_id`、`play_id`。
2. 修复后以 H5 Google 与 H5 Facebook 的同窗结果为验收样本：两组结果不应再逐行完全一致；若相同，必须给出业务或SQL层面的可解释原因。
3. 仅在筛选验收通过后，补入四渠道新增用户首日的进入人数/次数、局数、人均局数、真人下注用户/次数/金额、0局至11局+分布，以及 Limbo、Keno、Color Dice、Hilo、Plinko 的逐游戏对比。
4. 敏捷分析需补齐 `element_id → game_id → GAMESTART → GAMEEND/BETREWARD` 关联；否则点击、进入、首局完成和结算漏斗继续显示 `blocked`。

## 七、下一步：先把数据查准，再分析单游戏效果

1. **让设备数据可用。** 修复设备数据报表，使其能区分 App、H5、PWA 和不同渠道；补齐至少 14 天完整数据后，再分析低端机、弱网和浏览器问题。
2. **确认游戏数据筛选正确。** 用已知的 H5 用户和日期核对包体、渠道、媒体及结果是否正确；确认前，不把游戏人数、局数等数据写进分析结论。
3. **补齐游戏过程数据。** 记录用户是否加载成功、能否下注、失败原因和重试情况；每次游戏还要能关联到具体游戏、局次、入口、会话、H5 版本和配置版本。
4. **建立标准的游戏漏斗。** 按“进入游戏 → 开始首局 → 游戏结束 → 结算 → 当日再玩”统计人数和转化率；先确认每一步人数与同一批用户能对应上，再作为正式结果发布。
5. **补齐 GA4 体验分析。** GA4 每日数据稳定后，对比页面、渠道、浏览器、操作系统和屏幕尺寸，定位不同用户的体验差异。

## 附录：统计范围与来源

- 留存率按每天注册人数的多少加权计算。看 D7 时，只统计已注册满 7 天的用户；未满 7 天的用户不算作流失。
- 报告分别比较 H5 自然、PWA 自然、H5 Facebook 和 H5 Google；PWA 作为独立安装形态单列。
- 8 月 15—16 日 Facebook 新增骤降，已确认由投放账户封禁造成，不作为产品体验变化解读。
- 数据来源：四渠道新增用户留存基线、起源报表集市与敏捷分析审计结果、起源 BQ 游戏报表 H5 筛选验收（2026-08-21）、飞书更新记录修订 1812、GA4 H5 审计基线。
