# Waje 正式版 H5 新手体验与数据分析报告｜2026-08-14

## 1. 执行摘要

本次完成了正式站的一个**访客会话样本**：从 `Guest Login` 进入大厅、使用初始余额完成 Whot 最小下注与结算、核对交易流水，并检查了首充、Coins、手机号绑定、提现前置条件、帮助和消息中心。

最顺畅的链路是：

`访客登录 → 初始余额 → Whot 选场/匹配 → 局内操作 → 结算 → Transactions 对账`

现场可核对到：Whot 最小下注 `NGN 1.00`，结算入账 `NGN 1.80`，净变化 `+NGN 0.80`，账户余额由 `NGN 600.00` 变为 `NGN 600.80`。这只是一局结果，**不能据此推导 RTP、胜率或收益能力**。

当前最值得优先解决的不是“缺少入口”，而是新手主线的可理解性和可观测性：

- 访客初始资金在流水中显示为 `Others-Newbie (Cash)`，但本样本的该笔入账早于本次体验，说明会话不是纯 Day 0；新手奖励、现金和可提现资格的含义需要明确区分。
- `Super Sale` 在回到大厅、尝试进入其他游戏和点击 Daily Chip 时反复出现，容易抢占新手任务和试玩主线。
- 独立的新手任务中心在当前会话中不可见；Mail 为空，Daily Chip 可见但未进入到可领取/完成说明。
- 手机号绑定对提现和账户恢复是硬门槛，提示本身清楚，但应更早解释“未绑定时哪些资金/功能不可用”。

### 2.1 样本限制

Transactions 中可见一笔 `Others-Newbie (Cash) +NGN 600.00`，日期早于本次体验；因此不能把本次看到的 `NGN 600.00` 直接归因为“本次注册奖励”，也不能用其评估 Day 0 奖励到账率。报告不保留该会话的用户名、稳定用户标识、联系方式或订单标识。

## 3. 新手旅程与关键观测

### 3.1 主路径

```text
Guest Login
  → 大厅与余额 NGN 600.00
  → TopGame / Exclusives 中的 Whot
  → 选注：Bet 1（资产门槛 Assets 1+）
  → 匹配约 2 秒
  → 抽牌 / 出牌
  → Victory 结算
  → Transactions：下注 -1.00、中奖 +1.80
  → 余额 NGN 600.80
```

### 3.2 大厅与内容组织

首页由品牌/余额区、滚动中奖播报、搜索、AllGames 筛选、运营 Banner、分类游戏墙和底部导航组成。当前可见的内容层级包括：

| 层级 | 现场代表内容 | 新手作用 |
|---|---|---|
| TopGame | Whot、Limbo、CoinFlip、Keno、NairaSlots、Roulette、Bottle Spin、Fish、Color Dice | 快速进入高频玩法 |
| Exclusives | Fish、Whot、WajeSpin、NairaSlots、Roulette、JacksOrBetter、BaccaWhot、WhotDuel、Dice | 突出自有/重点游戏 |
| New / TopPicks | TaDa、PpGame 等内容及热门游戏 | 供应商内容与推荐分发 |
| Slots / Fish / Crash / QuickGames | 老虎机、捕鱼、Crash、棋牌和短局玩法 | 以玩法类型承接不同偏好 |
| 底部导航 | Sports、Deposit、Game、Withdraw、User | 资金、内容和账户的主导航 |

多数 TopGame 卡片带有 `Free` 标记，但本次只验证了 Whot 可用最小现金下注；`Free` 是免费试玩、免费首局还是仅视觉标签，仍需以事件和配置复核。

### 3.3 Whot：完整最小注样本

| 环节 | 已观察事实 | 产品/数据含义 |
|---|---|---|
| 进入 | 路由为 `/game/6001`，游戏由 iframe 承载 | 需要建立 H5 容器与 iframe 双侧事件链路 |
| 选场 | 可见 `Bet 1 / 200 / 500 / 1000 / 2000 / 5000`，对应资产门槛 | 场次、最小注、余额校验必须可追溯 |
| 匹配 | 选择 Bet 1 后进入 Matching，约 2 秒进入牌局 | 匹配耗时应进入首局漏斗和质量监控 |
| 局内 | 可抽牌、按当前花色/图形出牌；菜单提供退出、声音、音乐、震动、Note、Rule | 局内动作目前是 Canvas，埋点不能只依赖 DOM 自动采集 |
| 结算 | 结果页显示 Victory；流水有 Bets-Whot `-1.00`、Winnings-Whot `+1.80` | `BET → GAMEEND → ASSET/流水` 可完成最小闭环核对 |
| 延迟 | Canvas 左上显示约 `377–436ms` 的红色毫秒读数，页面未标注该值含义 | 不可直接当作 RTT；应补充指标名称、口径与告警阈值 |

本局的回报倍数为 `1.80 / 1.00 = 1.8`，只代表这一次结算。RTP 需要基于足够样本、统一玩法/场次/资产类型和完整结算状态计算。

### 3.4 福利、任务与商业化触点

#### 已确认的触点

- **新手初始资产线索**：流水存在 `Others-Newbie (Cash)`；需要确认触发条件、到期规则、可提现性和是否与访客身份绑定。
- **Super Sale**：展示 `Extra 150%`，并可见 `NGN 1,999` 的首充/分日组合权益；当前可见档位中包含 `NGN 2,000 + Coins 500`、Day 2 `NGN 100 + Coins 500`、Day 3 `NGN 100 + Coins 1,000`。具体金额以当前活动配置为准。
- **Daily Chip**：大厅右下角有独立入口，但点击后被 Super Sale 覆盖，未达到“任务说明 → 条件 → 领取”闭环。
- **Coins**：当前余额 `0.00`；页面明确说明充值可返 Coins，Coins 可用于 Coin Games、不消耗其他货币，高倍数玩法可增加 Extra BonusChip 获得机会。
- **推荐好友、添加到主屏、下载 App、客服**：均位于用户中心，是留存/分发触点。

#### 当前会话未见的内容

- 独立的新手任务列表、任务进度、完成条件和领奖历史；
- Mail 中的新手引导或任务通知（页面显示 No Message available）；
- Daily Chip 的领取成功、失败、补签或连续天数状态。

这不等于正式站不存在任务系统，只能说明该访客样本在当前时间点没有暴露完整任务主线。

## 4. 资金、账户与帮助模块

### 4.1 充值

充值页提供 PalmPay、OPay 和 Bank Transfer 三类入口，支持 `1,000 / 2,000 / 5,000 / 10,000 / 20,000 / 50,000 / 100,000 / 200,000` 快捷金额，页面显示最高充值 `NGN 1,000,000.00`。

| 方式 | 页面说明 | 本次状态 |
|---|---|---|
| PalmPay | 输入金额后可填手机号或改为银行转账；页面提示 30 分钟内完成 | 仅查看说明 |
| OPay | 可前往 OPay Checkout，或选择无 OPay 账户后获取虚拟账户；页面提示 18 分钟内完成 | 仅查看说明 |
| Bank Transfer | 临时转账账户 30 分钟有效；银行/USSD 转账后通常 10 分钟入账，24 小时未入账联系银行 | 仅查看说明 |

未填写金额、手机号、银行卡或钱包信息，未发起支付订单。因而本报告不能评价支付成功率、失败码、到账时长或支付回调一致性。

### 4.2 提现与手机号绑定

账户中心在访客会话中直接提示：**手机号验证是提现与账户恢复的必需条件**。引导将收益拆为 Easy Withdrawals、Account Protection、Fast Recovery 和 Quick Login，表达清楚。

但对新手而言，建议在获得初始余额、首次下注前就显示一条简短状态：

`当前余额可玩，但未绑定手机号前不可提现；绑定后需满足的其他提现条件见此处。`

这样能减少“可见余额 = 可提现余额”的预期偏差。由于未绑定手机号，本次未提交提现申请。

### 4.3 账户中心和帮助

账户中心可见 Total Balance、Deposit、Withdraw、Coins、Transactions、Mail、Customer Service（Online 24/7）、Add to home screen、Download the app、Recommend friends、Bind Phone Number 和 How to play。

How to play 的目录覆盖 General、注册、充值、提现、交易记录、余额、账号安全和下载 App。它较好地承接账户问题，但具体游戏规则仍主要在游戏 Canvas 内的 `Rule` 菜单，形成“账户帮助与玩法帮助分离”的认知成本。

## 5. 数据对账与可用指标

### 5.1 本次可核对的最小资金闭环

| 流水类别 | 金额（NGN） | 对账结论 |
|---|---:|---|
| 新手资产线索 | +600.00 | 发生时间早于本次体验，不作为 Day 0 归因 |
| Whot 下注 | -1.00 | 与选定 Bet 1 一致 |
| Whot 中奖 | +1.80 | 与结算页 Victory 一致 |
| 本局净变化 | +0.80 | 余额从 600.00 变为 600.80，可对上 |

### 5.2 建议的核心漏斗与指标

```text
访客登录成功
→ 新手资产到账/可见
→ 首屏活动曝光
→ 首个游戏点击
→ 游戏容器加载成功
→ 场次选择
→ 首注成功
→ 匹配成功
→ GAMEEND
→ 流水入账
→ 首充/绑定/每日任务
```

| 主题 | 指标 | 关键拆分 |
|---|---|---|
| 首局 | Guest 登录后首局率、首注成功率、从登录到首注时长 | 游戏、场次、包、版本、渠道、网络 |
| 匹配 | 匹配成功率、P50/P95 匹配时长、取消率 | 游戏、bet_level、机器人/真人、地区 |
| 结算 | `GAMEEND` 完整率、下注-结算-流水对账率、重复结算率 | game_id、unique_id、source、版本 |
| 福利 | Super Sale / Daily Chip 曝光、关闭、点击、领取、支付转化 | 曝光位、用户新旧、生命周期天数 |
| 提现门槛 | 绑定提示曝光率、绑定开始率、完成率、提现前拦截率 | 余额区间、充值状态、版本 |
| 帮助 | Help 打开率、问题分类点击率、客服转人工率 | 页面、问题类型、是否已绑定 |


所有资金相关事件至少携带：`user_id（脱敏内部键）`、`session_id`、`trace_id`、`game_id`、`round_id/unique_id`、`asset_type`、`amount`、`balance_before`、`balance_after`、`source`、`app/web_version`、`package_name`、`event_time_client`、`event_time_server`。

## 6. 问题与建议

| 优先级 | 问题/风险 | 现场依据 | 建议方案 | 验收指标 |
|---|---|---|---|---|
| P0（数据） | 新手资金、现金、Bonus/Coins、可提现资格的关系无法从首屏明确判断 | 流水存在 Newbie Cash；Coins 与主余额分离；提现需绑手机 | 建立统一资产标签与前端说明；流水/余额/提现资格共用资产字典 | 资产对账差异 `<0.1%`；余额类型说明曝光后相关客服咨询下降 |
| P0（数据） | Canvas 游戏无法靠通用 DOM 采集复原局内行为 | Whot 选场、匹配、抽牌、出牌、结算均在 Canvas | 由游戏 SDK 显式上报局内事件，并用 round_id 串联容器、GAMEEND、流水 | 首注—GAMEEND—流水链路完整率 `≥99.5%` |
| P1 | Super Sale 重复抢占游戏/任务入口 | 离开游戏、尝试其他入口及点击 Daily Chip 时均再次出现 | 加频控与互斥规则：任务/奖励点击优先，弹窗关闭后 24h 内不再强拦截 | Daily Chip 打开率、任务完成率上升；活动关闭率下降 |
| P1 | 访客新手任务主线不可见 | 当前无任务列表，Mail 为空，Daily Chip 未完成闭环 | 大厅/账户增加“新手进度”卡：首局、绑定、Daily Chip、首充、奖励状态 | 任务发现率、首日任务完成率、首局率 |
| P1 | 提现资格提示出现偏晚 | 已有余额和下注后才看到手机号绑定门槛 | 在余额区、首局后和提现页统一展示资格状态与原因 | 绑定开始率、提现页返回率、客服咨询率 |
| P2 | 游戏规则与账户帮助割裂 | Help 为账户帮助；玩法规则仅在游戏内菜单 | 游戏卡/选场页增加 3 行规则、最小注、RTP/波动说明链接 | 游戏进入后无下注退出率下降 |
| P2 | 毫秒读数没有口径 | Whot Canvas 显示红色 ms 值但未标注 | 标为网络 RTT/服务器 tick/帧耗时之一，并在埋点字典定义 | P95 延迟、异常阈值、用户投诉可关联 |

## 7. 回归与下一轮体验清单

1. 使用**新建且可追溯的 Day 0 测试账号**复跑注册、Newbie 资产、首局、Daily Chip、任务和 Mail，避免留存访客样本干扰。
2. 对 Whot、NairaSlots、Fish、Roulette 各完成至少一个最小闭环，按 `玩法规则 → 最小注 → 下注 → 结算 → 流水 → 余额` 记录，不以单局结果推断 RTP。
3. 验证 Super Sale 频控：首次曝光、关闭后、任务点击后、游戏返回后的出现条件与次数。
4. 验证手机号绑定后提现资格、可提现余额、失败码和到账流水；不得在分析资料中保存手机号、OTP、银行卡或钱包标识。
5. 从 BQ/Ares 核对 `GAMESTART → BET → GAMEEND → ASSET/ledger`，并按 H5 版本、包、渠道、游戏和场次检查漏数、重复和延迟。
