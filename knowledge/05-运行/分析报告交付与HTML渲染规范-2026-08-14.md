# 分析报告交付与飞书阅读规范｜2026-08-19

2026-09-07补充：后续报告必须遵从[报告排版与配色规范](./报告排版与配色规范-2026-09-07.md)。便携HTML使用项目统一阅读样式和 `scripts/deliver_readable_report.mjs`，保持事实与来源不变。

## 默认交付

2026-09-09补充：报告以用户最后修改/确认版为准，执行[报告定稿与跨格式同步工作流](报告定稿与跨格式同步工作流-2026-09-09.md)。飞书是默认协作入口，不代表它在每次任务中永久优先；当用户指定飞书已调整并要求同步HTML时，先回读最新飞书，再更新artifact及HTML，禁止反向用旧生成稿覆盖。最终产物须记录来源revision/哈希、转换时间、产物哈希及验收结果，保留历史备份；未请求的格式不自动发布。

自本规范更新起，项目内新增的产品、数据、竞品、版本、体验和用户评价分析报告默认交付两份：

1. 飞书云文档：作为团队内部阅读、评审、共享和持续协作的主报告；
2. Markdown：作为可追溯、可差异对比、可入库的项目存档。

飞书与 Markdown 必须基于同一事实、时间窗、口径和结论。HTML、PDF仅在用户明确要求时追加，不再作为默认交付。

## 飞书主报告要求

- 正文先给核心数据、结论和行动，不在主阅读路径堆放计算过程与口径解释；
- 重要数据和关键判断使用加粗或浅色高亮，避免大面积强色背景；
- 口径、限制和数据边界统一放入就近“备注”，不与核心结论混排；
- 使用“同日注册用户”“注册用户批次”等直白表达，避免无解释的 cohort、LTV 等术语；
- 图表、表格和文字采用浅蓝、浅绿、浅黄等护眼配色，保持移动端可读；
- 每张图表必须配一句直接结论，表格优先拆成阶段总体、阶段内渠道和阶段间变化等可比较结构；
- 创建或更新后必须通过飞书接口回读，核对标题、核心数值、图表和表格数量。

## Markdown 存档要求

- 保留核心结论、关键表格、口径备注、来源链接和可复算文件路径；
- 不要求复刻飞书排版，但核心数字和结论必须一致；
- 文件存入项目 `knowledge/` 对应主题目录，供后续检索和差异比对。

## HTML/PDF 可选交付

仅在用户明确提出离线分享、打印、外部发送或PDF归档时生成；沿用既有自包含、无外部资源、响应式和隐私安全要求。

## 验收清单

- [ ] 飞书与 Markdown 标题、日期、核心数字和结论一致。
- [ ] 飞书正文以结论为主，口径说明已下沉至备注。
- [ ] 核心数字、重要结论和行动项已加粗或高亮。
- [ ] 图表、表格在桌面和移动端均可阅读。
- [ ] 飞书文档已通过接口回读；报告中不包含凭据和个人信息。
