# 分析报告交付与 HTML 渲染规范｜2026-08-14

## 默认交付

自本规范生效起，项目内新增的产品、数据、竞品、版本、体验和用户评价分析报告默认交付两份：

1. Markdown：作为可追溯、可差异对比、可入库的源文件；
2. HTML：作为团队直接阅读、打印、演示和飞书导入的阅读版。

HTML 不替代 Markdown；两者必须基于同一事实、时间窗、口径和结论。若只完成其中一份，报告状态为 `delivery_incomplete`。

## 生成方式

通用命令：

```bash
python3 scripts/render_analysis_report_html.py \
  --input knowledge/路径/报告.md
```

默认输出为同目录、同文件名的 `.html` 文件。已有自动生成脚本必须在写完 Markdown 后调用该渲染器。

## HTML 阅读版要求

- 保留标题层级、执行摘要、证据边界、表格、代码/SQL 和来源链接；
- 使用可搜索、可复制的文本和原生 HTML 表格，不用整页截图替代正文；
- 对数据图表或流程优先使用可访问的 SVG/CSS/表格回退；
- 适配桌面、移动端和打印；
- 不写入账号、密码、Cookie、Token、手机号码、支付账户或用户明细；
- 没有直接证据的推断必须沿用“待验证/样本限制”标识。

## 验收清单

- [ ] Markdown 与 HTML 标题、日期、核心数字和结论一致。
- [ ] HTML 可在本地浏览器直接打开，目录和来源链接可用。
- [ ] 表格可横向滚动，移动端不截断关键内容。
- [ ] HTML 不依赖第三方字体、脚本或敏感资源。
- [ ] 生成日志或报告中不包含凭据和个人信息。
