# 用户分层需求 1.1 版本迭代规划研讨会｜数据行动

> 会议时间：2026-08-17 14:33–15:31（GMT+08）  
> 证据级别：智能纪要摘要。未读取关联文字记录，因此会议中提到的功能、模型和计划均不等同于已开发、已上线或已验证事实。

## 一、会议结论

1. **用户分层 1.1 的重点是补齐实验和分析能力。**
   - 解决现有方案中“无法区分不同测试用户”及用户分析不完整的问题。
   - 部分内容计划提前纳入 1.2 评估，以支持后续开发规划。
2. **本次讨论的三个核心模块。**
   - 引入外部模型预测用户行为，并生成可运营人群。
   - 支持创建固定人群，满足运营临时配置需求。
   - 配置实验组/对照组分流，并补充数据统计和执行明细。
3. **数据工作应先冻结核心指标，再确定埋点。**
   - Despera 计划在近期拆分重点指标，优先包括留存数据和基础付费数据，并与 Nick 核对可行性。
4. **奖励领取的人脸验证需独立推进。**
   - 需要单独形成需求，并与客户端及 Kevin 确认实施细节。
5. **模型与风控相关事项仍处于不同成熟阶段。**
   - 已有用户流失预测模型 V1.0；pLTV 模型刚启动；QIC 领钱验证问题待继续跟进。

## 二、对数据分析与埋点的影响

用户分层 1.1 应以“固定分母、稳定分流、全链路执行事实、对照组增量”作为数据主线：

```text
基础/模型人群快照
  → 场景进入
  → 实验组 / 对照组稳定分流
  → 节点执行、触达与奖励
  → 登录、游戏、付费与留存结果
  → 与对照组比较增量
```

本次会议确认的是方向和待办，尚未确认具体指标公式、分流比例、模型字段、埋点名称或上线时间。后续数据设计继续以 [[../02-数据/用户分层与场景运营V1.1-观测指标与埋点规划-2026-08-17]] 为实施基线，在指标核对后补充正式需求。

### 本轮应优先确认的指标

| 模块 | 首批确认指标 | 数据用途 |
|---|---|---|
| 实验分流 | 场景进入人数、分流完整率、实际分流比例、分组偏差 | 固定实验分母，验证组间可比性 |
| 用户结果 | D1/D7 留存、首充率、充值转化率、ARPU/LTV | 衡量方案相对对照组的效果 |
| 执行过程 | 节点执行率、触达送达率、奖励到账/领取率 | 区分策略无效、链路失败和用户未响应 |
| 数据质量 | 重复分流率、重复发奖率、事件完整率、成熟 cohort 占比 | 避免错误数据污染结论 |

### 埋点与事实层原则

- 场景进入与实验分流由服务端事实固定，不能只依赖客户端曝光或点击。
- 同一用户在同一实验中只分流一次，后续节点沿用首次 `group_id`。
- 留存、ARPU、LTV 和增量收益均以首次分流人数为分母；未成熟观察窗口显示 `N/A`。
- 模型预测标签、完整付费价值和风控明细只保存在受控服务端事实层；普通看板仅展示聚合结果。
- 人脸验证涉及 KYC/敏感数据，数据侧只记录脱敏状态、结果码和链路耗时，不保存或导出人脸图像与生物特征。

## 四、下一步行动

### P0

1. 与 Despera、Nick 完成首批核心指标核对，特别确认留存和基础付费指标的用户范围、分母、日期口径和数据源。
2. 固化场景进入、实验分流、节点执行、触达/奖励和结果回收的唯一关联键，避免后续无法做对照分析。
3. 将实验组、对照组、模型人群和固定人群拆为独立维度，避免将模型预测结果直接等同于运营效果。

### P1

1. 将人脸验证作为独立的 KYC/奖励领取链路设计，补齐状态码、失败原因与权限边界。
2. 为流失预测 V1.0 和 pLTV 模型建立模型版本、生成时间、覆盖率和预测偏差观测，不将模型输出直接作为事实结论。
3. 在用户分层 1.1 进入测试后，按场景、实验、方案、平台和渠道建立固定分母的效果看板。
