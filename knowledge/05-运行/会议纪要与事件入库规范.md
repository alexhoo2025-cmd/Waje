# 会议纪要与事件入库规范

适用于晨会、产品评审、版本发布、数据需求、运营策略与事故复盘等会议。目标是把会议内容转为可验证、可观测、可追溯的工作项，而不是把会议口述直接当作生产事实。

## 固定输出

1. **会议摘要**：只保留已明确的结论、任务、风险和依赖。
2. **数据分析拆解**：标识对指标、埋点、数据质量、报表、版本、渠道、游戏和用户分层的影响。
3. **事件台账**：每项生成 `EVT-YYYYMMDD-NN`，包含范围、Owner、来源、状态、数据动作和待确认项。
4. **行动清单**：按 P0/P1/P2 排序，写明下一步与验收证据。

## 入库字段

| 字段 | 说明 |
|---|---|
| 事件 ID | 会议记录使用 `EVT-YYYYMMDD-NN`；正式可发布变更另关联 `CHG-YYYY-NNNN` |
| 来源与证据 | 会议链接、文字记录、时间戳；AI 摘要不作为唯一证据 |
| 事项类型 | 产品功能、版本发布、渠道/投放、游戏/供应商、数据/埋点、报表、运营策略、事故/修复 |
| 范围 | 国家、端、包体、版本/构建、渠道、游戏、目标人群；未知明确写“待确认” |
| 状态 | 计划中、开发中、测试中、待发布、已发布待验证、生产已验证、待确认 |
| 数据影响 | 指标、事件、维度、事实表、看板、历史重算与权限影响 |
| 验收证据 | PRD、排期、测试、发布记录、配置版本、生产样本、数据对账或负责人确认 |

## 数据侧最低检查

- 新功能：目标指标、反指标、事件/属性、失败码、版本和开关、实验组、验收窗口。
- 版本/包体/渠道：包名或 Bundle ID、版本/构建号、发布时间、投放/渠道、前后基线。
- 游戏与供应商：`game_id`、供应商、入口位、玩法/配置版本、上架状态、RTP/收入/首局漏斗。
- H5/PWA 性能：运行形态、会话、发布版本、设备/网络、加载、错误、恢复与核心链路关联。
- 报表修复：异常根因、影响范围、补数/重算、修复前后对账和下游看板影响。

## 状态与安全边界

- 会议中的“在做、接入、发测试、跟进上线、计划重启”默认均不是生产事实。
- 涉及支付、提现、资产、KYC、风控、RTP、用户明细的数据，只入库聚合口径、责任和验证要求；不在普通会议索引中写入敏感明细。
- 无法确认的字段不猜测，以“待确认”保留，并在下一次沟通、PRD、排期或数据验证后更新。

## 晨会智能纪要自动入库

- 入口脚本：`scripts/run_lark_meeting_minutes_pipeline.py`；配置：`config/lark_meeting_minutes.json`。
- 调度：工作日 10:15（Asia/Hong_Kong），独立于每日 19:33 情报管道；成功只写本地知识库和运行回执。
- 检索范围：标题包含“智能纪要” + `Owner=Max` + 最近 3 天；当前为 `scope_mode=title_owner_fallback`，不宣称已验证 `waje fhn > max` 父目录。
- 证据顺序：智能纪要用于结构导航和待办；关联原始文字记录用于独立事实总结；无文字记录时仅生成降级摘要。
- 产物：`knowledge/05-运行/YYYY-MM-DD-晨会纪要-多领域工作安排与数据行动.md`、`data/processed/lark/meeting_minutes/YYYY-MM-DD/meeting-index.json`、`data/outputs/meeting_minutes/YYYY-MM-DD/run-log.json`。
- 安全边界：Lark 只读、无消息发送、无原文修改；不保存完整逐字稿、参会人 open_id、Token、Cookie、密码或个人联系方式。
