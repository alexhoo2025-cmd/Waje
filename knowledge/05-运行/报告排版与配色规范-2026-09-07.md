# Waje 分析报告规范｜分析、表述与视觉

首次生效：2026-09-07；升级版本：2026-09-09.1。保留原文件入口，扩展为本项目统一规范。依据用户明确要求及最终修改版，不把自动生成稿的残留问题当成用户偏好。适用于Waje项目新增和修订的报告；不改变其他项目、个人全局设置、数据权限或发布权限。

**使用顺序：先确定本报告的问题与口径 → 选择四类骨架 → 写结论和证据 → 选图 → 检查 → 渲染及回读。**

2026-09-10用户补充：分析、评估及总结报告默认产出阅读友好的HTML，Markdown保留为项目源稿；飞书等其他格式按本报告授权范围处理。机制和能力评估没有经营数值时，使用流程说明和能力对照表，不为满足渲染器而编造统计图。统一入口对明确声明mechanism、包含正文及原生表格的无图报告启用项目兼容层，其余字段、来源与交付检查保持生效。

## 规则来源与优先级

1. 本次任务最后明确确认的要求与统计口径，优先于通用模板。
2. 用户明确的通用要求，优先于旧稿残留、自动生成器默认标题或配色。
3. 跨报告重复出现的偏好，可作为默认风格；报告特有定义不全局化。
4. 新增自动检查阈值和工程做法是本次批准的实施规则，不伪装成用户历史原话。

最终版本通过交付链接、修订号、回读记录及内容哈希定位，不只看文件修改时间。远端与本地不一致时分别记录；无法确认最新版本时标为待确认，不自动升格为硬规则样板。历史报告只读保留。

## 分析与数据展现

### 最后修改版优先与同步

以用户最后修改或明确确认的版本为本报告内容、结构、措辞和排版基准；飞书、HTML、Markdown、artifact均可能成为该次基准，不固定某种格式永久优先。执行[定稿与跨格式同步工作流](报告定稿与跨格式同步工作流-2026-09-09.md)：全文读取、版本对比、先备份、受控转换、检查、回读/复查、登记。canonical artifact是当前定稿的渲染输入，不是比用户定稿更高的内容权威。

用户调整中可复用的阅读偏好归纳入规范，个别报告的假设、数值和统计口径不推广为通用规则。“推测／待证实／待核”保留原状态；源稿疑点单独列出，不能通过同步将其认证为事实。不同端存在并行修改时先比较内容，不按文件mtime直接覆盖。

- 以业务问题组织：**差异多大 → 集中在哪里 → 哪些解释有证据 → 下一步验证或行动**。不按SQL执行顺序堆数据。
- 埋点设计按“总体方案→核心指标及算法→具体实现→验收”阅读；纯机制讲解按“结论→流程分支→场景→边界”阅读。前者先让业务读者理解指标，后者不强行生成经营统计图。
- 重点对象深入分析，同时保留合理对照。“H5为重点”不等于省略APP；指标诊断按需要补人群、品类、头部与长尾、参与深度及回访。机制说明不强制套用经营图表。
- 绝对规模与比例同时提供；份额写清分母。百分点变化与相对百分比变化分开。不同统计窗口、成熟范围、币种或人群的结果分开展示。
- 人群、起点、端归属、统计日、币种和资产类型是**本报告参数**：Whot可按注册当日定义新用户；Tada/PP可按行为日账号龄0—29天定义。模板不替你决定，不用最新画像覆盖历史行为端。
- 人数、次数、局数、人局数分别命名；点击、受理、开局、支付、到账分别统计。通用名称不能掩盖实际含义。“成功支付率→付费率”仅适用于用户付费比例，不能改写订单支付成功率。
- 留存说明起点日为第几日、回访行为和观察范围。未达到观察天数显示N/A及简短原因，不填零；同批持续回访须计算交集，不能用两个比例相减代替流失人数。
- 图、表、正文与附件复用同一数据源；改数字时同步相关文字。未知、未识别及被抑制样本保留状态，不以删除覆盖问题获得“完整”。
- 正文保留会改变判断的口径和限制。SQL、字段、查询回执、非关键覆盖及模型运行记录放来源详情或附录；不足以支持结论的缺口不能藏起来。
- 观察、关联与因果分开。人均值不能代表所有用户；静态竞品资料不制作伪时间趋势；同源整理表不当作独立证据。

## 文字与阅读路径

- 默认中文标题与正文；产品名、RTP、TC和技术字段保留，首次出现时简短解释。默认英文模板标题须译为中文。
- 摘要通常2—4条：**加粗主题句＋关键证据＋业务含义**。不整段加粗，不在标题后重复同一段摘要。
- 默认标题用“执行摘要”；可保留“汇总结论”“先看结论”等同义表达。方案类可用“总体方案”承载开篇目标与重点，不要求为了套模板重复写两份摘要。
- 每节先判断、再证据、再含义；短句、动词和具体数值优先。正文建议一段2—4句，超过180字符只提示检查，不自动删改。
- 少用“需求合同”“覆盖合同”“窗长待签字”等术语。保留逻辑字段名在技术明细中，不把所有代码强行翻译成中文。
- 优先说明应该怎样做：“不产生双终态”可改为“每次请求只有一个最终结果”；“不把引导点击当作提现成功”可改为“引导点击、提现申请和实际到账分别统计”。
- **必要否定句保留。** 不可比、未达到观察期、不得上传凭据、不能由关联证明因果等不能被机械删除或改成肯定结论。
- 去掉与读者判断无关的过程记录；不添加没有依据的上线门槛、评分、工作量或因果解释。已确认口径不应又出现在末尾待定清单。

## 阅读结构

- 首屏给出题目、核心结论和行动；正文每一节先说明判断，再给证据。
- 一节承担一个阅读任务；完整保留已有结论、数据和必要限制，不以美化为由删减。
- 正文以单列为主。长字段表使用整行宽度；表格在窄屏内部滚动，页面不得横向溢出。
- 数据图用于比较、趋势和分布；流程应用流程图。不要用事件数量代替工作量估计。
- 长篇技术明细可折叠，但默认可见结论和决策所需限制；不能只折叠标题后丢失内容。

## 字体和留白

- 桌面内容最大宽度约1120px，正文16px、行高1.75—1.85；一级标题约32—34px，章节标题22—24px。
- 表格正文14—15px、行高至少1.6，单元格上下留白约12px；代码和编号完整显示，不缩写游戏ID。
- 段落、章节和卡片之间留白清晰；手机正文仍保持可读大小，不能全页等比缩小。

## 配色

- 浅灰蓝页面背景、白色内容区、深蓝正文。章节标题和关键数字用蓝色；避免低对比浅灰文字。
- 表头浅蓝，交替行用很浅的蓝灰；颜色配合文字标签表达状态。
- 浅黄用于待确认问题、浅绿用于建议或完成状态。红色仅用于异常或阻断，不做装饰。
- 如展示正负偏离，沿用用户要求：正值绿色、负值红色，绝对值越大色阶越深；文字保留正负号与单位，颜色不代表所有业务情境下的好坏。
- 保留随系统切换的深色模式：深背景、浅文字、清楚边界，不以手动主题开关替代。

## 默认可视化组件（2026-09-08起）

- 执行摘要使用浅蓝背景、蓝色边框的高亮模块，默认2—4条结论；每条先写加粗判断，再写证据和行动含义。
- 摘要后可放核心指标模块。指标模块必须有完整边框和浅蓝背景；每格只放“指标名、当前值、对比变化”，关键值使用深蓝色。
- 金额、规模和占比的明细表可使用数值条；实心段统一深蓝色，剩余段浅灰色。若使用列内最小—最大归一化，必须在表前说明，不能让读者误认为是绝对完成率。
- 表格表头使用中性灰蓝；普通数据保持中性。只对变化、偏离、风险或状态字段使用色阶，不整表铺色。
- 正向变化使用绿/蓝色系，负向变化使用橙/红色系；强弱色阶必须同时保留正负号、单位和精确值，颜色不单独承担含义。
- 折线图至少标注最高值、最低值和最新值；散点图必须直接标出两端异常点的名称和偏离值，不能让需要关注的异常点无名称。
- 图表标题保持中性描述；每张图表前后必须有一句直接结论，解释变化、业务影响和仍不能判断的部分。
- 金额变化写成“由X提升/下降至Y，变化Z%”；比例本身的绝对差写“变化Z个百分点”，相对变化才写“变化Z%”。
- 已知且不改变决策的覆盖率、技术限制和过程说明不占用正文核心区域；仅在确实影响结论时写入短注或附录。
- 长表允许横向滚动，但关键识别列、当前值、变化和风险列应尽量靠左，保证移动端首先看到结论所需字段。

## 统一实现与验收

- canonical artifact仍为数据与内容来源；共享阅读器负责图表、表格和来源交互。
- 项目样式：`config/report_readability.css`。便携HTML入口：`node scripts/deliver_readable_report.mjs --input <artifact.json> --output <report.html> --receipt <receipt.json>`。
- 此入口使用原便携构建器，并在增强阅读器与静态回退层应用同一份CSS，不维护第二份数据或图表实现。
- 必须验收桌面与窄屏、长表换行、来源交互、无外部依赖；主题样式变化额外检查浅/深色最终页面。
- 更新样式后验证当前请求的报告。其他历史成品在用户要求更新时应用；无需批量重写历史证据。
- 飞书报告创建或更新后必须全文回读，核对标题、章节数、表格数、图片数、核心数字、色阶字段、图片资源和最终修订号；“写入成功”不能替代回读验收。

### 交付前检查（2026-09-09起）

唯一机器规则入口为`config/report_output_policy.json`的`report_quality`。入口与旧调用方式保持兼容：

```sh
node scripts/check_report_quality.mjs --input <artifact.json|report.md|report.xml>
node scripts/deliver_readable_report.mjs --input <artifact.json> --check-only
node scripts/deliver_readable_report.mjs --input <artifact.json> --output <report.html> --receipt <receipt.json>
```

- 检查器不改写输入、不联网、不执行SQL。默认只输出检查JSON；显式指定`--receipt`才写检查回执。`--check-only`不导入渲染器、不构建、不发布。
- **硬错误拦截**：输入和必需标题、明确的中文标题违例、无效引用或来源、已声明口径/单位缺失、尺度矛盾、声明的跨表或公式不一致、个人明细或凭据、渲染失败。
- **风格问题提示**：长段落、术语、密集否定、过度加粗、重复结论、疑似因果过度表达及图表关键点标注。提示不阻止交付，不自动修改。
- 新artifact在`manifest.reportContract`声明本报告类型、参数、指标与需要核对的计算。旧artifact仍可读取，通过来源元信息做保守检查，并提示补结构化声明；不是把旧稿所有问题自动豁免。
- Markdown/飞书XML仅作文本与结构检查。业务正确性、未声明的计算、实际图表可读性与飞书回读保持“未验证/待人工复核”，不冒充通过。
- 检查结果包含规则编号、级别、位置、说明和建议；有未豁免错误时非零退出。视觉结果仍以原共享构建器回执为准，`structural_only`不改写成完整视觉验收。
- 本地浏览器就绪/探测超时最多重试一次，且输入哈希须保持一致；回执保留全部尝试。数据、格式、引用或溢出等错误不自动重试；两次仍失败继续阻断，不降低为通过。
- 例外通过单独JSON传入：绑定本报告原文件哈希、规则与精确位置，说明理由、批准者和项目内批准记录哈希。无效或宽泛例外不生效；格式损坏、引用损坏、计算错误和隐私风险不支持豁免。批准记录的真实性由人负责，检查器只核验引用与范围。
- 规范性参数冲突通过`decisions/openQuestions`明确声明时拦截；仅凭自然语言发现的疑似矛盾给人工提示。不能宣称自动理解了所有业务事实。
- 隐私检查仅识别已知明细字段和凭据模式，不替代发布前的人工脱敏复核。

### 持续使用

新增报告默认先用相应骨架和检查器；旧流程在后续修改时应用，不批量重发历史成品。保留历史负例做回归测试，不为测试通过修改原报告。普通日报周报不因新增规范而启动多Agent。

## 使用范围

本规范调整阅读质量，不额外改变各任务约定的输出格式、发送对象、发布权限或统计口径。

## 2026-09-11补充：最终单文件HTML交付标准

用户确认《Tada-TC异常分析-单文件.html》的最终阅读形式，纳入Waje项目后续报告默认产出规范。参考版本与哈希见[样式参考登记](../90-模板/分析报告/单文件HTML样式参考-2026-09-11.md)。本节归纳版式、重点表达及交付要求，报告内的具体经营数字、因果判断、日期和币种不作为其他报告默认值。

- **单文件交付。** 最终阅读产物为自包含HTML，数据、样式、图表运行资源全部内嵌，断网后双击可读；localhost仅用于预览，交付时提供实际HTML文件链接。Markdown及查询、数据、验收回执留在项目中供追溯。
- **核心议题优先。** 按“整体变化→主要贡献→重点对象→结论与行动”展开；摘要通常2—4条，每条先突出观点，再列核心数据。完整明细和技术对账置于附表，影响判断的限制就近显示。
- **全文高亮。** 摘要和正文的核心判断加粗；关键金额、比例、百分点和重点对象使用高对比文字与克制的浅蓝底色。保留普通解释文字，避免整段铺色或整段加粗。
- **图表峰值可读。** 趋势图标注高点、低点与最新值；贡献图指出最大贡献及最大抵消对象；热力图显示数值，注明极值的对象、日期及比较范围。标签空间不足时使用紧邻图表的说明，避免遮挡。
- **表格紧凑准确。** 最大/最小值以加粗、边框及“最高／最低”文字区分，按该表全部数据而非当前页计算，说明并列及零值处理。对比表优先采用“基线、当前、变化”三行；变化放在原指标列对应行内，用单位区分百分比与百分点，不为变化再建多数为空的列。
- **原始数值与显示分开。** 金额、比例保留数值类型以支持正确排序；格式化仅在显示时处理。关键比例及百分点默认保留两位小数，按任务精度调整，不因回调参数错误退化为整数。颜色表达方向或异常，数值极值标签本身不代表业务好坏。
- **阅读与验收。** 遵守本规范的内容宽度、字号、留白和深浅色要求；窄屏表格内部滚动，页面无横向溢出。验收实际交付的单文件HTML：断网打开、图表绘制、表格与高亮、桌面/窄屏及浅色/深色，记录文件哈希及未完成检查。

共享Data Report应用沿其支持的 `build --separate-data` 与 `export-offline` 流程导出同一份报告，再将便携HTML复制到 `output/html/`；legacy canonical artifact继续使用 `scripts/deliver_readable_report.mjs`。按输入格式选验证入口，不能将Data Report快照强行当作旧artifact检查，也不能把格式检查通过解释为业务口径通过。
