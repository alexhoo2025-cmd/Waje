## 为什么本次没有直接使用“浏览器 API”批量完成

1. **起源平台没有在当前授权范围内的官方导出 API。** 只能使用已登录的 `BQ-新增付费用户分析` 可见报表，不能抓取 Cookie、Token 或调用未授权隐藏接口。
2. **浏览器控制适合已登录查询，不等于稳定的数据接口。** 日期控件、悬浮筛选菜单、长查询等待和多个 Chrome 标签页会造成页面状态与当前可见窗口不同步。
3. **飞书 API 读能力可用，写能力未完成授权。** 读取和回读非常高效；行高批量写需要 `sheets:spreadsheet:write`，本轮通过网页编辑权限完成。后续若该 scope 审核通过，`rows-resize` 可将 12 个 Sheet 的行高修复压缩为 12 次可回读 API 调用。
4. **效率正确的边界。** 对已登录内部报表，浏览器应只承担“可见查询和导出”；本地合并、去重、校验、样式保持和交付应由脚本完成。不要用 UI 逐格写数。
