# 飞书原生文档与图表发布 SOP｜2026-08-11

## 目标

将本地 Markdown、HTML、结构化指标和图表数据，高效发布为可搜索、可复制、可评论、可持续更新的飞书原生文档与表格。避免整页截图，也避免在浏览器 Canvas 中逐格录入。

## 本次问题复盘

本次耗时的根因不是内容量，而是执行路径选错：浏览器中的飞书表格主要由 Canvas 渲染，DOM 不提供稳定的单元格节点；高分屏下还存在 CSS 坐标与设备像素不一致。逐格点击会引入焦点丢失、选区漂移、粘贴拆分、超时和重复写入，最终出现“只有一个子表、URL 混入 C3”的失败产物。

暴露出的流程问题：

- 开始前没有先确认是否存在官方写入 API、CLI 或连接器；
- 没有设置“浏览器交互次数/失败次数”止损线；
- 把浏览器同时当作数据写入器和视觉验收器；
- 写入后只看页面外观，没有通过 API 回读结构和数值；
- 临时方案没有立即沉淀为可复用脚本。

## 工具优先级

```text
Lark 官方 CLI / 授权 API
  → 批量写 Docs、Sheets、Wiki 和原生图表
  → API 回读校验
  → 浏览器只做最终视觉验收

授权 API 暂不可用
  → 导入结构化 XLSX
  → API 或人工核验工作表和图表对象

浏览器 UI
  → 只用于登录授权、权限确认和视觉 QA
```

硬性止损规则：

- 需要连续操作 3 个以上单元格、区块或文档节点时，直接切换批量 API/CLI；
- 同一定位动作失败 2 次，或浏览器写入超过 5 分钟仍未形成稳定闭环，立即停止 UI 写入；
- 用户要求“原生图表”时，验收标准是图表 API 能返回真实图表对象，截图不算完成；
- 写操作成功响应不等于完成，必须有回读和视觉双验收。

## 安全与授权

- 使用 Lark 自建应用的最小权限，文档和表格操作显式采用用户身份；
- App Secret 通过隐藏终端输入交给官方 CLI，并由 macOS 钥匙串保存；
- 用户 Token、App Secret、Cookie 和密码不得进入项目文件、Git、命令日志或知识库；
- 发布脚本不读取、不接收、不持久化凭证，只调用已授权的 `lark-cli`；
- 变更前记录目标 URL、工作表清单和修订信息，避免误写其他文档。

## 标准发布流程

### 0. 首次绑定（只需一次）

```bash
python3 scripts/setup_lark_cli.py
```

按提示输入 App ID 和 App Secret；Secret 输入过程不回显，不进入 shell 历史，也不写入项目。脚本会立即调用服务端验真，只有显示“绑定并验真成功”才进入后续用户授权；仅本地保存但服务端返回 `client secret is invalid` 不视为完成。

### 1. 内容中间层

先将报告拆为可复用的内容中间层：

```text
章节与标题
信息块与状态标签
原生表格
流程图/UML
指标数据集
图表规格
来源与时间窗口
```

主文档保留结论、结构和阅读路径；明细字段字典和图表数据下钻到专题文档或伴随表格。

### 2. 写入前预检

```bash
lark-cli config show
lark-cli sheets +workbook-info --url "<表格 URL>" --as user --format json
```

检查工作簿、子表名称、行列范围、现有图表和写入身份。小表全量读取，大表按窗口读取；参与公式、排序或筛选的列至少采样 50 行。

### 3. Dry-run

```bash
python3 scripts/publish_lark_tracking_v2.py
```

默认在本地校验 3 个 typed table、样式和图表规格，不产生远端写入。官方 CLI 即使使用 `--dry-run` 也会先检查应用配置，因此未绑定阶段不把它当作本地校验器；绑定完成后再进入真实 API 预检与执行。

### 4. 批量发布

```bash
python3 scripts/publish_lark_tracking_v2.py --execute
```

发布器一次完成：

- 重建 `overview_kpi`、`event_quality`、`quality_gate`；
- 保留数字、百分比和空值类型；
- 应用表头、对齐、边框、列宽、行高和冻结规则；
- 创建 `event_quality` 原生横向条形图；
- 回读 3 个子表并校验行数；
- 回读图表列表并校验标题；
- 将不含凭证的审计结果写入 `data/outputs/lark-publish/YYYY-MM-DD/`。

### 5. 文档发布

文档结构优先使用飞书原生 H1/H2/H3、信息块、四列以内表格、流程图和任务清单。图表数据存放在关联表格，正文通过原生关联能力引用；旧版本只增加顶部历史说明和 V2 链接，不删除原内容。

### 6. 双重验收

API 验收：

- `+table-get` 返回 3 个目标子表；
- `overview_kpi` 4 行、`event_quality` 4 行、`quality_gate` 5 行；
- `GAMEEND` 为 112,635,044 / 7,030,603 / 6.24%；
- PV、MV、ASSET 缺失的计数保持空值，不用 0 代替；
- `+chart-list` 返回标题为“GAMEEND 是当前异常率尖峰”的图表对象。

浏览器验收：

- 桌面端和移动宽度下无明显截断；
- 表头、百分比、长文本换行和风险色正确；
- 图表不遮挡源数据；
- 主文档可搜索、复制、评论，正文不是图片；
- V2 和两个历史版本之间的跳转有效。

## 本项目目标与时效

首次应用绑定与用户授权完成后，同类任务目标时效为 10–20 分钟：内容结构化 5 分钟、批量发布 2–5 分钟、API 回读与浏览器验收 5 分钟。浏览器不再承担批量写入，因此页面结构变化不会重新触发逐格调试。
