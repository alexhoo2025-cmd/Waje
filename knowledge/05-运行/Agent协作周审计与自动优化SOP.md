# Agent 协作周审计与自动优化

生效：2026-09-04。每周五17:00，Asia/Hong_Kong，在项目本地独立运行；默认单Agent执行，不额外调用Claude或Gemini测试审计本身。

## 统计口径

以本次计划周五17:00为截止点，首次回溯7天，后续从上次已完成审计截止点补查，避免周末和漏跑记录丢失。标注实际执行时间、统计窗口及缺口。
只读快照审计SQLite任务/事件、脱敏task/result/receipt/review/publication文件、已交付产物及Gemini网页专项回执。按父任务汇总，分派、模型尝试、返工与交付分别计数；跨周未完任务标进行中。历史模拟/benchmark/fixture单列，无法判断是否生产的记录标unknown，不纳入生产提速结论。

重点指标：分派是否必要、角色/模型匹配、首轮验收、最终交付、返工、端到端耗时、等待、上下文重复、证据与指标质量。分母及窗口必须明确；缺结束时间/验收记录等不能计为成功或零耗时。费用仅观察，不恢复每日预算或次数限制。

Gemini网页Agent用户确认效果较好，偶有账户/凭证验证需求；仅依据网页专项回执评估实际量化效果。无回执时标记覆盖不足，不能据本地CLI失败推断网页无效。本地Gemini CLI权限未开通、完全排除，审计不得调用、探测或恢复。

## 分析和自动优化

每项候选记录：问题证据、影响、方案、预期收益、改动文件、验证办法。优先改进复杂任务拆分、上下文交接、一次集中反馈、验收及失败接管。
允许自动修改协作配置中既有边界内的超时/重试/并发设置、桥接和交接的局部缺陷、对应测试、项目协作说明。缺少可比较样本时不凭比例或单次延迟调参；有明确复现的缺陷可修复。无必要优化时记录无变更及原因。

以下规则固定不变：简单日常任务不协作；只有聊天中的复杂项目任务按需分派；本地Gemini CLI不参与；网页Agent独立保留；费用仅观察；worker不获得额外工具或数据权限。不得自动修改全局模型/代理/凭据、IAM、云端部署、生产数据、外部发布、其他自动任务或Git提交推送。

修改前记录目标文件的当前内容指纹并保存可恢复的局部补丁；当前用户改动属于基线，不覆盖其他任务的变更。存在同文件活动任务或无法隔离的重叠修改时，记录待处理，继续完成其他可执行项。使用apply_patch小范围修改，实际运行相关回归并回读产物；失败只撤销本次自身补丁。测试通过只能证明功能验证，不宣称性能已经提升；下一周用真实任务复评。

## 产出与回执

输出到data/outputs/agent_collaboration/weekly_audits/<计划日期>/<唯一run_id>/，已有文件不覆盖。
- audit.md：先写结论与核心指标，再写问题、优化方案、已实施变更、验证和待确认事项。
- receipt.json：status、run_at、window、source_coverage、metrics及分母、optimization_plan、applied_changes、verification、artifacts、open_questions。
- patches/：本次局部变更及目标文件前后指纹；不保存密钥、账号、原始会话或业务明细。

最终简报建议300–500字，分为“本周效果、主要问题、已做优化、验证结果、下周观察”，附详细审计文件链接。样本不足或无法优化照实说明。

## 跨聊天记录要求

Claude使用现有桥接共享台账。复杂任务调用Gemini网页Agent后，由主Agent在data/outputs/agent_collaboration/web_receipts/<日期>/<唯一task_id>.json保存最小脱敏回执：task_id、parent_task_id、backend=gemini_web、origin=interactive、任务类型、开始/结束时间（未知为null）、执行状态、验收状态、结果/证据路径、认证中断、返工次数（未知为null）。无需复制聊天全文。人工反馈单独标注来源，不能冒充一次真实调用或量化成功率。
