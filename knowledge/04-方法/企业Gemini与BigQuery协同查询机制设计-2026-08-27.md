# 企业 Gemini 与 BigQuery 协同查询机制设计

## 1. 目标

企业 BigQuery 数据查询默认由 Gemini 命令行工具执行，Codex 不再把企业数据查询作为首选执行器。Codex 保留任务拆解、口径审计、数据质量判断和最终交付职责。

设计目标：

- 用企业 Gemini 的模型与 BigQuery 连接完成授权聚合查询，降低 Codex 上下文与执行成本；
- 不使用个人密钥，不保存服务账号密钥、令牌、原始用户明细或原始模型输出；
- 不允许模型绕过数据白名单、日期过滤、查询成本或敏感字段规则；
- Gemini 不可用时明确返回阻塞状态，不能静默降级到个人账号或无约束查询。

## 2. 角色分工

| 角色 | 负责内容 | 不负责内容 |
|---|---|---|
| Codex | 判断是否为企业数据任务；构造任务契约；校验数据范围、分母、时区和质量；生成正式报告 | 直接访问未授权明细、代替 Gemini 执行企业查询、把模型草稿直接作为业务结论 |
| Gemini 命令行工具 | 按授权对象生成和执行只读聚合查询；返回结构化交接包 | 写表、导出、修改数据集、输出用户级明细、替代最终审计 |
| 只读查询网关 | 校验语句、对象白名单、敏感字段、分区条件、成本和行数；执行获准查询 | 推理业务结论、写入业务数据 |
| BigQuery | 通过授权视图提供聚合数据 | 向模型开放基础用户明细表 |

## 3. 自动路由规则

以下任务自动进入 Gemini 企业查询链路：

1. 用户明确要求查询、统计、审计、核对或分析企业 BigQuery 数据；
2. 任务涉及企业业务库、认证行为库、授权视图、设备性能、游戏、留存、支付、风控或数据质量；
3. 任务需要多表聚合、较长周期统计、异常检测、初稿分析或跨资料对照。

以下任务仍由 Codex 直接完成：

- 本地文件编辑、文档润色、最终报告编排；
- 只解释已有结果、不触发企业数据查询的问答；
- 没有企业身份、允许对象或合规范围的请求。

自动路由不是“无条件执行”。只有全部前置门禁通过，才会实际调用 Gemini；任一门禁失败返回 `blocked_authentication`、`blocked_iam` 或 `blocked_sql_validation`。

## 4. 运行架构

```text
用户的数据问题
      ↓
Codex 任务分类器
      ↓
企业查询任务契约
      ↓
身份、项目、视图、成本和策略预检
      ↓
Gemini 命令行工具（企业默认凭据 + Vertex AI）
      ↓
BigQuery 远程工具 / 只读查询网关
      ↓
企业授权聚合视图
      ↓
Gemini 结构化交接包
      ↓
Codex 口径、质量和事实边界审计
      ↓
正式报告或结论
```

数据项目、模型运行项目和查询执行项目必须显式传递，不能默认相同：

| 资源层 | 当前设计 |
|---|---|
| 模型运行项目 | `indigo-gecko-500503-j3`，区域 `us-central1` |
| 企业数据项目 | `wajenigeria`，仅允许授权视图或经批准数据集 |
| H5 行为数据项目 | `waje-analytics-readonly`，区域 `US`，单独登记，不与企业库混用 |
| 原生应用分析数据项目 | `waje-special`，区域 `europe-west4`，单独登记，不与 H5 混用 |

## 5. 前置门禁

每次企业查询前自动执行以下只读检查：

| 门禁 | 通过条件 | 失败状态 |
|---|---|---|
| 企业身份 | 默认凭据属于企业账户 | `blocked_authentication` |
| 模型运行 | 可调用指定 Vertex AI 模型 | `blocked_iam` 或 `model_unavailable` |
| 工具调用 | 工具项目启用 BigQuery 接口且拥有工具使用权限 | `blocked_iam` |
| 数据范围 | 目标对象在授权视图或数据集白名单内 | `blocked_sql_validation` |
| 查询语句 | 单条只读查询；有日期过滤；无敏感明细投影 | `blocked_sql_validation` |
| 成本 | 预估扫描量不超过阈值 | `blocked_cost` |
| 结果质量 | 返回数据截止时间、完整日、样本量和分母 | `quality_warning` |

当前门禁状态：

| 检查项 | 当前状态 | 说明 |
|---|---|---|
| 企业默认凭据 | 已通过 | `robin@afuruika.net` 已完成默认凭据授权 |
| 模型运行项目可见性 | 已通过 | 可读取 `indigo-gecko-500503-j3` 项目 |
| 模型调用权限 | 阻塞 | 缺少 `aiplatform.endpoints.predict` |
| 配额项目权限 | 阻塞 | 缺少 `serviceusage.services.use` |
| BigQuery 远程工具扩展 | 未安装 | 模型门禁通过后再安装 |
| 授权对象白名单 | 未配置 | 当前 `allowed_datasets`、`allowed_views` 均为空 |

## 6. 查询安全网关

模型产生的查询不能直接信任。网关必须在执行前强制：

1. 仅允许单条 `SELECT` 或 `WITH` 查询；
2. 拒绝写入、删除、导出、建表、授权、过程调用和动态执行；
3. 禁止 `SELECT *`；
4. 要求日期或分区过滤；
5. 仅允许已登记的授权视图或数据集；
6. 禁止直接投影用户标识、手机号、邮箱、证件、账户、订单、设备唯一标识、令牌和 Cookie；
7. 常规任务默认扫描不超过 1 GiB，复杂任务上限 5 GiB；先试算再执行；
8. 最多返回 3,000 个聚合行、3 MiB 结果；涉及用户贡献的分组默认低于 10 个样本时合并或抑制；
9. 为每个查询加任务编号、数据截止时间和调用来源标签。

强制使用授权聚合视图优先于基础明细表。若必须读基础表，先由数据负责人提供显式对象白名单和字段白名单。

### 6.1 远程工具固定白名单

企业 Gemini 只能连接一个受控的 BigQuery 远程工具端点，并只暴露以下五类能力：列出数据集、读取数据集元数据、列出表、读取表元数据、执行只读查询。

不得暴露通用查询、写入、建表、删表、导出、迁移、传输、身份与权限管理工具。客户端隐藏工具不构成安全边界；管理员还应在工具项目设置拒绝策略，拒绝任何非只读工具调用。

数据访问也必须从权限层收敛：查询身份只可读取“授权聚合视图”所在数据集，而不能读取基础明细表。普通数据查看角色在基础表上还可能具有导出、复制或快照能力。

## 7. Codex 与 Gemini 通信契约

### 7.1 请求包

```json
{
  "task_id": "固定且可重试的任务编号",
  "task_type": "设备性能、轻量化游戏、留存、风控或数据质量",
  "question": "用户问题",
  "data_project": "明确项目标识",
  "location": "明确区域",
  "allowed_objects": ["仅授权视图"],
  "date_from": "开始日期",
  "date_to": "结束日期",
  "timezone": "业务时区",
  "dimensions": ["允许的分析维度"],
  "max_bytes_billed": 1073741824,
  "max_rows": 3000,
  "privacy_mode": "aggregate_only"
}
```

### 7.2 Gemini 交接包

Gemini 只返回：

```json
{
  "status": "成功、无数据、延迟、质量警告、身份阻塞、权限阻塞或失败",
  "sql": "经校验的只读查询",
  "source_objects": ["实际授权对象"],
  "data_cutoff": "数据截止时间",
  "complete_day": true,
  "metrics": ["聚合指标"],
  "summary": "初步结论",
  "quality": {
    "sample_size": 0,
    "denominator": "分母说明",
    "missing_reason": null
  },
  "next_steps": ["待办"],
  "evidence_level": "已证实、已报告、推断或未验证"
}
```

不得返回原始行、用户明细、身份标识、完整设备标识、订单明细、Cookie、令牌或未经审计的长文本。

### 7.3 状态机

```text
已接收
  → 预检中
  → 身份或权限阻塞 / 语句阻塞 / 成本阻塞
  → 已委派
  → 已校验查询
  → 已执行聚合
  → Codex 审计中
  → 已交付 / 质量警告 / 无数据 / 延迟
```

失败不回退到个人密钥，也不静默改为 Codex 直查企业库。保留最小化回执，不保存原始模型输出。

## 8. 结果存储与可追溯性

每个任务仅保存以下文件：

```text
data/outputs/gemini/日期/任务编号/
  request.json       请求包，不含凭据
  preflight.json     门禁与权限状态
  result.json        清理后的结构化结果
  receipt.json       执行、成本、数据截止和质量状态
  report.md          Gemini 初稿，供 Codex 审计
```

禁止保存：完整提示词中的敏感上下文、原始模型输出、访问令牌、服务账号文件、原始查询行和浏览器会话信息。

## 9. 验收流程

1. 管理员补齐模型调用、配额和工具使用权限；
2. 注册仅包含授权视图的白名单；
3. 安装官方 BigQuery 远程工具扩展并列出可用工具；
4. 运行“列出授权视图元数据”测试；
5. 运行“一天聚合事件量”测试，验证日期过滤、成本上限和结果脱敏；
6. 运行一次完整的设备或留存分析任务；
7. 由 Codex 对 SQL、分母、时区、数据截止、事实边界和结果质量复核；
8. 只有以上全部通过后，启用“企业 BigQuery 查询自动委派 Gemini”的默认路由。

### 9.1 分阶段启用

| 阶段 | 允许动作 | 不允许动作 | 退出条件 |
|---|---|---|---|
| 第一阶段：受控试运行 | 身份预检、元数据、单个授权视图的按日聚合、只读拒绝测试 | 基础表读取、写入、导出、自动全量路由 | 模型、工具、白名单与只读拒绝策略全部验收通过 |
| 第二阶段：稳定自动路由 | 所有符合条件的企业查询默认委派 Gemini | 绕过门禁、个人密钥回退、明细查询 | 查询回执、数据质量和异常处理持续稳定 |

## 11. 现有实现的改造范围

当前桥接器已有任务契约、敏感字段清理、只读语句检查和回执保存基础，但不能直接作为自动执行网关：模型返回查询后才进行校验，且当前仅支持单一企业项目。

后续改造应包括：

1. 将单一数据项目改为多数据源档案：企业业务库、移动网页分析库、原生应用分析库分别登记项目、区域、时区、授权视图和预算；
2. 将流程拆成“Gemini 生成计划 → 执行前校验 → 试算 → 受控执行 → Gemini 解读 → Codex 审计”；
3. 将模型自述的身份状态替换为桥接器记录的真实预检与查询回执；
4. 使用结构化解析、试算和实际查询计划补强当前正则校验，强制聚合、分区、区域和成本限制；
5. 新增请求包、查询计划、校验结果、执行回执和清理后交接包；
6. 补齐来源、区域、敏感嵌套字段、注释绕过、试算超预算、模型伪造身份和跨项目混用的回归测试；
7. 将本地环境文件、MCP 凭据与默认凭据相关文件加入忽略规则，避免误提交。

## 12. 已确认的数据源沟通结论

根据二〇二六年八月二十七日的项目沟通和控制台截图，以下内容可作为后续数据源登记依据：

| 数据范围 | 当前沟通证据 | 协同机制处理方式 |
|---|---|---|
| 企业起源数据 | 对方明确说明源头原始数据位于 BigQuery，可提供查询接口或查询权限 | 作为独立“起源原始数据”档案；人工和受控网关可按权限查询，Gemini 默认只读取其脱敏聚合视图 |
| 移动网页 Firebase 数据 | 企业项目列表中可见 `waje_ng_firebase_h5` | 作为移动网页 Firebase 数据档案，区域、表结构和新鲜度仍需元数据核验 |
| 苹果端 Firebase 数据 | 企业项目列表中可见苹果端数据、崩溃、分群、消息和性能相关数据集 | 作为苹果端档案，按产品分别登记表和区域 |
| 安卓端 Firebase 数据 | 沟通中明确“尚未迁移完成”，当前截图也未见对应安卓端数据集 | 标记为 `not_ingested_or_pending_migration`，不得写成无数据或性能正常 |
| `GE_90006` | 沟通中被说明为原始数据入口；截图不足以确认其业务域、表名、区域或敏感字段 | 先做元数据清单，不在未核验前将其纳入模型白名单 |

### 12.1 原始数据与模型访问必须分层

“需要起源数据的查询权限”是合理的业务需求，但它不等于“把原始数据直接交给模型”。应拆成两层：

```text
数据负责人 / 受控人工查询
  → 起源原始数据集（只读、最小权限、用于核验与建立聚合口径）
  → 授权聚合视图
  → Gemini 与 Codex 自动分析链路
```

这样既满足产品、数据和研发对起源数据的追溯需求，也避免模型读取用户级、订单级、设备唯一标识或其他敏感明细。

### 12.2 需要向数据负责人补齐的元数据

在将起源数据加入自动路由前，需一次性确认：

1. 数据集实际项目、区域、数据集标识和表清单；
2. 每张表的业务含义、日期或分区字段、刷新频率与数据截止时间；
3. 是否包含用户、订单、资金、设备、身份或其他敏感字段；
4. 可供 Gemini 查询的脱敏聚合视图及其指标口径；
5. 安卓端 Firebase 的迁移范围、目标数据集、预计完成时间和历史回补规则；
6. `GE_90006` 的确切用途、表结构和读取范围。
