# 相关文档拆解与知识入库默认工作流

## 默认规则

凡是与 Waje 产品、游戏、数据、埋点、版本、配置、支付、提现、风控、KYC、运营、竞品或项目协同密切相关的外部文档，完成读取和拆解后，默认加入项目知识库，并刷新项目知识图谱。

适用来源包括：

- 飞书 Wiki、Docx、Sheets 和会议纪要；
- 用户提供的网页、PDF、Excel、图片和导出文件；
- 产品需求、发版报告、配置说明、数据口径和外部竞品资料。

如果用户明确要求“只回答、不入库”或资料与项目无关，则不执行自动入库。

## 标准处理链路

```text
识别项目相关性
  → 只读获取原文/附件
  → 记录来源、版本、时间和权限状态
  → 提取结构、机制、指标、流程和待确认项
  → 区分事实 / 推断 / 建议 / 待验证
  → 脱敏后生成 Markdown 专题资料
  → 更新知识库索引和交叉引用
  → 刷新 knowledge/_generated/ 知识图谱
  → 输出文件路径、来源和证据状态
```

## 入库文件规范

### 推荐目录

| 内容类型 | 默认目录 |
|---|---|
| 产品、玩法、体验和需求 | `knowledge/01-产品/` |
| 数据、指标、埋点、配置、报表和风控 | `knowledge/02-数据/` |
| 竞品、市场、公开舆情和公众号 | `knowledge/03-竞品/` |
| 分析方法、模板和通用 SOP | `knowledge/04-方法/` |
| 会议、自动化、发版和运行记录 | `knowledge/05-运行/` |

### 标准内容结构

```text
标题 / 日期 / 来源类型
来源链接、文档 token、revision 或文件哈希
摘要与适用范围
核心逻辑 / 机制 / 流程
数据指标、字段和口径
事实、推断、建议、待验证项
风险与异常点
对产品、数据、研发和运营的影响
相关知识库链接
证据状态与安全边界
```

需要可视化时，优先使用 Mermaid 流程图、关系图、状态图和 Markdown 表格；只有用户明确要求或版式确有必要时再生成 HTML，不用整页截图替代正文。

## 证据与版本规则

- 保留原始来源链接、标题、来源类型、抓取时间和 revision/content hash，便于回溯。
- 飞书文档优先以用户授权的只读身份读取；不能访问时标记 `permission_pending`，不猜测正文。
- 文档中的“计划、可能、测试中、配置候选”不得改写成已上线或生产事实。
- 新包是当前产品主分析对象；老包、历史版本和作废配置只作参考，不能混入新包 KPI、RTP、留存、LTV、支付或风控统计。
- 已有同主题资料时新增日期版本或差异记录，不覆盖历史原文和历史结论。

## 脱敏与安全边界

知识库只保存脱敏后的分析结论和来源定位，不保存：

- Token、Cookie、密码、App Secret、API Key 和服务账号文件；
- 手机号、邮箱、open_id、用户个人明细和完整聊天逐字稿；
- BVN/NIN、银行账户、证件号、生物识别信息和可直接用于测试认证的身份数据；
- 内含授权码的图片直链或未经审查的原始附件快照。

如原文包含上述信息，只提取规则、字段、流程、阈值和验证要求，并在文档中标注“原文含敏感内容，未复制”。

## 交付与记忆更新

每次自动入库至少完成：

1. 写入对应专题 Markdown；
2. 在相关索引或 README 中增加入口；
3. 执行 `python3 tools/build_graph.py`；
4. 在最终回复中给出文件路径、来源链接、证据状态和未完成项。

项目级背景和默认规则同步维护在：

- `GEMINI.md`；
- `knowledge/README.md`；
- `knowledge/00-索引/项目首页.md`；
- `knowledge/00-索引/Agent项目背景与知识图谱快速上手-2026-08-17.md`。

这些文件构成其他 Agent 的项目记忆入口；聊天窗口之间不依赖隐式上下文传递。
